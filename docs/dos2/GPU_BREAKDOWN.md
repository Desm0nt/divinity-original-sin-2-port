# DOS2: куда уходит GPU-время (Adreno 750, Turnip 27, `TU_DEBUG=sysmem`) — 14.11.2026

Только ПК: логи `src/work/logs/` (p2b, touch1, q1, q2_boot), IR `p2b-nb/`, код `xbg_game.cpp` / `hle_nvn.c` / `hle_dos2_quality.c`.
Телефон не трогался. Инструмент: `tools/dos2_gpu_breakdown.py` (PGRAPH-прокси трафика или разбор GPASS). Все мс ниже — **оценки**,
пока нет строки `NVN GPASS` с телефона (раздел 1).

## 0. Коротко
- **Потаймингов проходов в логах нет.** Профайлер есть и работает в этом дереве: `DM_GFX_PASS_PROF` (+ `DM_GFX_PASS_VALUES=0`),
  строки `NVN GPASS`; конфиг прогона — раздел 1.
- Кампания (p2b f=2509: 66 проходов, 675 draw, GPU 11,3–12,9 мс при 60 fps): **≈ 65 % GPU пропорционально площади 3D**
  (2160x972: освещение, G-buffer, пост), ≈ 15 % — UI-слой окна + фильтры Iggy, остальное — тени, мелкие проходы, барьеры.
  От числа draw кампания почти не зависит (touch1: 363 → 545 draw, GPU 10,4–12,6 — шум).
- 3D-меню (пик 16–17 мс, 38–60 fps): **растёт с числом draw** — 2301 → 625 draw при тех же 35 проходах дают 16,0 → 10,86 мс,
  т.е. **≈ 3,1 мкс GPU на draw** (с ним ≈ 0,5 occlusion-запроса на draw: `inpass_reports` 1050 → 249).
- **Новая находка:** `SetRenderEnableConditional` в `hle_nvn.c` игнорируется («the host draws unconditionally», p2b 17:06:28 при
  входе в меню). На Switch draw'ы за проваленным occlusion-тестом GPU не рисует, мы рисуем все. Порт ETR `condr` (PERF-E05) —
  главный кандидат на пик меню.
- Поправка к вводным: в **sysmem нет tile load/store** — loadOp LOAD/DONT_CARE и storeOp не стоят ничего, проход пишет DRAM прямо
  по мере draw (KB `gpu-mali.md`: «load/store op там не действуют»). Поэтому `renderArea` / отцеп DS / DONT_CARE у фильтров Iggy на
  Adreno-sysmem почти ничего не дают; дают на Mali/PowerVR (и на Adreno только при GMEM).
- HDR-цели уже R11G11B10F (#127/#270/#271), RGBA16F в кадре 1080p p2b нет; тени D16 1536² (3x768); SSAO выключен
  (GraphicSettings +0x6d = 0, `PPSAO*` в кадре нет); bloom в сэмпле кампании p2b отсутствует (в меню есть: 6 проходов).
- Цепочка полуразрешённых частиц — **по сцене**: в p2b её нет (частицы уже в полном разрешении, p50), в touch1 / q2 есть
  (`facf8294` / `34348860` в 180 / 226 строках).
- **Оговорка DCVS:** при 60 fps (vsync) governor держит GPU на неполной частоте, `gpu_ms` = работа / текущая частота. 11–12 мс в
  кампании ≠ «упёрлись»; реальный упор — пик меню. Частоту писать рядом с каждым замером (раздел 1).

## 1. Пер-проходное время: как снять
`xbg_game.cpp`: `pass_prof_begin/_end` пишут `vkCmdWriteTimestamp(BOTTOM_OF_PIPE)` до `vkCmdBeginRenderPass` и после
`vkCmdEndRenderPass` каждого прохода профилируемого кадра (лимит 1024 запроса / 32 слота — хватает: 66–125 проходов ×2), чтение — в
retire слота, строки `NVN GPASS frame= slot= i= kind=pass us= WxH att= fmt= draws= verts= first=0:<vs>;4:<ps> last= mixed= dz=` и
`... summary pass_us= span_us=`. Включение — `DM_GFX_PASS_PROF="from period count"` (dm/env; `1` = `300 600 0`) или маркер
`gfx-pass-profile`. С ним по умолчанию включается **GVAL** (`DM_GFX_PASS_VALUES`, compute-чтение сетки 32x18 после каждого прохода) —
для времени выключать.

**Прогон (с разрешения хозяина; бэкап `files/save` до force-stop — `run_dos2.sh` делает force-stop в начале и в конце):**
```
tools/run_dos2.sh gp1 180 DM_GFX_PASS_PROF=300,180,0 DM_GFX_PASS_VALUES=0 DM_GFX_PASS_GRAPH=1 DM_DOS2_DRS=off DM_DOS2_DRS_LOG=1
```
(окно ⚙ 1080p, как p2b; 3D-меню ≈ presents 300–1500, кампания дальше; кадр профиля каждые 3 с). Параллельно, тем же агентом:
```
adb shell 'while true; do cat /sys/class/kgsl/kgsl-3d0/gpuclk /sys/class/kgsl/kgsl-3d0/gpu_busy_percentage; sleep 1; done' > work/logs/gp1.clk
```
Читать: `grep "NVN pass profile" work/logs/gp1.log` (включён), `python tools/dos2_gpu_breakdown.py work/logs/gp1.log --gpass` (группы
и топ-12 проходов каждого кадра), сырьё `grep "NVN GPASS"`; соответствие `i=` ↔ `p<N>` PGRAPH — по размеру, `draws=` и ключу ps.
Оговорки: штамп BOTTOM_OF_PIPE на Turnip сериализует проходы (каждый проход несёт свой «пузырь» слива) — сравнивать `span_us` с
`gpu_ms` соседних окон PERF; профилируемый кадр медленнее обычного. Второй прогон `gp2` — то же в сцене с цепочкой частиц (локация
touch1) и в бою с эффектами.

## 2. Что видно без таймингов (прокси)

1:1 (текстуры, overdraw, покрытие draw не учтены). Время — при ≈ 40–45 ГБ/с полезной полосы GPU (LPDDR5X; UBWC снижает) ≈ 22–25 мкс
на МБ без сжатия.

Сумма 8,9–13,5 мс против 11,3–12,9 измеренных. Ещё сверки:
- **Фильтры Iggy маленькие.** Меню f=835 (35 проходов, 3D того же размера, bloom есть, фильтров и портрета нет, 625–668 draw) —
  10,9 мс; кампания (+31 проход: портрет 20, фильтры 16, −bloom 6) — 11,3–12,9 мс. Если бы 14 фильтров были полноэкранными, это
  +4–5 мс; разница ≤ 2 мс на всё → покрытие фильтров ≲ ⅓ кадра, их цена на Adreno — в основном фикс. цена прохода + барьер.
- **Барьеры:** `NVN PERF pass_ends … barriers op25=40 op38=40 op61=2` = 82 `full_barrier` (ALL_COMMANDS → ALL_COMMANDS) за кадр,
  `depth_idle=12` проходов с DS без depth-доступа (фильтры Iggy). На Turnip это WFI + слив CCU: оценка 0,4–1,5 мс в сумме.
- **Запросы:** кампания 226 / меню ~1050 in-pass отчётов SAMPLES за кадр; ETR GPUCOST ≈ 1,4 мкс на begin/end → 0,3 / 1,5 мс.
  `vkCmdCopyQueryPoolResults` без WAIT на Adreno (`DM_GFX_QUERY_WAIT` по умолчанию 0) — один WFI на кадр.
- **900p ↔ 1080p** (q2 9–12 мс против p2b 11,3–12,9) растёт слабее площади (+45 %) — разные сцены и DCVS; не довод против площади.
