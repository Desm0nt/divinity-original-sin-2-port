# DOS2: раскладка касания iPad из SWF — точные цифры для переноса на PC-фильмы (19.11.2026, ветка `dos2-uimodes`)

Этап 2 плана `TOUCH_MODES_PLAN.md` (§4): положения, размеры, якоря и формулы раскладки iPad, снятые с самих `_t`-фильмов IPA 3.6.72
(`work/ipa/extract/ipad_gui/`), против PC-фильмов (`sw_gui/*.swf` — это и есть PC-фильмы из `Game.pak` игрока; `hotBar`, `minimap`,
`statusConsole`, `partyInventory` и др. байт в байт совпадают с PC-фильмами в IPA) и `_c`. Только статика: фильмы не проигрывались,
на телефоне ничего не запускалось. Из файлов iPad берутся только **числа** (`TOUCH_ART.md`).

Инструмент — `tools/dos2_layout.py` (`info`, `pair`, `code`, `dis`, `ei`, `consts`, `summary`, `codediff`, `json`; описание в шапке файла).
Сырые выгрузки (не в git): `work/uimodes/layout/ipad/*.json`, `sw/*.json` (все экземпляры, EI, строки раскладки, константы),
`summary_all.txt`, `pair_<фильм>.txt`, `codediff_<фильм>.txt` (разница кода PC → `_t` по методам).

Обозначения. «Сцена» — координаты в px сцены фильма (Flash, ось y вниз). `W` — ширина экрана в px дизайна при высоте 1080:
iPad Pro 11" (2388x1668) `W = 1546`, 16:9 `W = 1920`, телефон 20:9 `W = 2400`. Коробка `x0,y0..x1,y1 (ш x в)` — границы того, что
нарисовано (с прозрачными краями картинок, поэтому видимая часть бывает меньше). **И** = измерено (таймлайн / константа / код),
**В** = выведено (логика, не проверено прогоном).

## 0. Коротко

1. **Почти вся раскладка iPad — статическая**: `_t`-фильм рисуется в «fixed» по высоте экрана и ставится движком по якорю к краю
   (`setAnchor`), элементы стоят на таймлайне. Код AS3 двигает немногое: хотбар (слоты строятся циклом), полосы `statusConsole_t`
   (сдвиг вверх на 117), портреты (столбик с шагом `spacing_mc.height`), колонка панелей (`listDisplay`, шаг 80).
2. **Главный множитель касания — 1,52**: ячейка 76 px против 50 у PC (`touchConstants.CELL_SIZE = 76`, `hackScaling = 1.52`,
   `invCellFactorTouch = 1.52`). Окна панелей — стандартное окно 1160 x 1040…1080 по центру экрана
   (`STANDARD_WINDOW_WIDTH = 1160`) вместо PC-окон 680 px у края. Кнопка закрытия 50x50 вместо 23x23.
3. **Движок iPad сверх общего правила (масштаб по высоте экрана и настройка «масштаб UI») добавляет только масштаб класса**: 1,1 для
   портретов (`playerInfo_t`, тип 0x96 и 0xa8); особого «тач-масштаба» по размеру экрана нет (§1). То есть, чтобы PC-фильм выглядел
   как iPad, его надо **переставить и увеличить в самом фильме**.
4. С видео (`TOUCH_MODES_PLAN.md` §1) сходится почти всё в пределах ±10 px; расходятся: число слотов хотбара (в фильме 12, на видео 13),
   кнопки у хотбара (справа их две), кнопки у миникарты (другой набор), верх портрета (y 20 против 8). Таблица — §4.
5. Нет в PC вовсе (рисовать): колонка панелей и шлем, ☰, круг «ПОДТВЕРДИТЬ» и ✕, лупа, плашка действия над объектом, 5 переключателей
   миникарты + быстрое сохранение, выбор колоды и полоса колод, зона «бросить предмет». Остальное — переставить / увеличить PC-экземпляр.

## 1. Как iPad ставит фильм на экран (движок, `Divinity Original Sin 2` Mach-O, адреса VA)

| что | где | как (И — по коду) |
|---|---|---|
| чтение переменных фильма | `0x1004a9480` (UIObject) | `root.layout` → `+0x50`: fitHorizontal 1, fitVertical 2, fixed 3, fit 4, fill 5, fillVFit 6; `isDragging` `+0x30`; `isUIMoving` `+0xe1`; `uiScaling` есть → `+0xe0`; `keepCustomInScreen`; при флаге `+0x16` бит 0 — `uiLeft/uiRight/uiTop/uiMinHeight/uiMinWidth` (`+0x7c/+0x84/+0x80/+0x8c/+0x88`); `anchorId/anchorPos/anchorTPos/anchorTarget` (`+0xa0/+0xc0/+0xd0/+0xb0`) — якорь без вызова `setAnchor` |
| размер на экране | `0x1004aa918` (OnResize, `w, h` экрана; `W, H` сцены → `+0x64/+0x68`) | fitHorizontal: прямоугольник `(w, w·H/W)`; fitVertical: `(h·W/H, h)`; fit / fill: меньшая / большая из двух; **fixed**: `k = h / D · c`, при режиме ввода ≠ 1 (не пад) ещё `k ·= S` и `root.uiScaling = c · k` (`0x1004aabf4`); прямоугольник `(W·k, H·k)` или `setMcSize` · k; **fillVFit**: сцена фильма становится `(w·H/h / c, H / c)` (форма экрана), прямоугольник = весь экран |
| `c` — масштаб класса (`+0x94`) | `0x1004ab9c0` | 1,0 по умолчанию; **1,1** у `playerInfo_t` (создатель `0x101341174`, тип 0x96) и `UITouchObjectCharacterSwitcher` (`0x101717124`, 0xa8); у одного мирового UI-класса (`0x101688b80`) `1 + (1 − t)·k` от зума камеры `t` |
| `S` — настройка «масштаб UI» | `[[0x101ec58a8] + 0x34]` | **В**: то же смещение `+0x34`, что у Switch (`DOS2_PORT.md`: `main+0x2bb8a60 +0x34 = 0.9` «масштаб UI»); строка опции `UIScaling` есть; значение по умолчанию на iPad статикой не найдено |
| `D` — опорная высота | `u32 [[0x101d98648] + 0x100]` | статикой не прочитана. **В**: PC/`_t`-фильмы нарисованы под высоту 1080. Switch-замер (`TOUCH_CONSOLE_PLAN.md` §13: `minimap_c` в окне 2400x1080 при масштабе 1,3, режим пада → без `S`) даёт на Switch `D ≈ 830` при той же формуле. **Уточнено 19.11 по коду Switch (`main+0xae3be0`, ветка `0xae3c8c`; `TOUCH_MODES_PLAN.md` «Implemented: touch HUD»): `D = [uimgr+0x110] = 1080`, а 1,3 у `minimap_c` — это `c · S` (масштаб класса из настроек · «масштаб UI»); `S` на Switch применяется в любом режиме ввода, `root.uiScaling = c · S` (без `h / D`)** |
| положение | EI `setAnchor(свояТочка, цель, точкаЦели)` / `setPosition(...)` (один раз) | цель `screen`, `splitscreen`, `mouse` или чужой `anchorId`; точки `top, bottom, left, right, center, topleft, topright, bottomleft, bottomright` |

Следствия. «fixed»-фильм с высотой сцены 1080 при `S = 1, c = 1` рисуется 1:1 в px дизайна; его точка якоря совпадает с точкой экрана.
Отсюда правила пересчёта сцены в экран (дизайн 1080): `bottom` — `x + (W − ширина сцены)/2`, `y` как есть; `topright`, `right` —
`x − (ширина сцены − W)`, т. е. «правый край − (ширина сцены − x)»; `topleft` — как есть; `center` — `x + (W − ширина)/2`, `y + (1080 − высота)/2`.
**Открытый вопрос** (В): PC `hotBar` в `onEventResolution` считает видимую ширину как `(w/h)·1080/uiScaling` — это верно, только если
`uiScaling` не содержит `h/D`; по коду движка содержит. Проверить фактический `k` на телефоне (строки `HUD rects` гибрида) прежде, чем
переносить числа: все цифры ниже — в px дизайна 1080, на Switch их надо делить на лишний множитель `1080/D`, если он там есть.

## 7. Что измерено и что нет
- **И**: все коробки (таймлайн кадра 1, матрицы перемножены от корня, маски обрезают), константы и присваивания кадра 1, формулы из
  дизассемблера ABC, якоря и `setPosition`, EI на каждом элементе, формулы движка из §1 (дизассемблер Mach-O).
- **В**: значения `D` и `S` движка; что видимая картинка кнопок меньше коробки; порядок кнопок колонки; положение лупы движком;
  перевод видео в px (±8 px по `TOUCH_MODES_PLAN.md`).
- Не сделано: элементы, которые AS3 создаёт по данным игры (содержимое списков, иконки статусов, пункты меню), сняты только как размеры
  ячеек / шаги; кадры кроме первого (кнопки с состояниями) — через `--all-frames`.
