# DOS2: касание, второй круг (18.11.2026, ветка `dos2-touch6`)

Просьбы хозяина с телефона (играл пальцем) и что сделано. Всё — статика (SWF / ABC / `main.raw` 4979b200) + сборка; **на телефоне не
запускалось** (телефон был у хозяина). Пак: `work/touch2/TouchUI.pak` (набор `hints` + новый проход), APK этой ветки.
Работает только с паком TouchUI (`DM_DOS2_TOUCHUI` по умолчанию включён, когда пак есть); пад не тронут.

Новые файлы / правки: `tools/dos2_taps5_touch.py` (пятый проход по `_d`-фильмам, только дописанные методы), `tools/dos2_touchui_pak.py`
(вызывает его между `taps4` и `hudrect`; `--no-taps5` — без него), `tools/dos2_hudrect_touch.py` (прямоугольники подсказок хотбара),
`dm/host/hle_dos2_touch.c`, `hle_dos2_touch_world.c`, `hle_dos2_touch_gesture.h` + `tests/dos2_touch_gesture_test.c`.

## 1. Долгое нажатие на навык хотбара = его подсказка (как в быстром доступе по Y)

- `bottomBar_d`: палец на слоте ≥ 0,5 с без сдвига (18 px) → штатный `slotsHolder.selectSlot(n, true)` (рамка + `Slot.onMouseOver` → EI
  `SlotHover`, как курсор пада). Фильм показывает ответ движка только при `active` (панель раскрыта по Y), поэтому `updateTooltip` обёрнут
  (`dmTtUpdOrig`): пока просили мы — идёт с `active = true`. Подсказка остаётся после отпускания, следующее касание где угодно её убирает
  (`hideTooltip` + EI `SlotHoverOut`). Удержание не нажимает навык (`dmSlotN` прохода `taps` сбрасывается).
- Запасной путь: если за 0,7 с подсказка не пришла — EI `dmPadBtn(4)` (Y = быстрый доступ, путь пада), затем, когда панель активна, тот же
  слот выбирается — подсказка как у пада. Панель тогда остаётся раскрытой (закрыть — «отмена» / B, как с падом).

## 2 + 6. Сохранения: загрузка (главное меню) и сохранение (в игре) — один фильм `saveLoad_d` (тип 0x4a)

- Тап по записи (в т. ч. «Новое сохранение») = штатный выбор `loadSave_mc.setCursorPosition(i)` (то же, что ↑/↓: EI `selectedEntry`, панель
  сведений); тап по уже выбранной = `loadSave_mc.actionPressed()` = A пада (`loadPressed` / `savePressed` (перезапись спросит окно) /
  `newPressed`). Запись засчитывается, только если видна и палец внутри рамки списка (`list.frameHit`). Прокрутка — двумя пальцами, как раньше.
- Подсказки внизу («(A) … (X) Удалить (B) Назад …», `btnContainer_mc`) — по своему списку элементов, как строка подсказок настроек
  (`dos2_taps3_touch.add_hintbar`): нажать+отпустить на подсказке = EI `dmPadBtn(iconId)`. Общий штамп с проходом подсказок `taps3` — двойного нажатия нет.

## 3. Инвентарь: меню предмета (X) пальцем + аудит панелей

- `partyInventory_d`: **долгое нажатие на предмет (≈0,6 с) = меню предмета**: предмет под пальцем выбирается
  (`larInventory.selectItem(getSlotForMousePosition)`), штатное состояние удержания / перетаскивания сбрасывается (как в его `holdTimerEnded`),
  затем EI `dmPadBtn(3)` = X пада (`ControllerContextMenu` → `panel_1.showActionMenu`). Штатный 300-мс таймер удержания `larInventory`
  (EI `showActionMenuItem`, на телефоне меню не давал) на каждом нажатии останавливается — второго меню не будет. Тап = выбор, двойной тап =
  использовать, сдвиг > 20 px = перетаскивание — как было. В режиме мультивыбора долгое нажатие ничего не делает.
- `inventorySkillPanel_d` (половина предметов): то же, меню — `inventory_mc.cursorShowActionMenu()`.
- `equipmentPanel_d` (у куклы и её инвентаря не было кода мыши совсем): тап по слоту куклы / ячейке = выбрать (`doll_mc.selectSlotByPos` /
  `eqInv_mc.selectSlot`, курсор пада и подсказка), тап по выбранному = `mainpanel_mc.cursorAccept()` (A: что надеть / надеть), долгое
  нажатие = выбрать + `cursorShowActionMenu()` (X). Ячейки, прокрученные за рамку (scrollRect / маска предков), не ловятся.
- **Хост** (`hle_dos2_touch.c`): палец на меню / панели (мир на паузе) раньше не давал нажатия, пока его не поднимут (тап = нажатие+отпускание
  в одном опросе), а долгое нажатие превращалось в правый клик, который консольные фильмы не слушают. Теперь неподвижный палец через 200 мс
  получает левое нажатие, удерживаемое до отпускания (`DM_DOS2_TOUCH_UI_PRESS_MS`, 0 = как раньше); только UI контроллера (PC-UI сохраняет
  правый клик). Тап остаётся тем же кликом. Без этого не работали бы долгие нажатия в панелях.
- Аудит (что пальцем ещё нельзя): **торговля `trade_d`** — ячейки обеих сеток без кода мыши (выбор только стиком; ряд кнопок iPad: вкладки,
  весы, окно, ✓ — есть). Модель торговли сложнее (активное окно `switchActiveInventory`, всплывающий инвентарь бартера) — не сделано в этой
  ветке, следующий шаг: тот же приём, что у экипировки, по `normalInventory_4.selectSlot` / `barter_24.selectSlot` + `trade_1.selectItem`.
  Лист персонажа (`statsPanel_d`): вкладки, +/−, инфо — кнопками ряда (сделано раньше); ремесло: ✓ / инфо / список — ряд; смена персонажа
  в инвентаре (правый стик) — по-прежнему нет кнопки.

## 4. «Кинуть» (Throw Item) и другие режимы прицеливания: тап = цель, а не ходьба

- Что нашлось (`main.raw`): пункт контекстного меню «Кинуть» = `hbce667b6…` («Throw Item», `russian.xml` «Кинуть»), действие 0x1b
  (`main+0xfcd3f8`); прицеливание броска — задача контроллера ввода типа 2 (атака / навык: `main+0xe1de50`, vtable `main+0x29c9cf0`, в её
  коде строки «Cast skill», «Target is too heavy», «Target is too far!»). PC-клик тапа шёл через общий путь Action1 с байтом режима 0 →
  предпросмотр «идти в точку» → ходьба отменяла бросок (тот же класс, что бочка, `TOUCH_CONSOLE_PLAN.md` §15.2–15.3).
- Сделано — приём бочки: пока у контроллера предпросмотр **или** текущая задача типа из `DM_DOS2_TOUCH_AIM_TYPES` (по умолчанию `2`),
  он в «режиме цели» (`dt_target_task`): нет окна PC-пикинга, у пальца на мире нет мышиных записей, тап = селектор пада в точку земли под
  пальцем (`[helper+0x108]+0x30`), затем A пада, когда предпросмотр снова этого типа (или через 0,5 с). Подготовленный навык — та же задача,
  его тап идёт так же (близостный выбор селектора берёт персонажа у точки). `DM_DOS2_TOUCH_AIM=0` — как раньше (PC-клик).
- Риск: тип 2 — статический вывод. Если в бою предпросмотр 2 появляется просто от наведения пада на врага, тап по полу будет «селектор + A» =
  ход пада в точку (с задержкой ≈0,5 с) — тот же результат, но без PC-контура под пальцем. Лог `DM_DBG=1`: `[world] aim mode (throw / prepared
  skill): … previews task type N, runs M`, `[touch] world tap … AIM (throw / aim mode …)`, `[world] placement: ray from the finger … -> ground`,
  `[touch] placement tap: pad A pressed …`.

## 5. Подсказки боя пальцем

- «Удерживайте B чтобы закончить свой ход» (`endTurnHint_mc` / `holdEndTurnHint_mc`, или инфо-кнопка с иконкой B в бою): нажатие = собственный
  `onEventDown("IE UIEndTurn")` фильма, отпускание = `onEventUp` — ровно удержание B пада: круг заполняется, `animationDone` шлёт EI `endTurn`;
  короткий тап только начинает / сбрасывает круг, как B.
- Ряд «(A) перейти  (X) действия» над хотбаром (`bottombar_mc.btnList`, `BtnInfo.iconId` = код кнопки): нажать+отпустить = EI `dmPadBtn(iconId)`
  (A хост жмёт через 750 мс — защита «тап ≠ A»). На этих элементах пустые слушатели `mouseDown` — нажатие считается UI, не миром.
- Если слушатели элементов на телефоне не сработают (так бывало), хост всё равно знает их места: `dos2_hudrect_touch.py` шлёт `btn<код>`
  для каждой инфо-кнопки и `hold1` для подсказок конца хода; мировой тап в `btn/hold` = эта кнопка (`dt_hint_tap`), а палец, удержанный в
  `hold<код>`, держит кнопку пада до отпускания (`dt_hold_hint` → `dt_pad_hold`, новое в `dm_dos2_touch_pad_pump`). Подсказка над целью
  «(X) Действия…» (`overhead_d`, `hint3`) — как раньше.

## 7. Регрессия: после touch6 каждое касание в мире «брал» хотбар (ветка `dos2-touch7`, 18.11)

- **Симптом** (телефон хозяина, APK из `53264d6`, пак sha `8edc3563…`; лог `src/work/logs/C_base.log`, до touch6 — `nrB_mat.log`): тап по песку
  не ведёт персонажа, свайп одним пальцем не крутит камеру, иконки левой колонки (`dmColumn_d`, 0x8d) не жмутся, строка подсказок
  «(A) перейти (X) действия» мигает на каждом касании. В логе на каждое нажатие `world: the left press at 1340,600 was TAKEN by a UI object:
  mouse gesture (… UI type 0x3b)`, `presses the UI took 22`, у `Action1` — `world clicks 0`, `walks started by a click 0`. Двумя пальцами
  камера крутится, подсказка навыка по долгому нажатию работает.
- **Причина:** `tools/dos2_taps5_touch.py` (п. 1 / 5 выше) повесил `mouseDown` / `mouseUp` на **stage** `bottomBar_d`. Нажатие, не попавшее ни в
  один элемент фильма, адресуется самому stage — слушатель срабатывает, и Iggy отвечает `handled 1` в любой точке экрана (`Iggy button …
  bottomBar_d.swf … code 1 … -> handled 1` в 22 нажатиях из 22; в `nrB_mat.log` те же точки — `handled 0`; отпускание тоже `handled 1` от
  stage-`mouseUp`). Диспетчер UI `main+0xaea7b0` пишет этот ответ в `[x5]` (`0xaea8d4`): объекты ниже (колонка) получают «нажатие взято
  верхним» (`flag 1`), нажатие захватывает мышь (`[uimgr+0x10d]`, `[uimgr+0x218]`, `0xaea8ec`), ввод не становится `Action1` мира — даже
  PC-клик тапа, пошедшего по таймауту, до мира не дошёл. Пустые слушатели на `btnList` / подсказках конца хода тут ни при чём: их область мала.
- **Фикс — на хосте, пак не меняется** (`hle_dos2_touchui_route.c` п. 5): для фильмов со stage-слушателем (`DM_DOS2_TOUCH_STAGE_TYPES`, по
  умолчанию `3b`) в игре ответ «handled» на левую / правую / среднюю кнопку остаётся за фильмом, только если палец (курсор UI) внутри
  живого HUD-прямоугольника ЭТОГО фильма (`dmHudRects` из `dos2_hudrect_touch.py`: `hotbar` = `bottombar_mc` вместе со строкой подсказок,
  `btn<код>` / `hold<код>`, вшитые кнопки `dmVis*`, `hint4`; запас `DT_HINT_SLOP` = 1,2 % высоты). Снаружи хост обнуляет `[x5]` и возвращает
  захват мыши как был: слушатель фильма уже отработал (тап где угодно по-прежнему прячет подсказку навыка), нажатие идёт объектам ниже
  (колонка) и миру. Нет живых прямоугольников фильма (`DM_DOS2_HUDRECT=0`, фильм молчит > 5 с) — ответ фильма остаётся (как в touch6).
  Сайт захвата сверяется словами (`k_rt_capture`). `DM_DOS2_TOUCH_STAGE_TYPES=0` — поведение touch6.
- Шесть функций touch6 не задеты: подсказка навыка (палец на слоте — внутри `hotbar`), загрузка / сохранение и инвентарь / экипировка (не
  `bottomBar_d`, это меню и панели: мир там и так на паузе), «Кинуть» (мировой тап — теперь снова доходит), подсказки боя (`btn` / `hold`
  внутри прямоугольников — нажатие остаётся за фильмом, его `dmT5Down/Up` и хостовые `dt_hint_tap` / `dt_hold_hint` как раньше).
- **Тест:** `dm/host/tests/dos2_touch_gesture_test.c` — тап по песку (1340,600 / 1060,520 / 1500,620 / 900,620) при показанной строке
  подсказок не взят; тап по иконке колонки (чужой фильм) не взят; «(A) перейти», «(X) действия», слот хотбара, `dmVisOpt_mc`, `hint4` —
  взяты; устаревшие / нет прямоугольников — ответ фильма остаётся.
- **На телефоне** (`DM_DBG=1`), тап по пустой земле: `[route] left press at 1340,600: bottomBar_d.swf (type 0x3b) answered it with its stage
  listener, outside its HUD rects: NOT taken (the objects below and the world get it)`, затем `[touch] world: the left press at 1340,600 was
  taken by no UI object: the finger is the world's` и `[touch] world tap at 1340,600: PC click …`; в сводке `[route] … stage-listener movies:
  button events given back N` и `world … presses the UI took 0`. Без `DM_DBG` первые 6 строк `NOT taken` пишутся всё равно.

## 8. Колёса ZL / ZR пальцем и левым стиком (ветка `dos2-touch7`, 18.11)

- **Какие фильмы:** `panelSelect_c.swf` (UI 0x53, событие «IE PanelSelect»: инвентарь / навыки / карта / журнал …; stage 1200x1080,
  `radialHolder_mc` в 600,470) и `partyManagement_c.swf` (0x52, «IE PartyManagement»: отряд, A — группировка; stage 1920x1080, колесо в 960,470).
  Оба открыты, пока зажата их кнопка пада (`onEventDown` → `openMenu`), выбор — на ОТПУСКАНИИ (`onEventUp` → `closeMenu(true)` → EI
  `openPanel(id)` / `setActiveChar(id)`). Какая из ZL / ZR какое колесо — на телефоне не сверено; хосту не важно.
- **Как кормится выбор:** `onFrame` фильма: `atan2(stickVAxis, stickHAxis)` → `list.selectDirectionRad` (стрелка `indic_mc`). Переменные
  пишет движок каждый кадр (`main+0x1219020..0x1219130`, SetVariable vt+0x58): `stickHAxis = Right − Left`, `stickVAxis = Down − Up` из событий
  `UIRadialLeft/Right/Up/Down` (id 0x126..0x129: `main+0x108cc40..0x108ce48`), оба 0, если длина < 0,75 (выбор тогда остаётся прежним).
  Эти события — правый стик пада.
- **Что сделано (хост, `hle_dos2_touch.c` раздел radial, правила в `hle_dos2_touch_gesture.h` `dt_radial_*`):** пока колесо видимо
  (`dm_dos2_route_player`, обход объектов UI):
  - палец на экране = правый стик npad от центра колеса к пальцу на полный наклон (мёртвая зона 7 % высоты); ведение пальцем = подсветка
    следует; центр — по прямоугольнику FlashPlayer фильма (+0x10..+0x1c, как `dt_player_fit`) и месту колеса на stage;
  - палец поднят вне мёртвой зоны = **выбор**: стик держится ещё 120 мс (`DM_DOS2_TOUCH_RADIAL_MS`), затем зажатый игроком ZL / ZR
    «отпускается» для игры (`dt_radial_release` в `dm_dos2_touch_pad_pump`) и остаётся отпущенным, пока игрок сам его не отпустит
    (иначе колесо открылось бы снова); поднят в центре — ничего (как пад: отпустить курок самому);
  - левый стик пада (экранного / железного) ведёт колесо, пока правый в покое; левый при этом обнуляется (персонаж не идёт);
  - правый стик пада главнее всего (палец и левый стик заполняют только покоящийся правый).
  Колесо отряда (0x52) добавлено в «меню» `dm_dos2_route_world_ok` (как 0x53 раньше): жесты мира на паузе, плавающего стика нет — палец идёт колесу.
- Переключатели: `DM_DOS2_TOUCH_RADIAL=0` (всё выкл.), `DM_DOS2_TOUCH_RADIAL_LSTICK=0` (без левого стика), `DM_DOS2_TOUCH_RADIAL_MS`.
- **Тест:** `dos2_touch_gesture_test.c` — центр по прямоугольнику, направление стика = угол колеса (вправо 0, вверх −π/2, вниз +π/2,
  вниз-влево 3π/4), длина > 0,75, левый стик → правый (и не перебивает правый пада), «отпускание» курка до реального отпускания.
- **На телефоне:** зажать ZL (или ZR) на паде, другим пальцем коснуться пункта колеса — подсвечивается, поднять палец — открывается панель
  (или выбран персонаж), колесо закрыто, пока курок не отпустят и не нажмут снова. Лог: `[touch] radial: panelSelect_c (panels) (UI type 0x53)
  is open, centre 1200,470 …`, `[touch] radial: finger up at …: choose …`. Если подсветка не идёт за пальцем — движок не связывает
  `UIRadial*` с правым стиком npad (прислать лог); если не совпадает сектор — прислать `centre …` и точку пальца.

## Шаги на телефоне (пак `work/touch2/TouchUI.pak` → `<romfs>/Data/TouchUI.pak`, APK ветки, env как обычно + `DM_DBG=1`)

1. Главное меню → «Загрузить»: тап по сохранению — выделение переезжает, справа сведения; второй тап по нему — загрузка. Тап по подсказкам
   внизу (Удалить / Назад) — как кнопки пада. Лог: `[touch] dmPadBtn(95x)` (трассы строки подсказок), `pad button … (hint tap, BTN code N)`.
2. В игре: меню → «Сохранить»: тап по «Новое сохранение» → выделение, второй тап — новое сохранение; тап по старому, второй тап — окно
   «перезаписать?» (его кнопки — тапом, как раньше).
3. Хотбар: удержать палец на навыке ~0,5 с — над панелью подсказка навыка; поднять палец — подсказка остаётся; тап где угодно — исчезает;
   навык при этом не применяется. Если подсказки нет, а через ~0,7 с раскрылась панель быстрого доступа с подсказкой — сработал запасной Y
   (сообщить: значит, движок не отвечает на `SlotHover` в свёрнутой панели).
4. Инвентарь: удержать палец на предмете ~0,6 с — меню предмета (как X). Короткий тап — выбор, двойной — использовать, тянуть — перетаскивание.
   То же в половине предметов панели навыков. Экипировка: тап по слоту куклы — выбор, второй тап — список вещей, тап по вещи — выбор, второй — надеть;
   удержание — меню (X). Лог: `[touch] UI finger still 200 ms … left press now`, `pad button 0x… (hint tap, BTN code 3)`.
5. Инвентарь → предмет → «Кинуть»; тапнуть по земле в 3–5 м — предмет летит туда, персонаж не бежит. Лог: `[world] aim mode … task type 2`,
   `world tap … AIM`, `placement tap: pad A pressed`. Если строки `aim mode` нет — прислать `[world] … preview task type N` в режиме броска
   (тогда `DM_DOS2_TOUCH_AIM_TYPES=N` и поправить умолчание). Проверить и навык с прицелом: тап по цели / земле.
6. Бой, свой ход: удерживать палец на «Удерживайте B…» — круг заполняется, ход заканчивается; отпустить раньше — круг сбрасывается.
   Тап по «(A) перейти» / «(X) действия» — как A / X пада. Лог: `pad button 0x… HELD for the player (held hint (hold1))` (если сработал хостовый путь).
7. Пад: всё как раньше. Откат по частям: пак `--no-taps5`; `DM_DOS2_TOUCH_UI_PRESS_MS=0`; `DM_DOS2_TOUCH_AIM=0`.
