# DOS2: один обработчик касания для всего интерфейса — разбор и устройство (20.11.2026, ветка `dos2-uimodes`, HEAD 846e3a5)

Просьба хозяина 20.11: «В гибриде не помешало сделать тапы в полуконсольном-полуайпадовском интерфейсе. В идеале — перевести всё на ОДИН
обработчик (или переписать в консольные, если так проще), чтобы весь интерфейс работал по одному алгоритму».

Этот документ — разбор и устройство, **кода не меняет** (параллельно другой агент чинит хост; перенос — следующий шаг). Всё ниже — статика:
документы `TOUCH_MODES_PLAN.md`, `TOUCH_CONSOLE_PLAN.md`, `TOUCH2.md`, `TOUCH_VISIBLE.md`, `TOUCH_UI_AUDIT.md`, шапки и тела инструментов
`tools/dos2_*touch*.py`, `tools/dos2_ppanel_*.py`, `tools/dos2_ptouch_gaps.py`, файлы хоста `dm/host/hle_dos2_touch*.c|h`, `hle_dos2_uimode.c`.
На телефоне ничего не запускалось. Обозначения: **Г** — режим «гибрид» (байт режима ввода `main+0x2bb8918` = 1, консольные классы, наши
`_d`), **К** — режим «касание» (байт 0, PC-классы, наши `_p`), «тип» — номер типа UI движка (`[obj+0xf0]`).

## 0. Коротко

1. **Сейчас у касания пять разных механизмов**, а у одной функции бывает до пяти путей (подсказки-кнопки: слушатели элементов
   `dos2_hint_touch.py` → обход дерева `dos2_taps3_touch.py dmHgWalk` → список `add_hintbar` → прямоугольники хоста `hint<код>` / `btn<код>` →
   свой проход `msgBox_d`). Жесты распознаются в трёх местах: хост (`dt_step`, два набора правил: гибрид и `dt_t1_*`), сами фильмы (таймеры
   удержания 300 / 500 / 600 мс, двойные тапы 450 / 500 / 550 мс, «тап по выбранному = принять» без окна времени) и Flash (родной двойной щелчок PC).
2. **Главные расхождения** (§2): долгое нажатие значит шесть разных вещей (подсказка, меню предмета X, контекстное меню, открыть инвентарь,
   флажок на карте, удержание A / B); двойной тап — пять окон времени и два разных смысла у портретов (лист персонажа в Г, камера в К);
   стражи «тап ≠ принять» и модальности — четыре разных в Г и ни одного хостового в К; в К пальцы над PC-панелями идут пробным нажатием мира.
3. **Найденные ошибки по коду** (§2, Р1–Р4 — высокая уверенность по чтению кода, на телефоне не проверялись):
   - Р1: в К `dm_dos2_route_world_ok` не знает PC-типов панелей (0x74, 0x77, 0x29, 0x66, 0x16, 0x2e, 0x0e, 0x88, 0x2f, 0x68, 0x15 — у них нет
     модальных битов), поэтому при открытом инвентаре / листе / навыках / торговле / диалоге в игре палец идёт **пробным нажатием**: взял фильм →
     `G_DRAG`, и у пальца больше нет ни подсказки (350 мс), ни контекстного меню (600 мс), ни второго щелчка двойного тапа «в точке первого»;
   - Р2: то же для HUD К в игре (`hotBar_p`, `playerInfo_p`, `dmSide_p`): долгое нажатие на слот = зажатая кнопка → отпускание = щелчок = навык
     применён; долгое на портрете не даёт правого щелчка → обработчик `openCharInventory` хоста (`hle_dos2_touch_gaps.c`) в игре не сработает;
   - Р3: в К все `dmPadBtn` (заставка «Нажмите A», ряды подсказок `optionsSettings_d` / `saveLoad_d` / `characterCreation_d` / `mods_d`, которые
     К оставил с 1641f15) — это импульс npad при байте режима 0; фильтр слушателей `0x844014` в этом режиме отбрасывает записи пада у тех, кто
     их не просит; живое переключение, которое раньше их «ловило», в К выключено (846e3a5). Скорее всего эти тапы в К мертвы;
   - Р4: в К `hle_dos2_touchui_route.c` снимает при байте 0 и страж модальности, и страж «тап ≠ принять» для **всех** объектов — включая
     консольные `_d`-меню, которые К оставил; остаётся только правило движка «флаг 0x200» и собственные стражи фильмов.
4. **Рекомендуемое устройство** (§3): один распознаватель — хост (чистые правила `hle_dos2_touch_gesture.h`, тайминги iPad: тап, двойной
   300 мс, короткое долгое 350, долгое 600, тяга, прокрутка одним и двумя пальцами — одинаково в Г и К); одна цель — её выбирает хост по
   прямоугольникам, которые шлют фильмы (без пробного нажатия); одна доставка — событие ввода `IE dm*` ровно одному объекту UI (механизм
   `hle_dos2_touchui_ie.c`, адресно); один разбор в фильме — общий код `dmTouch` (реестр элементов, попадание, исполнение), вставляемый одним
   проходом; одна карта на фильм (данные: путь экземпляра → глагол → действие); один словарь действий (`native`, `ei:`, `call:`, `ie:`,
   `pad:`, `host:`, `scroll:`); один страж модальности и один страж «тап ≠ принять» — в хосте, для обоих режимов.
5. **Консольные `_c` или PC** (§4): у HUD и игровых панелей класс движка выбирает байт режима при сборке набора игрока, поэтому два семейства
   фильмов остаются (Г — `_c` + `dmTouch`, К — PC + `dmTouch`), а общими становятся код касания, карта глаголов экрана и договор хоста. Меню вне
   игры (главное, настройки, сохранения, моды, создание персонажа, окно сообщения) — консольный класс в обоих режимах: **один фильм** `_c` +
   `dmTouch` на оба. Общие фильмы (портреты `playerInfo.swf`, `statusConsole.swf`, `containerInventory.swf`, `subtitles.swf`, `overhead.swf`) и наш
   тип 0x8d (`dmColumn_d` / `dmSide_p`) — **один фильм** на оба режима. Переписать всё в консольные нельзя дешевле: в К нужны PC-привязки
   (камера клавишами, PC-перетаскивание, наведение), в Г — пад, а пад жив только при байте 1.
6. **Перенос** (§5): ≈ 53–76 ч агента и 11–14 коротких прогонов; первым — опыт на один прогон (доходит ли адресное `IE dm*` до фильма), затем
   ядро без экранов, затем наш тип 0x8d (самый безопасный), общие фильмы, меню вне игры, HUD, панели парами, в конце — удаление старых путей.

## 1. Что есть сейчас

### 1.1 Пути хоста (как касание доходит до фильма)

| знак | путь | где | когда |
|---|---|---|---|
| **Х1** | мышь через общий фильтр: байт `[mgr+0x170]` открыт / закрыт по окнам (`dm_dos2_touchui_gate`, KBM=2) | `hle_dos2_touch.c dt_drain` | Г, без перехвата маршрутизации (запасной путь `DM_DOS2_TOUCH_ROUTE=0`) |
| **Х2** | адресная мышь: перехват `0xaea7b0`, список разрешённых типов (группы `hud` / `ctx` / `panels` / `dialog` / `menus`), страж модальности (биты 0x1e00), страж «тап ≠ принять» (`UIAccept` ≤ 600 мс после левой записи касания, если A npad не нажимался 300 мс), правило «слушатель сцены» для типов `DM_DOS2_TOUCH_STAGE_TYPES` (по умолчанию только 0x3b) | `hle_dos2_touchui_route.c rt_hook` | Г: в меню и в игре |
| **Х3** | мышь PC-режима: при байте 0 `rt_hook` ничего не фильтрует (`pcui`), раздаёт движок (родное правило 0x200), стражей нет | `rt_hook`, ветка `pcui` | К |
| **Х4** | пробное нажатие мира: палец в игре без «меню» шлёт левое нажатие сразу; взял объект UI → мышиный жест (`G_DRAG`), не взял → палец мира | `dt_step` → `G_WPROBE`, `dt_world_poll`, `dm_dos2_route_taken` | оба режима, «меню» по `dm_dos2_route_world_ok` (только консольные типы, Р1) |
| **Х5** | мир: PC-щелчок от пальца в режиме контроллера (`DM_DOS2_TOUCH_WORLD=3`: окно PC-пикинга, `Action1` с байтом 0, `0xe151f0` = 1 для пола), режимы цели (тип 10 «переместить», тип 2 «кинуть / навык»: селектор пада + A) | `hle_dos2_touch_world.c`, `dt_w3_*`, `dt_place_tap` | Г; в К — только щелчок `dt_w3_tap_t` и плашка действия |
| **Х6** | прямоугольники фильмов (`dmHudRects`): `hint<код>` / `btn<код>` = мировой тап там = кнопка пада, `hold<код>` = удержание кнопки, `dt_hud_hit` для плавающих стиков Java; запасной путь миникарты `dt_minimap_tap` (тап по области = «−») | `dt_ei_hudrects`, `dt_hint_tap`, `dt_hold_hint`, `dt_minimap_hit` | Г (К прямоугольников не шлёт) |
| **Х7** | жесты К по `touchscreen_1.json`: тап = левый щелчок, двойной = второй щелчок в точке первого, короткое долгое = наведение без щелчка, долгое = правый щелчок, ведение одним / двумя пальцами = клавиши `w a s d`, поворот = `delete` / `end`, щипок = удержание `pageup` / `pagedown`, тап 2 / 3 пальцами = `lalt` / `lshift`, свайп 3 пальцами = `o` | `dt_t_*`, `dt_tm_*`, `G_TMULTI` | К (байт 0 и HUD-часть режима = касание) |
| **Х8** | особые слои: карта (`G_MAP`: тяга = левый стик против движения, щипок = правый стик y, тап = щелчок UI и через 220 мс курсор + A, если журнал не ответил EI), колёса ZL / ZR (`G_RADIAL`: палец = правый стик) | `dt_map_*`, `dt_radial_*` | Г |
| **Х9** | события ввода iPad `IE Tap` / `IE LongPress` / `IE ShortLongPress` (узлы с id 0x7f01…0x7f03 в хеше `events` фильма, `OnInputEvent` каждому видимому объекту с узлом) | `hle_dos2_touchui_ie.c` | вызывается на каждом тапе в обоих режимах, но действует только на `_t` (их нет в паках): сейчас холостой |

Вызовы фильм → хост (EI, все в сливе `0xd25d90`, поток игры): `dmPadBtn(код)` → импульс npad `dm_dos2_touch_pad_pulse` (A — через 750 мс,
мимо стражей фильмов; второй импульс в 250 мс отбрасывается; от немодального окна под модальным — отказ `dm_dos2_touchui_may_press`);
`dmPanel(id)` → `openPanel` объекту `panelSelect_c` (0x53, `hle_dos2_touchui_vis.c`); `dmColumnPoll(состояние)`; `dmHudRects(строка)`;
`dmSide(1…8)` → escape или `hotbarBtnPressed(id)` PC-хотбару (`hle_dos2_touchui_hud.c hu_ei_side`, правило «одно окно» `hu_view_plan`);
`dmAim`, `dmAimBtn` (левый / правый щелчок в точке прицела), `dmKey(1 | 2)` (f5 / o); `openCharInventory` (портреты К, `hle_dos2_touch_gaps.c`);
`buttonPressed` главного меню (отложенное A при занятом сохранении, `dt_ei_mm_button`).
Хост → фильм: только имена, которые зарегистрировал класс движка, поэтому пять «чужих» каналов: `setActiveInCombat(100 + n)` (`bottomBar_d`),
`addWatermarkText(100 + n)` (`dmColumn_d`), `showActiveSkill(2000000 + x·2000 + y)` (`hotBar_p`, плашка), `setAnchor(1000000 + n)`
(`partyInventory_p`), `setHelmetOptionState(1000000 + n)` (`characterSheet_p`).

### 1.2 Как палец становится жестом в хосте сегодня (`dt_step`, `dt_world_poll`, хвост `dt_drain`)

| палец | тап | двойной тап | неподвижный палец | тяга одним | два пальца |
|---|---|---|---|---|---|
| Г, UI (`G_PENDING`; меню / панель на экране или вне игры) | нажатие + отпускание на отпускании | нет (решает фильм) | **через 200 мс — левое нажатие держится** (`DM_DOS2_TOUCH_UI_PRESS_MS`), правого щелчка нет; дальше решает фильм своими таймерами | сдвиг > 2,5 % высоты → нажатие в точке начала, движение, отпускание | щипок = правый стик y (зум), по горизонтали = правый стик x (поворот, только в игре), по вертикали = колесо |
| Г, HUD в игре (Х4 взял) | щелчок | нет | левое нажатие держится с самого касания | мышиное перетаскивание | как выше |
| Г, мир (Х4 не взял) | PC-щелчок (Х5): пол — идти, объект — действие; в режиме цели — селектор + A | нет | 300 мс: на объекте — 500 мс правый щелчок = «Действия…»; на полу — ходьба за пальцем (левый стик); на `hold<код>` — удержание кнопки пада | до 300 мс правее 40 % ширины — поворот камеры (правый стик x), иначе ходьба стиком | как выше |
| К, UI (`G_PENDING`) | щелчок | второй щелчок **в точке первого** (≤ 300 мс, ≤ 5 % высоты) | 350 мс — отпускание без щелчка (наведение = подсказка PC); 600 мс — правый щелчок + `IE LongPress` | как в Г | первый палец на UI: щипок и вертикаль = колесо |
| К, HUD или PC-панель в игре (Х4 взял, Р1 / Р2) | щелчок | два настоящих щелчка (Flash сам) | **левое нажатие держится с касания**: ни подсказки без щелчка, ни правого щелчка | мышиное перетаскивание | колесо |
| К, мир | тап: объект — плашка действия (круг «Подтвердить»), пол — PC-щелчок; второй тап двойного — ещё щелчок / пропуск ролика | ≤ 300 мс | 350 мс — наведение (или плашка при `DM_DOS2_TOUCH_T_PICK=long`); 600 мс — правый щелчок = `ContextMenu` | клавиши `w a s d` | щипок `pageup` / `pagedown`, поворот `delete` / `end`, сдвиг `w a s d`, тап `lalt`, 3 пальца — `lshift`, свайп `o` |

Жест «Назад» Android: Г — B пада на 110 мс; К — escape (846e3a5).

### 1.3 Опись: каждый касаемый фильм и чем он нажимается

Слушатели: **С** — постоянные слушатели сцены (нажатие / отпускание сцены, попадание считается по живой геометрии), **Эс** — нажатие на
элементе + временный слушатель отпускания сцены (снимается на отпускании), **Э** — слушатели элементов, **Р** — слушатель корня фильма
(всплытие от детей), **N** — родной мышиный код фильма (Larian), **IE** — вызов исходного `onEventDown / onEventUp(индекс)` фильма (путь пада внутри
Flash). «Шлёт» — что уходит движку / хосту.

## 2. Расхождения и их ошибки

**Ошибки в коде (высокая уверенность по чтению; на телефоне не проверено):**
- **Р1.** К: `dm_dos2_route_world_ok` (`hle_dos2_touchui_route.c`) считает «меню» только типы групп `k_groups` (консольные) и объекты с битами
  0x1e00. PC-панели набора игрока созданы хостом с флагами 0x201e0 (`hle_dos2_touchui_hud.c`, таблица 18 типов) — модальных битов нет; окна,
  которые игра делает в режиме 0 сама (торговля 0x2e, диалог 0x0e, награда 0x88, точки 0x2f, делитель 0x15), тоже не в списке. Итог: `dt_world_now`
  = 1, палец идёт через `G_WPROBE`, окно PC-пикинга (`dt_w3_sync`) открывается под панелью, а взятый панелью палец становится `G_DRAG`. В
  `G_DRAG` хвост `dt_drain` правого щелчка не даёт, `dt_t1_release` не спрашивается. Значит, все «долгое = контекстное меню», «короткое
  долгое = подсказка без щелчка», «второй щелчок в точке первого» из разделов TOUCH_MODES_PLAN о панелях в игре не действуют.
- **Р2.** К, HUD в игре — тот же путь: долгое на слоте `hotBar_p` = отпускание = `SlotPressed` (навык применён), подсказка только наведением;
  долгое на портрете `playerInfo_p` = без правого щелчка, `openCharInventory` хоста не вызывается. Отмечено в TOUCH_MODES_PLAN «жесты», риск 5, но
  последствия для портретов и хотбара там не названы.
- **Р3.** К: `dmPadBtn` = импульс npad. При байте 0 фильтр слушателей `0x844014` отдаёт записи класса «пад» (устройства 3…6) только слушателям с
  битом 4, своей маской или классом = байт режима. Раньше нажатие пада в К ловило живое переключение (и пересобирало UI — 846e3a5 это убрал),
  теперь запись уходит в фильтр. Под удар: заставка `mainMenu_d` (`dmPadBtn(2)`), ряды подсказок `optionsSettings_d`, `saveLoad_d`, `mods_d`,
  `characterCreation_d` (все — в таблице К по 1641f15). Опции, строки, пункты меню работают (они зовут AS3 / EI напрямую).
- **Р4.** К: `rt_hook` при `pcui` не применяет страж модальности и страж «тап ≠ принять» ни к одному объекту, включая консольные `_d`-меню вне
  игры. Остаются стражи самих фильмов (400 / 700 мс) и правило движка 0x200. Откуда «щелчок = `UIAccept`» берётся, так и не найдено
  (TOUCH_CONSOLE_PLAN §6), поэтому нельзя сказать, что при байте 0 его нет.

**Расхождения смысла (одна функция — разные жесты по экранам и режимам):**
- **Р5. Долгое нажатие.** Подсказка (слот `bottomBar_d` 500 мс; торговля К — правый щелчок погашен, остаётся наведение), меню предмета X
  (`partyInventory_d`, `equipmentPanel_d`, половина предметов навыков — 600 мс), контекстное меню (инвентарь / контейнер / ремесло / мир К —
  правый щелчок 600 мс; мир Г — правый щелчок 500 мс после 300 мс), инвентарь (портреты К), флажок (карта К), удержание A (обучение) / B
  (конец хода), ходьба за пальцем (пол, Г). У iPad: короткое долгое = подсказка, долгое = контекстное меню / начать перетаскивание, слот хотбара —
  долгое = перетащить.
- **Р6. Двойной тап.** Окна: 300 мс (хост К), 450 (`skills_p`, `trade_p`, `waypoints_p`, `dmTap`), 500 (`playerInfo_d`), 550
  (`inventorySkillPanel_d`), родной двойной щелчок Flash (`larInventory`, PC-фильмы), и «тап по уже выбранному = принять» вообще без окна
  (`saveLoad_d`, `equipmentPanel_d`, строки правки класса в `characterCreation_d`). Смысл у портретов разный: Г — лист персонажа, К — камера.
  В мире: Г — ничего, К — второй щелчок и пропуск ролика.
- **Р7. Тайминги удержаний в фильмах** не совпадают с хостом: подсказка слота 500 + запасной Y 700; меню предмета 600; штатный таймер
  `larInventory` 300 (гасится); раннее нажатие хоста 200; правый щелчок хоста 500 (Г PC-UI) и 600 (К); тап по подсказке ≤ 800 мс
  (`hint_touch`) / ≤ 1,5 с (`taps3`, `taps4`); слот ≤ 700 мс.
- **Р8. Прокрутка.** Одним пальцем — строки настроек (48 px на строку), списки создания персонажа (14 px), диалог (`dialog_c` свой / `dialog_p`
  14 px), журнал К (8 px), рецепты К; везде остальное — только два пальца (колесо). Карта: Г — стик хоста, К — родное перетаскивание PC.
- **Р9. Правый щелчок как сырое событие.** Хост К шлёт фильмам правый щелчок на долгом. У PC-фильмов у правого щелчка свой смысл: торговля —
  `cancel` (закрыть окно; погашено только в `trade_p`), контейнер — `rightClickItem` (мёртвое имя; заменено). Остальные PC-окна по этому признаку
  не проверены — тот же класс ошибок может сидеть в любом.
- **Р10. «Назад».** Г — B пада, К — escape; у консольных `_d`-меню в К escape = `UICancel` только если привязки `keyboard_1.json` загружены.
- **Р11. Одно окно за раз** — только К (`DM_DOS2_TOUCH_ONE_PANEL`); в Г колонка открывает поверх.

**Расхождения устройства (одна задача — несколько механизмов):**
- **Р12. Стражи «тап ≠ принять».** Г: хост 600 мс (в игре — всем; вне игры — разрешённым и `k_block`; никогда — 0x48 / 0x57 / 0x17) + фильмы:
  `hint_touch` 400 мс на `onEventUp / Down`, `executeSelected` 700 мс (`mainMenu_d`, `gameMenu_d`, `msgBox_d`), второй слой 700 мс у
  `characterCreation_d`; A от подсказки нажимается через 750 мс, чтобы пройти мимо всех. К: хоста нет (Р4), у `_p` своих нет.
- **Р13. Стражи модальности.** Г: движок (0x200) + хост (0x1e00, Х2) + отказ `dmPadBtn` / `dmSide` от немодального окна под модальным
  (`dm_dos2_touchui_may_press`; у `dmSide` исключение для 0x74 / 0x77) + `dm_dos2_route_world_ok` по типам. К: только движок. Х9 (`IE Tap`)
  шлёт событие всем видимым окнам сразу — без порядка.
- **Р14. Слушатели сцены.** Постоянные слушатели нажатия сцены (`taps`, `taps3`, `taps4`, `taps5`, `mainmenu`, `list`, `cc`) делают Iggy
  ответчиком «взято» на всю сцену; хост это исправляет только для типов `DM_DOS2_TOUCH_STAGE_TYPES` (0x3b) и только в игре (touch7). Для меню
  это безвредно (мир на паузе), но любой новый HUD-фильм с таким слушателем снова съест мир. Фильмы `_p` используют безопасный образец
  (нажатие на элементе + временный слушатель отпускания сцены).
- **Р15. Слушатели элементов.** Г показал (tw1–tw3), что слушатели на элементах подсказок не срабатывают, а слушатели сцены — да; причина не
  найдена. У `minimap_d` кнопки мыши не доходят вообще. Фильмы `_p` и родной код PC держатся на слушателях элементов — в режиме 0 это обычный
  путь PC, но на Switch-движке не проверен.
- **Р16. Пробное нажатие.** Оно нужно только потому, что хост не знает, где элементы. Цена: задержка до 250 мс на полу, побочные эффекты
  (отменяло «Переместить» — пришлось вырезать особый случай `g.wplace`; прячет подсказку навыка; открывает PC-пикинг), Р1 / Р2.
- **Р17. Каналы хост → фильм** — пять «чужих» имён с числовыми смещениями (§1.1); каждое новое окно требует найти имя, которое зарегистрировал
  его класс.
- **Р18. Пробелы, которые остались только в одном режиме:** Г — ячейки торговли без мыши, выбор награды, смена персонажа в инвентаре,
  количество в ремесле; К — ничего из этого (PC-код), но Р1 / Р2.

## 3. Один обработчик

### 3.1 Принцип: «одно» в каждом звене

| звено | сейчас | будет |
|---|---|---|
| распознать жест | хост (два набора правил) + таймеры фильмов + двойной щелчок Flash | **хост**, одни правила `dt_t1_*` / `dt_is_dtap` / `dt_two_mask` из `hle_dos2_touch_gesture.h` с таймингами iPad, для UI одинаково в Г и К |
| решить, чей палец | пробное нажатие (Х4) + список типов (Х2) + прямоугольники (Х6) | **хост по прямоугольникам**, которые шлёт каждый фильм с `dmTouch`, сверху вниз по списку объектов UI, с правилом модальности |
| доставить | мышь (Х1–Х3), импульсы npad, `IE Tap` всем (Х9) | мышь — **только объекту-цели** (для родного кода: тяга, ползунки, наведение) + **одно событие `IE dm*`** этому же объекту |
| разобрать в фильме | 15 разных проходов | **`dmTouch`**: реестр элементов из карты, попадание, исполнение глагола |
| исполнить | `dmPadBtn`, `dmPanel`, `dmSide`, `dmKey`, `dmAimBtn`, свои EI, `executeSelected` … | словарь действий (§3.3) + один вызов хоста `dmAct(код, a, b)` |
| стражи | 4 вида в Г, 0 в К | один страж модальности и один «тап ≠ принять» в хосте, оба режима |

Почему распознаватель в хосте, а не в AS3 (как было в задании): Iggy даёт фильму одну мышь — два / три пальца, щипок, поворот фильм не увидит;
мир распознаёт хост в любом случае; два распознавателя с одинаковыми числами — это то расхождение, которое мы и убираем. AS3-распознаватель
остаётся **запасным** (§3.2, п. 7) на случай, если опыт М0 покажет, что событие `IE dm*` не доходит: те же константы, вписанные при сборке из
того же заголовка.

### 3.2 Общий код `dmTouch` (AS3, один проход `tools/dos2_touchkit.py`)

Вставляется последним проходом в любой касаемый фильм (`_c` → `_d`, PC → `_p`, наши 0x8d) — только дописанные методы и перенаправленные черты,
как сейчас (ни одно исходное тело не меняется). Исходник — один, на подмножестве Python, которое уже переводит в AVM2 `dos2_cc_touch.py`
(`cc_compile`); его же исполняет проверка без телефона (§6). Методы документа, все с приставкой `dmK`:

1. **`dmKInit`** (обёртка `onEventInit`, исходный — `dmKInitOrig`): строит реестр из карты, вписанной в фильм константой (массив строк: путь
   экземпляра, вид, запас в px, коды глаголов); дописывает в массив `events` фильма имена `IE dmTap`, `IE dmDTap`, `IE dmSLong`, `IE dmLong`,
   `IE dmHold`, `IE dmScroll`, `IE dmSet` (обёртка скрипта кадра 1, где фильм заполняет `events`).
2. **`dmKFind(x, y)`** — элемент под точкой сцены: обход реестра (не всего дерева), видимость по цепочке родителей (`visible`, `alpha > 0`),
   обрезка `scrollRect` / маской предков (логика `dmHgWalk` из `taps3`), прямоугольник = `getBounds(stage)` + запас (не меньше 8 мм на экране —
   число даёт хост через `IE dmSet`), для сеток и списков — строка / ячейка по арифметике контейнера (как `cc_touch` и `dmScroll`). Порядок —
   по глубине: верхний элемент побеждает.
3. **`dmKEv(индекс, игрок, значение)`** — обёртка `onEventDown / onEventUp`: свои индексы (`IE dm*`) разбираются здесь, всё остальное идёт в
   исходный метод как есть. Тап / двойной / короткое долгое / долгое → `dmKAct(элемент, глагол)`; `IE dmHold` вниз / вверх — для глаголов
   удержания (A у обучения, B у конца хода, «удерживайте A» у торговли / награды): вниз = исходный `onEventDown(i)`, вверх = `onEventUp(i)`;
   `IE dmScroll` — сдвиг (значение = px) для глагола `scroll:`; `IE dmSet` — настройки хоста (значение = ключ · 10⁶ + число: ячейка, запас, режим
   раскладки) — **замена пяти «чужих» каналов** §1.1.
4. **`dmKAct(элемент, глагол)`** — таблица переходов, которую сборщик пишет из карты: каждое действие — несколько готовых последовательностей
   (§3.3). Перед действием — притенение элемента (alpha 0,6 на 120 мс), как у всех нынешних кнопок.
5. **`dmKRects`** (тик `enterFrame`, раз в 10 кадров, при изменении; не реже раза в 30 кадров) — обобщённый `dmHudRects`: строка
   `"sw,sh|id,x,y,w,h,флаги;…"` по реестру; флаги: элемент, **фон окна** (тап мимо элементов внутри окна — окну, не миру), прокрутка, родная тяга.
   Хост по ней решает цель (К1) — пробное нажатие не нужно.
6. **Никаких постоянных слушателей сцены и элементов для нажатий.** Единственный вход — события `IE dm*`; мышь от хоста нужна только родному
   коду фильма (N). Этим закрываются Р14 и Р15.
7. **Запасной распознаватель** (только если М0 провалится): нажатие на корне фильма (`mouseDown` корня — всплытие только от нарисованного) +
   временные слушатели сцены на движение / отпускание + тик: тап / двойной / короткое долгое / долгое / тяга с теми же константами. Хост тогда
   для целей с `dmTouch` шлёт нажатие сразу при касании и не шлёт правого щелчка.

Что уходит из нынешних проходов в `dmTouch`: попадание и действия `hint_touch`, `mainmenu_touch`, `list_touch`, `taps`…`taps5`, тапы
`cc_touch`, `panel_touch` (кнопки ряда), `column_touch`, `minimap_touch`, `hudrect_touch`, `doc_tap` / `doc_scroll` `ppanel_skills`, тапы /
прокрутка `ppanel_trade`, тапы `pchud_touch`. Что остаётся как есть: **раскладка и графика** — пересадка `dos2_swf_graft.py`, `dos2_hud_touch.py`
(рисунки кнопок), `dmLay` из `dos2_ppanel_inv.py` / `dos2_ppanel_skills.py` / `dos2_ppanel_trade.py` / `dos2_pchud_touch.py`, обёртки, гасящие
родные действия PC (`downList = -1` торговли, `playerInventory = true` контейнера, `trade_1.onRightDown` из `ptouch_gaps`).

### 3.3 Карта: данные, а не проходы

**Два уровня.** (1) Глаголы экрана — одна таблица на оба режима (`tools/dos2_touchmap/screens.py`): какой жест что значит. (2) Карта фильма
(`tools/dos2_touchmap/<фильм>.py`): где элемент и как этот фильм исполняет глагол. Сборщик отказывает, если карта фильма не покрывает все
глаголы своего экрана — режимы не могут разойтись незаметно.

```python
# screens.py — смысл жестов, одинаковый в гибриде и в касании (по таблице iPad, §3.6)
SCREEN['inventory'] = {
    'cell':  {'tap': 'select', 'dtap': 'use', 'slong': 'tip', 'long': 'menu', 'drag': 'move', 'scroll2': 'scroll'},
    'tab':   {'tap': 'tab'},
    'close': {'tap': 'close'},
}
# partyInventory_d.py — гибрид, класс 0x8e
MOVIE['partyInventory_d'] = {'screen': 'inventory', 'family': 'c', 'types': [0x8e],
    'cell':  {'path': 'inventoryPanel_mc.<larInventory>', 'kind': 'grid',
              'select': 'native', 'use': 'native', 'tip': 'native', 'move': 'native',
              'menu': ['call:<grid>.selectItem(<grid>.getSlotForMousePosition())', 'pad:ControllerContextMenu']},
    'tab':   {'path': 'inventoryPanel_mc.tabs_mc.*', 'tab': 'call:inventoryPanel_mc.tabs_mc.selectTab(@id)'},
    'close': {'path': 'dmRowClose_mc', 'pad': 50, 'close': 'pad:UICancel'},
}
# partyInventory_p.py — касание, класс 0x74
MOVIE['partyInventory_p'] = {'screen': 'inventory', 'family': 'pc', 'types': [0x74],
    'cell':  {'path': 'inventory_mc.list', 'kind': 'grid',
              'select': 'native', 'use': 'native', 'tip': 'native', 'move': 'native',
              'menu': 'call:onContextMenuInputUp()'},
    'close': {'path': 'inventory_mc.close_mc', 'pad': 50, 'close': 'native'},
}
```
(Пути — из нынешних проходов: `taps4` `tabs_mc.selectTab(id)`, `taps5` `larInventory.selectItem(getSlotForMousePosition)`, `ppanel_inv`
`onContextMenuInputUp`.)

**Словарь действий** (одно действие или список по порядку):

| действие | что делает | когда брать | проверка при сборке |
|---|---|---|---|
| `native` | ничего: родной код фильма получает мышь хоста (щелчок, двойной щелчок Flash, наведение, тяга) | PC-элементы, у которых смысл совпадает с iPad; консольные с родным кодом (`larInventory`, `contextMenu_c`) | у элемента есть слушатель мыши в ABC (`dos2_ui_audit.py`) |
| `ei:Имя(арг…)` | EI фильма | у класса есть обработчик | имя сравнивает цепочка `OnFunctionCalled` класса (проверка `dos2_ptouch_gaps.py`; мёртвое имя — отказ сборки) |
| `call:путь.метод(арг…)` | метод AS3 фильма (штатный путь пада: `list.selectMC`, `executeSelected`, `setCursorPosition`, `cycleHotBar` …) | выбор, вкладки, «принять» внутри фильма | метод есть, число параметров совпадает |
| `ie:IE Имя` | исходные `onEventDown(i)` + `onEventUp(i)` фильма — путь пада внутри Flash, без движка и без фильтра (так делает `cc_touch`) | событие, которое фильм обрабатывает сам (его `onEventUp` кончается EI) | имя есть в `events` фильма; разбор `onEventUp` доходит до EI |
| `pad:IE Имя` | событие ввода **через движок** (класс окна тоже его видит): Г — импульс npad (как сейчас), К — запись клавиши, к которой это событие привязано в `keyboard_1.json` / `inputconfig.json` (escape = `UICancel` …); помечено как «от хоста» — стражи его пропускают | только где действие делает класс движка (торговля `itemSendToBarter`, меню предмета `ControllerContextMenu`) | имя есть в таблице событий `main`; для К — есть привязка клавиши, иначе отказ сборки |
| `host:глагол(арг)` | `dmAct(код, a, b)`: открыть панель (Г `openPanel` у 0x53, К `hotbarBtnPressed` по `hu_view_plan`), меню паузы, карта, f5 / o, круг / ✕ прицела, инвентарь персонажа, пропуск ролика | функции, которых нет у класса окна | код есть в таблице хоста |
| `scroll:путь` | одним пальцем: `IE dmScroll` двигает полосу (`scrolledY` / `scrollTo`, ограничение `getContDiff`), список на время забирает мышь у строк | списки, где у iPad прокрутка одним пальцем | путь полосы есть |
| `hold:IE Имя` | вниз / вверх `IE dmHold` = исходные `onEventDown` / `onEventUp` | удержания A / B | имя в `events` |
| `none` | ничего (явно: например, долгое в торговле) | | |

**Правило выбора** (пишется в генераторе, не руками): `native`, если родной код фильма уже делает глагол экрана; иначе `call:` / `ie:` (путь
внутри фильма — от режима не зависит); `ei:` — если есть живой EI; `pad:` — только если действие делает сам класс движка; `host:` — если нет
ничего. `dmPadBtn` остаётся только как совместимость на время переноса.

### 3.4 Договор хоста (оба режима одинаково)

- **К1. Цель пальца — по прямоугольникам.** При касании хост проходит объекты UI сверху вниз (`[uimgr+0xf8]`, тот же порядок, что
  `0xae83e0`), только видимые и с битом ввода; первый видимый модальный объект (биты 0x1e00) заканчивает проход: он цель, если точка в его
  прямоугольниках (элементы или фон окна), иначе — никто (тап мимо модального окна ничего не делает и в мир не идёт). Фильм с `dmTouch` и
  точкой в его прямоугольниках — цель. Фильм без `dmTouch` (переходное время) — прежнее пробное нажатие. Никого — мир (К9). Чистая функция
  `dk_target(...)` в новом `dm/host/hle_dos2_touch_kit.h`, тест `dm/host/tests/dos2_touch_kit_test.c`. Хранилище прямоугольников — нынешнее
  `dt_ei_hudrects` (срок жизни 1,5 с, перевод сцены в окно по прямоугольнику FlashPlayer `dt_player_fit`), обобщённое на любой фильм.
- **К2. Мышь — только цели.** На время жеста `rt_hook` пропускает мышиные события только объекту-цели (оба режима; заменяет список групп Х2 и
  ветку `pcui` Х3). Движение мыши идёт сразу (наведение, подсветка), нажатие — как сейчас: на тапе — на отпускании, на тяге — в точке начала
  при сдвиге; для элементов с флагом «родная тяга» (ячейки, ползунки, кукла) — сразу при касании, чтобы родной код начал перетаскивание.
  Правого щелчка хост больше не шлёт (Р9): долгое — это глагол `long`, который карта исполнит как надо (у PC-инвентаря — `onContextMenuInputUp`).
- **К3. Один распознаватель UI.** `dt_step` для пальца с целью: тап / двойной (300 мс, 5 % высоты) / короткое долгое (350) / долгое (600) /
  удержание (после 600 — `IE dmHold` вниз, вверх при подъёме, если глагол удержания) / тяга (2,5 % высоты) / прокрутка одним пальцем (если под
  пальцем элемент с `scroll:`) / два пальца (колесо цели). В Г и К одинаково; раннее нажатие через 200 мс (`DM_DOS2_TOUCH_UI_PRESS_MS`) и правый
  щелчок на долгом уходят для целей с `dmTouch`.
- **К4. Доставка жеста.** `IE dm*` — только цели, через её `UIObject::OnInputEvent` (`0xae38b0`; так уже делает `hle_dos2_touchui_ie.c`, нужно
  сделать адресно и дописать имена `dmTap`…`dmSet`, id 0x7f10…); через `DM_DOS2_TOUCHUI_IE_DELAY` опросов после мыши этого касания (курсор
  фильма уже у пальца). Значение события (`+0x18`) несёт число для `dmScroll` / `dmSet`.
- **К5. `dmAct(код, a, b)`** — один обработчик EI хоста вместо `dmPadBtn` / `dmPanel` / `dmSide` / `dmKey` / `dmAimBtn` / `dmColumnPoll`; старые
  имена — псевдонимы до конца переноса. Реализация глагола выбирается по режиму внутри хоста (панель: Г — `openPanel` объекту 0x53, К —
  `hotbarBtnPressed` и «одно окно»).
- **К6. `pad:`-события** — транспорт по режиму: Г — импульс npad (`dm_dos2_touch_pad_pulse`), К — запись клавиши по таблице привязок
  (генерируется при сборке из `keyboard_1.json` / `inputconfig.json` игрока). Оба помечены «от хоста» (время + код), задержки 750 мс для A больше
  нет. Опыт М0 проверяет и третий путь — прямой вызов `0xaea7b0` для одного объекта с собранным событием: если он доходит и до класса, он
  заменит оба транспорта.
- **К7. Страж «тап ≠ принять» — один, в хосте, оба режима:** `UIAccept` объекту-цели в пределах 600 мс после нажатия касания отбрасывается,
  если не помечен «от хоста» и A пада не был нажат 300 мс (нынешнее правило Х2 без исключения для байта 0). Стражи в фильмах с `dmTouch` не
  нужны: `dmTouch` зовёт исходные методы напрямую (как `cc_touch`), а `IE dm*` — не `UIAccept`. Исключение главного меню (0x48 / 0x57) уходит
  вместе с М4: заставка — глагол карты `mainMenu_d`, не «тап = A»; экран загрузки (0x17) своего `dmTouch` не получает и исключение сохраняет.
- **К8. Модальность — одно правило** (К1) для мыши, `IE dm*` и `dmAct`: вызов от объекта, который не цель текущего жеста, отклоняется (обобщённый
  `dm_dos2_touchui_may_press`).
- **К9. Мир отдельно.** Палец мира — только если К1 никого не нашёл **и** на экране нет окна: «окно» = любой видимый объект с `dmTouch` и
  флагом «окно» в его отчёте (фон окна) или модальный — список типов `dm_dos2_route_world_ok` больше не нужен (закрывает Р1). Жесты мира — по
  профилю режима (К10).
- **К10. Профили мира — единственное место, где режимы различаются намеренно:** Г — решения хозяина 16.11 (свайп = поворот, удержание =
  ходьба, PC-щелчок `WORLD=3`, режимы цели «переместить» / «кинуть», `hold<код>` подсказки), К — таблица iPad (`w a s d`, плашка действия, `lalt`
  / `lshift` / `o`). UI-жесты (К3) от профиля не зависят.

### 3.5 Что меняется в файлах при переносе (для следующего шага, сейчас не трогать)

- `dm/host/hle_dos2_touch_kit.c` / `.h` (новые): хранилище прямоугольников (из `dt_ei_hudrects`), `dk_target`, таблица `dmAct`, транспорт `pad:`.
- `hle_dos2_touch.c`: `dt_step` — цель по `dk_target` на `EV_DOWN`, `G_WPROBE` только для фильмов без `dmTouch`, распознавание `dt_t1_*` для
  UI в обоих режимах, вызов доставки К4.
- `hle_dos2_touchui_ie.c`: адресная доставка, новые имена, значение события, пометка «от хоста».
- `hle_dos2_touchui_route.c`: мышь только цели (К2), страж К7 в обоих режимах, правило 5 (слушатель сцены) — для всех фильмов без `dmTouch`.

## 7. Не доказано / риски

1. Адресное `IE dm*`: механизм `hle_dos2_touchui_ie.c` стоит в каждой сборке с 15.11, но на телефоне не подтверждался (`_t`-путь бросили в тот же
   день). Риск из его шапки: вызов `OnInputEvent` из перехвата опроса — если Iggy занят, «re-enter» без действия. Отвечает М0.
2. `pad:` в К через клавиши: какие события привязаны к клавишам в `keyboard_1.json` Switch-пака игрока, не выписано; `UIAccept` клавишей —
   не проверено. Нет привязки — глагол обязан иметь `ie:` / `call:`.
3. Прямоугольники как источник цели: фильм, который перестал тикать (скрыт), через 1,5 с перестаёт быть целью — так задумано; фильм, который
   не шлёт `dmKRects` (сбой тика), станет «прозрачным» — запасной путь: пробное нажатие для такого фильма (как сейчас).
4. Мышь только цели (К2) меняет поведение родных PC-окон, которые ждали мышь «насквозь» (перетаскивание предмета из окна в мир, на хотбар):
   на время тяги с флагом «родная тяга» мышь надо отдавать по правилу движка — проверяется в М7 (инвентарь → хотбар, инвентарь → земля).
5. Отказ от правого щелчка (К2): PC-окна, где правый щелчок — нужная функция (флажок карты удаляется правым щелчком в `journal_p`), обязаны
   получить её глаголом карты; генератор должен находить слушатели `rightMouseDown` / `rightMouseUp` в ABC и требовать решения в карте.
6. Р1–Р4 — выводы чтения кода; если параллельный агент их починит до переноса, `dmTouch` их просто не унаследует.
7. Решения хозяина (§3.6): портрет — двойной тап, слот хотбара — долгое, «тап по выбранной» → двойной тап; пропуск ролика и «одно окно» в Г.

Собранные паки (вне репозитория, как обычно): `dos2-port\work\uimodes\kit\m0\TouchUI.pak` (проба М0), `…\kit\m2\TouchUI.pak`
(пилот М2), `…\kit\default\TouchUI.pak` (тот же набор `touch` без ключей — для сравнения А / Б).

**Как работает набор в фильме.** `frame1` → исходный, затем семь имён `IE dmTap`, `IE dmDTap`, `IE dmSLong`, `IE dmLong`, `IE dmHold`,
`IE dmScroll`, `IE dmSet` дописываются в `events` (хост даёт им узлы с номерами 0x7f10…0x7f16). `onEventInit` → исходный, затем карта и тик
отчёта (каждые 10 кадров, при изменении, и не реже каждого третьего раза). `onEventDown` / `onEventUp`: событие набора разбирает набор, любое другое
идёт в исходный метод как пришло (если его нет — «не обработано»). На нажатии события набор ищет элемент под мышью сцены (сначала по своему
прямоугольнику в порядке карты, потом ближайший из увеличенных до наименьшего размера), на отпускании исполняет глагол по таблице карты — но
**только после `dmSet` act = 1** (его шлёт хост при `DM_DOS2_TOUCH_KIT=1`); до этого набор лишь пишет `dmKitTrace`. Старый код нажатий
фильма остаётся: при `KIT=1` хост не шлёт ему нажатий мыши на элементах без флага «родное» (`t` / `d`), поэтому он молчит.

**Словарь действий карты (что собрано):** `host:panel(n)` / `side(n)` / `pad(n)` / `key(n)` / `map` / `menu` (→ `dmAct`), `ei:Имя(аргументы)`,
`call:путь.метод(аргументы)` (пустой путь = сам фильм), `ie:IE Имя`, `hold:IE Имя`, `toggle:свойство`, `scroll:путь_полосы`, `native`, `none`.
`pad:IE Имя` (транспорт К6 по режиму) **не собран** — карта с ним отклоняется.

**Проверка карты при сборке:** каждый путь — существующий экземпляр; каждый смысл экрана покрыт; лишних действий нет; `ei:` — живое имя
(обработчик хоста или сравнение в цепочке `OnFunctionCalled` класса, адрес — `class_fn` в карте; разбор цепочки — `dos2_ptouch_gaps._chain`);
`call:` метода фильма — метод есть и число параметров совпадает; `ie:` / `hold:` — имя в `events`; `host:` — код из `hle_dos2_touch_kit.h`.
Отказы проверены отдельно (дыра в карте, `pad:`, неизвестный глагол, мёртвое имя `ei:`).

### Выключатели (все по умолчанию 0)

| выключатель | что делает |
|---|---|
| `DM_DOS2_TOUCH_KIT=1` | договор К1–К9 для фильмов с набором: палец на их прямоугольниках — пальцу набора; без таких фильмов (пак по умолчанию) всё идёт старыми путями |
| `DM_DOS2_TOUCH_KIT_M0=<биты>` | опыт М0, только лог: 1 — адресное `IE dmTap` в наш тип 0x8d на каждый тап; 2 — прямой вызов `0xaea7b0` с собранным `UICancel` для окна настроек через 3 с после его появления; 4 — все события ввода, которые получает UI за 800 мс после импульса `dmPadBtn`; `all` = 7. Не зависит от `KIT` |
| `DM_DOS2_TOUCH_KIT_LEAST=<мм>` | наименьший размер попадания (по умолчанию 8 мм через `DM_DOS2_TOUCH_MM_PER_1080`; без него 7 % высоты) |
| `DM_DOS2_TOUCHUI_IE_DELAY=<опросы>` | (прежний) через сколько опросов после мыши касания уходит тап / двойной тап набора и М0-1 (по умолчанию 2) |

Нужны включённые перехваты EI, событий ввода и маршрута (они включены по умолчанию с `DM_DOS2_TOUCHUI`); иначе — красная строка `[kit] needs …`.

### Строки лога

- `[kit] DM_DOS2_TOUCH_KIT_M0=7: experiment M0 (log only): …` и/или `[kit] DM_DOS2_TOUCH_KIT=1: …` — при старте; `【红】[kit] main+… differs` — сверка не прошла, набора нет.
- `[ie] type 0x8d dmSide_p: events [dmTap, dmDTap, …]: 7 touch event(s) wired` (с `DM_DBG=1`) — фильм получил узлы имён набора.
- М0-1: `[kit] M0-1: a tap at X,Y: "IE dmTap" queued for type 0x8d …`, затем `[kit] M0-1 sent: "IE dmTap" (id 0x7f10) -> type 0x8d <фильм> …: FlashPlayer::OnInputEvent down -> D, up -> U`, затем от фильма `[kit] M0-1 REACHED: <фильм> (type 0x8d) onEventUp("IE dmTap", value 1): stage mouse X,Y, element under it: <кнопка>`. Красная `M0-1 sent: … NO NODE` — имени нет в `events` фильма.
- М0-2: `[kit] M0-2: options window type 0x… up: …`, `[kit] M0-2 sent: built UICancel … down: pass 1 -> …, pass 2 -> …, handled …; up: …`, `[kit] M0-2 after: 15 polls later the options object … is GONE / hidden: CLOSED … | still open …`.
- М0-3: `[kit] M0-3 pulse: dmPadBtn(N) = pad …, mode touch|hybrid: its keyboard twin | the npad pulse in D ms …`, `[kit] M0-3 pulse: the twin is raw key 0x…`, `[kit] M0-3 key 0x… DOWN / UP record injected (mode byte B)`, `[kit] M0-3 +N ms (dmPadBtn(N)): input event 0x… "<имя>" down|up -> type 0x… <фильм>, pass 1|2: answered A, handled H[ = TAKEN]`.
- Набор (`KIT=1`): `[kit] dmKRects from <фильм> …: N rect(s), stage WxH, scale K …; dmSet act / least / mode queued`, `[kit] finger at X,Y -> type 0x… <фильм>, element <id> (flags …)`, `[kit] dmAct(код имя, a) in touch|hybrid`, `[kit] trace: …` (с `DM_DBG=1` — каждый глагол и доставка), `[kit] summary: …` (раз в 1800 опросов при `DM_DBG=1`).

### М0 на телефоне — шаги (утром; копия `files/save` до запуска, таблица прогонов заранее, игру остановить после; 2 мин остывания после трёх прогонов)

Пак: `dos2-port\work\uimodes\kit\m0\TouchUI.pak` → `<romfs>/Data` вместо обычного (в нём всё как в `touch`, кроме проб в
`dmColumn_d` / `dmSide_p`; старые нажатия колонки и правой стороны работают как раньше — проба только пишет в лог).
`dm/env`: `DM_DBG=1`, `DM_DOS2_TOUCH_KIT_M0=all` (и больше ничего нового).

| # | режим | что делать | сколько | отвечает на |
|---|---|---|---|---|
| 1 | гибрид (`DM_DOS2_UI_MODE=hybrid`) | главное меню → «Настройки», 4 с ничего не трогать; потом загрузить сохранение; в игре 3 тапа по кнопкам колонки справа (например, «Инвентарь», закрыть, «Навыки», закрыть, «Карта», закрыть) и 1 тап по пустому месту колонки | ≈ 60 с от загрузки | М0-1 в Г, М0-2 в Г, М0-3 в Г (подсказки «A» / «B» в настройках) |
| 2 | касание (`DM_DOS2_UI_MODE=touch`) | заставка — тап (там `dmPadBtn(2)`); главное меню → «Настройки», 4 с ничего не трогать; снова открыть настройки, тап по подсказке «(B) Назад»; загрузить сохранение; 3 тапа по кнопкам правой стороны (инвентарь, навыки, журнал — каждый раз закрыть) и 1 тап по шлему | ≈ 60 с от загрузки | М0-1 в К, М0-2 в К, М0-3 в К (Р3) |

Как читать ответ:
- **Опыт 1 (доходит ли адресное `IE dm*`).** Есть `M0-1 REACHED` с правильной кнопкой под мышью → адресная доставка работает в этом режиме, и
  мышь сцены к этому времени у пальца: основной путь набора (К4) годен. Есть `M0-1 sent … down -> 1, up -> 1`, но нет `REACHED` → Iggy
  позвал метод, но вызов EI из него не дошёл (или метод не тот) — нужен запасной распознаватель (§3.2 п. 7). `NO NODE` → в паке нет
  имён (не тот пак) или фильм прочитал `events` раньше, чем их дописали. `REACHED`, но `element under it: none` или мышь далеко от
  тапа → мышь не успела: поднять `DM_DOS2_TOUCHUI_IE_DELAY` до 4 и повторить.
- **Опыт 2 (прямой вызов `0xaea7b0`).** `M0-2 after: … CLOSED` → собранное событие доходит до класса окна, этот путь может заменить оба
  транспорта К6. `still open` при `handled 1` → фильм взял событие, а класс — нет; при `handled 0` и `answered 0` — объект его не принял вовсе.
  `vt+0xa8 = main+…` в строке показывает, свой ли обработчик у класса.
- **Опыт 3 (Р3: `dmPadBtn` в К).** После `M0-3 key 0x… DOWN record injected` есть строка `input event … "UICancel"` / `"UIAccept"` с
  `= TAKEN` у окна настроек / заставки → клавиша-двойник работает, Р3 закрыт. Есть события, но никто не взял → окно при байте 0 не принимает
  их; нет ни одного события → запись клавиши отбросил фильтр. В Г для сравнения должны быть `the npad pulse` и `TAKEN`.

### Не проверено / риски (всё — статика)

1. Ничего не запускалось на телефоне: ни проба М0, ни набор. Iggy и методы с `*rest` (флаг `NEED_REST`: движок зовёт
   `onEventDown(индекс, игрок, значение)`, у наших методов один параметр + остальное) — проверено только проверкой ABC.
2. М0-2 зовёт `0xaea7b0` из опроса пада (внутри опроса ввода), как сейчас `hle_dos2_touchui_ie.c` зовёт `OnInputEvent`: повторный вход в
   менеджер UI не исключён. Если упадёт — убрать бит 2 (`DM_DOS2_TOUCH_KIT_M0=5`).
3. Исполнитель не исполняет AVM2: он прогоняет тот же исходник набора в Python на дереве показа из SWF. Родные методы фильма (исходные
   `onEventInit`, `dmColApply`, `dmBAct`) только записываются, не исполняются; поэтому стрелка «развернуть» колонки скрыта вручную
   (`hidden_at_start` в карте). Обрезка `scrollRect` предками в `dmKFind` не сделана (нужна спискам в М7).
4. `KIT=1` с паком пилота не проверялся: К2 (мышь только цели) и К7 включаются только для цели набора; два пальца на цели — колесо этой цели.
5. Пилот М2 — **два фильма** (`dmColumn_d` в Г, `dmSide_p` в К) с одной картой экрана, а не один `dmSide.swf`, как в §5: перенос в один фильм
   остаётся на М2.
6. `stage.mouseX / mouseY` в Г: мышь до фильма доходит через маршрутизацию (тип 0x8d в группе `hud`) — так и должно быть, но для адресных
   событий это проверяет только опыт 1.
