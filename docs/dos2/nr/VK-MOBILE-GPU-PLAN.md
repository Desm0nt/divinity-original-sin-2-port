Только разбор и план. Код, сборка, ветки, телефон не трогались. Дерево `wt-vk`, ветка `dos2-vk`, вершина `fbada69`.
Пометки: **[лог]** — число из лога телефона (Mi 14 Ultra, Adreno 750, Turnip, `TU_DEBUG=sysmem`), **[код]** — строка исходника,

## 0. Коротко (10 строк)

1. На Mi 14 кадр упирается сразу в два потолка: GPU 12.7 мс и поток записи 13.3 мс из 13.4 мс кадра [лог, `VK-NATIVE-STATUS.md` «Телефон 21.11»]. Поэтому на Adreno 750 fps дают только приёмы, которые убирают **и draw, и проходы**, а не одни байты.
2. GPU по частям [лог U02h:2460–2485]: геометрия 6.4 мс (пре-пасс 1.66 + G-buffer 3.0 + тени 0.99 + forward 0.71), свет 2.4, пост 2.3, UI 1.06, вне проходов 0.41.
3. Главная находка для тайлеров — **UI, а не 3D**: Iggy рисует тени и размытие текста в цели размером с экран (2400x1080), 60–75 проходов на кадр ради прямоугольников ~350x42 [лог U07r `trace:`, U02h:2467; код `hle_dos2_vkn_ui.c:606–690`]. Модель трафика: 1807 + 1903 МБ на кадр без политики, 954 + 1109 МБ с политикой Mali [лог U02h:2424, U13r `pass policy (mali`]; из них на UI ≈ 1.3 ГБ. Сужение области сейчас снимает только 10 % пикселей [лог U13r `ui pass:`].
4. Три приёма «для тайлеров» на новом пути почти не работают, и это видно в логах: сохранение по истории — 0 вложений из 143; гибрид пре-пасса — 0 принятых ключей из 393; слияние Vignette∘Combine (F2) не взводится [лог U13r `pass policy`, `prepass:`; U02h `post:`]. Сначала чинить их, потом писать новое.
5. Стоковый драйвер Qualcomm (сам выбирает GMEM) и Maleoon получают политику «не тайлер»: `vkn_policy_tiler` знает только Mali и PowerVR [код `vkn_policy.h:40`]. Дёшево исправить.
6. Точные приёмы для всех GPU: кэш результатов фильтров Iggy (минус ~60 проходов и ~40 draw на кадр), хэш констант кэша теней только по читаемым байтам (до −400 draw на кадр, если подтвердится замером), один слитый хвост поста.
7. Точные приёмы только для тайлеров: область прохода по региону Iggy, пре-пасс и G-buffer одним проходом, узкие зависимости проходов, раскладка без `UNDEFINED`.
8. Большая перестройка «G-buffer → свет в памяти тайла» (входные вложения, transient) — 8–12 агент-часов, только Mali / PowerVR / GMEM, на Turnip sysmem ноль; делать после данных с настоящего тайлера.
9. Не предлагается (нечего менять или видимая потеря): SSAO в половинном разрешении (SSAO в шейдере света нет), упаковка G-buffer (все цели уже ≤ 4 Б/пкс), `R11` (уже R11G11B10F), bloom через compute, свет в пониженном разрешении, fp16 на Adreno (+8 % стоимости) [KB NR-ONCHIP §0, NR-FRAME §3, PERF-X17, PERF-DOS2-NR].
10. Ожидание [м]: Adreno 750 — GPU 12.7 → 11.3–11.8 мс и поток записи 13.3 → 11–12 мс (74 → 82–88 к/с стоя); тайлеры — модель трафика 2.06 ГБ → 0.35–0.45 ГБ на кадр. Порядок работ — раздел 6, около 30 агент-часов без пункта 8.

## 1. Карта кадра

### 1.1 Источники и оговорки

- Виды проходов, размеры, число draw, GPU-мс: строки `gpu by pass` (выборочный кадр раз в 20 с), U02h:2460–2485; повтор в U07r, U24, U13r — разброс проходов ±5 %, один выброс G-buffer 5.24 мс в U13r (кадр 9351) против 2.9–3.2 во всех остальных выборках — не тренд.
- Форматы: имена файлов дампа `work/dumps_u5/dump_U07r/vkn_600_*` (число после `f` — `VkFormat`: 37 RGBA8, 122 B10G11R11F, 83 RG16F, 70 R16, 9 R8, 76 R16F).
- **Порядок 3D-проходов взят из разбора старого пути** (`NR-FRAME.md` §1.1, дамп IR 17.11) и сверен с видами проходов нового лога. Сам бэкенд порядок не печатает: `trace:` пишет только draw в большие цели RGBA8 [лог U07r, 86 строк]. Поэтому первый кусок плана (П0) — журнал проходов.
- Байты: «тайлер» = загрузка + сохранение каждого вложения по его Б/пкс, без AFBC / UBWC; «sysmem» = запись целей + чтение выборок. Это модель [м]. Важная оговорка: модель считает загрузку и сохранение всей области прохода; настоящие Mali / PowerVR могут не трогать тайлы без геометрии — тогда цена проходов UI с маленьким прямоугольником ниже модели. Проверит только устройство; сужение области (П1) снимает вопрос при любом поведении драйвера.
- 2160x972 = 2.10 Мпкс: 1 Б/пкс = 2.1 МБ, цель 4 Б/пкс = 8.4 МБ. 2400x1080 = 2.59 Мпкс: RGBA8 = 10.4 МБ.

### 1.3 Где больно

**Тайлер (Mali, PowerVR, стоковый Adreno в GMEM, Maleoon).**
1. Цели фильтров Iggy (строка 2): 60–75 проходов на цель размером с экран. Под политикой Mali: 60 проходов UI, у 48 снята глубина (−949 МБ), область подсказана 24 раза и применена 22, но пикселей осталось 140.6 из 155.5 млн (90.4 %); 33 отказа «экономия меньше 10 %» [лог U13r `ui pass:`]. То есть цвет по-прежнему грузится и сохраняется целиком: ≈ 60 × 10.4 × 2 ≈ 1.1 ГБ на кадр [м].
2. Слой UI рвётся 11 раз уходами в цели фильтров (строка 1): каждое возобновление — загрузка и сохранение 10.4–20.7 МБ.
3. Сохранение `DONT_CARE` по истории не срабатывает ни разу: `stores 143.0: dontcare 0.0, ... not eligible 51.0` [лог U13r]. По старому разбору мёртвых сохранений в 3D и нет (`DEADST 0`, KB NR-FRAME §2) — значит рычаг не в правиле, а в **числе проходов**: чем меньше границ, тем меньше пар «сохранить и снова загрузить».
4. Пре-пасс и G-buffer — два прохода с одной глубиной (сохранить 8.4 + загрузить 8.4 МБ) и двойная раскладка 1.6 млн вершин; гибрид пре-пасса не принимает ни одного ключа: `pre_draws=678 cand=4 skip=0 ... keep kill=335 fs=339 ... keys=393 ok=0` [лог U13r `prepass:`].
5. G-buffer → LinearDepth → PCF → свет: 16 Б/пкс G-buffer сохраняются в память и тут же читаются светом (≈ 120–133 МБ на кадр, KB NR-FRAME §2 строка 5).
6. Каждая граница прохода ждёт и вершинную стадию: внешняя зависимость прохода содержит `VERTEX_SHADER` и `COMPUTE_SHADER` в стадиях-приёмниках, барьеры — `ALL_COMMANDS → ALL_COMMANDS` [код `vkn_state.c:436–447`, `vkn_pass.c:100–107`]. На Mali это запрещает перекрытие раскладки следующего прохода с растеризацией предыдущего (−13 % кадра, KB FN-32). `TILEBAR=1` сужает только явные барьеры чтения (28 на кадр).
7. Проход, начатый не загрузкой, объявляет начальную раскладку `UNDEFINED` [код `vkn_state.c:427`] — на Mali это сбрасывает подпись исключения неизменных тайлов (KB FN-33); слой UI и окно почти не меняются от кадра к кадру и теряют больше всех.

**Adreno 6xx / 7xx с узкой шиной (Turnip sysmem, LPDDR4X).** Загрузки и сохранения бесплатны; болят полноэкранные проходы — они упираются в полосу памяти уже на 750 (≈ 76–87 ГБ/с эффективно, KB PERF-DOS2-NR). Список полноэкранных записей за кадр: G-buffer, LinearDepth, PCF, свет, Fade ×2, хвост ×3–4, Combine, показ — 12–13 штук; сокращается только слиянием хвоста (П5). Второй рычаг — число draw: пре-пасс + G-buffer + тени + forward = 2074 draw; оценка класса Snapdragon 7 ≈ ×3.5 GPU-мс Mi 14 и процессор слабее в 2–3 раза [м, `VK-STAGE5-PLAN.md` §4].

**Adreno 750.** Поток записи 13.3 мс и GPU 12.7 мс. Байты не болят, болит счёт draw и проходов: 890 draw уже снимает кэш теней; следующие по размеру — 418 draw теней, которые кэш каждый кадр считает «новыми по константам» (`c1 244/67`, `c2 730/351` известных / новых) [лог U02h `shcache why`], и ~290 draw и 87 проходов UI.

## 2. Перестройки (по убыванию «выигрыш / работа»)

Общие правила каждого пункта: переключатель `DM_VK_NATIVE_*` со значениями 0 / 1 / 2 сверка / 3 яд, где яд возможен; умолчание по семейству в `vkn_policy.h`; игроку флаги не нужны; после слияния — запись в `docs/port-kb` и `MATRIX.md`. Часы — агент-часы.

### П0. Журнал проходов и три дешёвые правки политики (2 ч) — делать первым

- **Журнал.** `DM_VK_NATIVE_PASSLOG=k`: на k-м кадре уровня строка на каждый проход по порядку — имена целей (`vkn_tex.sname`), размер, область, начало и конец каждого вложения, байты модели, число draw, причина конца прохода (смена целей, выборка своей цели, копия, очистка, сужение области, конец кадра). Место: `vkn_pass.c` рядом с `vkn_prof_pass_begin` (строка 982) и в `end_open`; причина — параметр `end_open`. Итоговая строка «МБ по причинам». Без неё пункты П6–П10 нельзя ни спланировать точно, ни принять.
- **Политика тайлера по драйверу.** `vkn_policy_tiler` [код `vkn_policy.h:40`] → правда ещё для `VKN_FAM_MALEOON` и для Adreno со стоковым драйвером (`driverID == VKN_DRVID_QUALCOMM_PROPRIETARY`; функция получает `driver_id`). Касается только `LOAD`, `STORE`, `FRESH`, `TILEBAR`, `UIPASS`; шейдерные умолчания (MAT, XLQ, PRESKIN) не трогать — на Adreno они мерены нулём. Xclipse оставить «не тайлер» до данных.
- **Отчёт о сжатии кадра** (невыполненный кусок В5 этапа 5): `VK_EXT_image_compression_control` по каждому вложению, одна строка при создании цели: сжато или нет и причина. Место `vkn_tex.c` после создания образа (строки 561–570). Сейчас цели создаются с `TRANSFER_SRC | TRANSFER_DST | SAMPLED`, без `MUTABLE`, `STORAGE` только по запросу [код `vkn_tex.c:561–565`] — по правилам KB TEX-12 / FN-34 / FN-35 это дружелюбно к UBWC и AFBC; строка нужна, чтобы увидеть это на чужих устройствах в логе игрока.

Картинка: не меняется. Проверка: хост-тест `vendor_policy_test` (новые строки семейства), прогон под `DM_GFX_SIM_GPU=mali` — журнал совпадает со счётчиками `pass policy`.

### П1. Область прохода у целей Iggy — по региону, всегда (2 ч) — тайлеры, точно

Что сейчас: область = первый прямоугольник эпохи ∪ история того же начала, порог «не меньше 10 % экономии» [код `vkn_ui.h:86–91`]; результат 90.4 % пикселей.
Как иначе: у вытолкнутой цели (глубина стека > 0) Iggy сам задаёт регион — `tdb_impl` считает прямоугольник очистки `cx, cy, cw, chh` и пишет регион в узел [код `hle_dos2_vkn_ui.c:652–690`]. Всё, что Iggy рисует в эту цель до `TextureDrawBufferEnd`, и всё, что потом из неё читает, лежит внутри региона + 2 пкс. Значит область прохода для всей эпохи вытолкнутой цели = регион, выровненный по `renderAreaGranularity` (KB FN-19), без истории и без порога 10 %. Шаги размытия (`BlurPass`, `h_blur`, строка 578) идут в ту же пару целей с тем же регионом.
Отказы: draw вне региона (ножницы шире) → как сейчас, конец суженного прохода и полная область (счётчик); очистка всей цели → полная область.
Переключатель: `DM_VK_NATIVE_UIPASS=4` (2 + регион), умолчание 4 на тайлерах; `DM_VK_NATIVE_UIPASS_VERIFY=1` считает «сузил бы». Яд: уровень 3 уже есть — добавить заливку пурпуром пикселей цели вне региона перед эпохой (если Iggy читает вне региона, пурпур виден на экране).
Точность: точная — Vulkan сохраняет пиксели вне области.
Выигрыш [м]: модель трафика −1.0…1.1 ГБ на кадр на тайлерах (60 проходов × 10.4 МБ × 2 → 60 × ~0.1 МБ). G57: от −5 до −50 мс в зависимости от того, пропускает ли драйвер пустые тайлы сам (см. оговорку 1.1); PowerVR так же; Adreno Turnip 0; стоковый Adreno — как тайлер после П0.
Без устройства: строка `ui pass:` — пикселей с областью ≤ 5 % от полных; яд без пурпура. С устройства: время.
Риск: низкий (механизм подсказки области уже работает на 22 проходах).

### П2. Кэш результатов фильтров Iggy между кадрами (3–4 ч) — все GPU, точно

Что сейчас: тень и размытие каждого текста HUD пересчитываются каждый кадр: 32 сведения теней и ~1.2 прохода размытия на кадр, 75 проходов и 42 draw в цели `tex#0000` [лог U02h `ui:` — разность двух окон, U02h:2467].
Как: ключ блока «`TextureDrawBufferBegin` … сведение фильтра» = хэш всего, от чего зависит результат: регион, вид и параметры фильтра (запись `ctx + 0x1180…`, `filter_composite`, строка 730), список draw внутри блока (программа, состояния, матрицы, байты вершин из кольца UI, номера текстур и **версии их содержимого** — счётчик заливок в `vkn_tex` уже ведётся для кэша теней). Таблица на 128 записей: ключ → своя текстура результата размером с регион (не цель Iggy: её ручка уходит в свободный список). При совпадении ключа с прошлым кадром: draw блока и шаги размытия не записываются, сведение читает сохранённую текстуру (координаты пересчитать на её размер). При несовпадении — обычный путь, результат копируется в кэш одним `vkCmdCopyImage` региона.
Тонкость: блок надо видеть целиком до решения. Записи UI уже идут через поток записи (`vkn_rt_ui_*`), значит блок буферизуется в потоке записей между началом и концом, хэш считает поток движка, решение принимается на `TextureDrawBufferEnd`.
Переключатель `DM_VK_NATIVE_UIFC`: 0 / 1 / 2 сверка (рисовать как 0 и сравнивать текстуру результата с кэшем чтением региона раз в N кадров, `differ 0`) / 3 яд (при попадании кэш перед использованием затемняется пурпуром на один кадр из 64 — видно, что читается именно он). Умолчание 1 везде после сверки.
Точность: точная при полном ключе; пропущенное поле ключа ловит сверка.
Выигрыш [м]: Adreno 750 GPU −0.4…0.5 мс (строка 2 таблицы 1.2 почти целиком), поток записи −0.3…0.4 мс (≈ 75 draw и очисток × 4 мкс); Adreno 6xx / Snapdragon 7 −1.5 мс GPU; тайлеры: проходов 119 → ~45, слой UI снова один проход (уходов в цели фильтров нет) — вместе с П1 убирает UI из списка проблем; PowerVR, Xclipse — как свои классы по draw.
Без устройства: хост-тест (новый блок в `vkn_stage3_test`: одинаковые блоки → попадание, изменённый байт вершины / версия текстуры → промах); на Mi 14 сверка `=2` и счётчик попаданий (ожидание ≥ 90 % стоя). С устройства: ничего сверх fps.
Риск: средний — время жизни ручек Iggy и «особые» draw движка внутри блока (`custom draws` 40 на кадр): блок с таким draw не кэшируется.

### П3. Кэш теней: хэш констант только по байтам, которые шейдер читает (1 ч замер + 2 ч) — все GPU, точно

Что сейчас: кэш пропускает 895 draw из 1402, но 418 draw каждый кадр «новые по константам» (каскад 1: 67, каскад 2: 351) [лог U02h `shcache why`]. Хэшируется блок констант целиком [код `vkn_shc.c:75, 442`].
Гипотеза: часть этих draw — статические меши, у которых в блоке меняется поле, которое вершинный шейдер глубины не читает (время, параметры материала для цветового прохода). Тогда хэш по маске читаемых диапазонов вернёт их в кэш.
Шаг 1, замер (1 ч): режим `DM_VK_NATIVE_SHCACHE=4` — для «новых по константам» draw сравнить блок с прошлым кадром побайтно и напечатать гистограмму изменившихся смещений по ключу шейдера; маску читаемых смещений взять отражением SPIR-V (цепочки доступа к блоку от `gl_Position` — тот же проход зависимостей, что `xbg_spirv_posonly`, KB NR-POSONLY). Если изменившиеся байты читаются (ветер, скиннинг) — пункт закрыт, остаётся П9.
Шаг 2 (2 ч): маска на шейдер в `vkn_shlib` (диапазоны блока, от которых зависит позиция и, при вырезе, альфа), хэш по маске.
Точность: точная (байты, от которых выход шейдера не зависит). Сверка — существующая `SHCACHE=2` (`verify differ 0`).
Выигрыш [м], если гипотеза верна на 70 %: −290 draw на кадр → Adreno 750 поток записи −1.2 мс, GPU −0.4 мс; слабые классы кратно (процессор ×2–3, GPU ×3.5); тайлеры — меньше вершин в раскладке атласа.
Без устройства: шаг 1 требует одного прогона на Mi 14 (нужны настоящие блоки сцены). Риск: низкий; худший исход — «гипотеза неверна», потеря 1 часа.

### П4. Починить три неработающих приёма (3–4 ч) — в основном тайлеры

1. **Гибрид пре-пасса принимает 0 ключей** [лог U13r `prepass:` `ok=0 ... keep kill=335 fs=339`]. Разобрать причину `fs` (339 draw пре-пасса оставлены «из-за фрагментной стадии», хотя MAT в том же прогоне снимает её у 39 % depth-draw) — вероятен порядок в цепочке приёмов (MAT после решения гибрида) или факты шейдера не доходят. Цель: draw без выреза (≈ половина из 678) не рисуются в пре-пассе, их draw G-buffer идёт с `LEQUAL` и записью. Файлы `vkn_prepass.c` (строки 178–260), `xbg_prepass.h`. Точность: глубина бит в бит (`prepass_test`), режимы 2 / 3 есть. Выигрыш [м]: тайлеры −0.8 млн вершин раскладки, G57 −1…2 мс; Adreno 750 — мерить парой прогонов (пре-пасс 1.66 мс станет меньше, G-buffer получит перерисовку; ждём ±0.3 мс), умолчание на Adreno остаётся 0 до замера.
2. **F2 (Vignette∘Combine) не взводится**: `fused F1 0 / F1A 752 / F2 0 ... armed F1 1 F2 0` [лог U02h `post:`] при уровне поста 4. Найти отказ (`vkn_post.c`, строка отказов печатает только F1A), взвести. Выигрыш — один полноэкранный проход 2400x1080 (≈ 0.2 мс на 750, 20.8 МБ на тайлере); ≤ 1 младшего разряда (как описано в `vkn_post.h:53`).
3. **Красная строка LIGHTFUSE** «Sp copied into the skipped Fog's target» 16 раз за прогон [`VK-NATIVE-STATUS.md`, вывод 7] — лишняя полноэкранная копия или штатный обход; разобрать вместе.
Сохранение по истории (`dontcare 0`) чинить не надо: в 3D мёртвых сохранений нет, его заменяют П6–П7.

### П5. Один хвост поста: EoCFog и контур внутрь слитого шейдера, Combine внутрь показа (3–4 ч) — все GPU, ≤ 1 младшего разряда

Что сейчас после F1A: `GBuffer2` ×2 (F1A, затем EoCFog), `GBuffer3` (контур), Combine в окно, показ с поворотом и RCAS — 4–5 полноэкранных проходов RGBA8, 1.6 мс на 750 без показа [лог U02h:2464, 2472, 2473].
Как: (а) EoCFog читает сцену и карту тумана войны своей точкой → вклеить в F1A как последний шаг, с точной имитацией промежуточного округления в 8 бит (`floor(x * 255 + 0.5) / 255`), генератор `tools/dos2_post_fuse.py`, доказательство интерпретатором как у F1; (б) Combine (сцена + слой UI + виньетка) читает свою точку → вычислять внутри draw показа для каждого из 5 отводов RCAS (10 выборок вместо прохода 10.4 МБ записи и чтения); код показа `dm/android/vulkan_present.cpp` (поворот и RCAS уже один draw, строка `rotate` лога).
Переключатель: уровни `DM_VK_NATIVE_POST=5` (а) и `6` (а + б); сверка `DM_VK_NATIVE_POST_VERIFY` существующая (обе ветви в один кадр, сравнение цели).
Точность: (а) точная до округления драйвера (ждём 0–1 младший разряд), (б) ≤ 1 младшего разряда.
Выигрыш [м]: Adreno 750 −0.4…0.6 мс GPU; Adreno 6xx / Snapdragon 7 −1.5…2 мс (полоса); G57 −40 МБ ≈ −2…4 мс; PowerVR −5 мс; Xclipse как 750 × 1.5.
Без устройства: интерпретатор 400 / 400 на шейдер, `POST_VERIFY` на Mi 14. С устройства: взгляд хозяина на край тумана войны и контур (контур после сглаживания — уже принятое отличие уровня 4).
Риск: средний — форма хвоста меняется в меню, диалогах, на карте; отказ = старый путь (как у F1A: счётчики «refusals»).

### П6. Проходы без лишних границ: пре-пасс + G-buffer одним проходом, узкие зависимости, раскладка без `UNDEFINED` (4 ч) — тайлеры, точно

1. **Пре-пасс и G-buffer — один проход** (2.5 ч). При открытии прохода «только глубина» на цели, которая в прошлом кадре следующей получила набор G-buffer с той же глубиной, открыть сразу проход G-buffer (4 цвета + глубина), draw пре-пасса идут в нём с маской записи цвета 0 (вариант конвейера: класс совместимости G-buffer, маска 0 — поле уже есть в `vkn_pipe_desc`). Когда движок ставит цели G-buffer и чистит цвета — проход не закрывается; очистки цвета предсказаны в начале прохода (`loadOp CLEAR` значениями прошлого кадра), при несовпадении значения — `vkCmdClearAttachments` (точно, просто дороже). Неверное предсказание набора — закрыть и открыть как раньше (счётчик). Файл `vkn_pass.c` (`vkn_pass_targets`, `begin_set`), история — по образцу ключей `sk_ent`. Переключатель `DM_VK_NATIVE_PASSJOIN`: 0 / 1 / 2 счёт / 3 яд (цвета в начале слитого прохода пурпурные до очистки движка — если очистка не пришла, видно). Снимает сохранение + загрузку глубины (16.8 МБ) и один проход; G57 −0.8…1.7 мс, PowerVR −2 мс [м]. Пары запросов видимости (672 на кадр, `COND=0` — не исполняются) слиянию не мешают.
2. **Узкие зависимости прохода** (1 ч). На семействах-тайлерах внешние зависимости: приёмник `att_st | FRAGMENT_SHADER | TRANSFER` без `VERTEX_SHADER` и `COMPUTE_SHADER` [код `vkn_state.c:446`]; чтение цели из вершинной стадии или compute (редкость: счётчик `tilebar_full`) получает явный полный барьер — он и так ставится при смене раскладки. Все проходы семейства создаются одинаково (совместимость не страдает). Переключатель — внутри `DM_VK_NATIVE_TILEBAR=2`. Mali до −13 % кадра [KB FN-32], если драйвер ещё не перекрывает; PowerVR не мерено.
3. **Начальная раскладка = текущая** вместо `UNDEFINED` для проходов с `CLEAR` / `DONT_CARE` (0.5 ч) [код `vkn_state.c:427` и такая же строка для цвета]. Только Mali: сохраняет подпись исключения неизменных тайлов (KB FN-33). `DM_VK_NATIVE_TE=1` на Mali.
Проверка без устройства: слой проверки Vulkan (`DM_VK_VALIDATION=1`) чист; журнал П0: проходов −1, пар «сохранить / загрузить» глубины −1; яд. С устройства: время.

### П7. Слой UI одним проходом и кэш всего UI (4–6 ч) — после П2; все GPU, точно

Если после П2 в слое UI остаются уходы в цели (анимированный текст, окна с фильтрами): блок «вытолкнуть цель … вернуть» ничего не читает из родительской цели (особые смешивания с чтением приёмника получают заглушку, `hle_dos2_vkn_ui.c:52`), значит его записи можно исполнить **до** прохода слоя. В потоке записей (`vkn_rt.c`) блоки уходов переносятся вперёд слоя; слой UI = 1 проход. Счётчик и сверка порядком: `=2` исполняет как раньше и сравнивает цель слоя.
Вторая ступень: хэш всех записей UI кадра (0.6 МБ, ≈ 0.1 мс) + версии текстур; при равенстве с прошлым кадром записи UI отбрасываются, слой `tex#002d` остаётся прошлым (очистку слоя тоже пропустить). Особые draw движка с целями, записанными в этом кадре (портреты), запрещают пропуск. Переключатель `DM_VK_NATIVE_UICACHE` 0 / 1 / 2 сверка / 3 яд.
Выигрыш [м] в кадрах без изменений UI: Adreno 750 GPU −0.8…1.0 мс (весь UI, кроме Combine), поток записи −1.0 мс (246 draw UI); в бою и при движении курсора по подсказкам — ноль. Тайлеры: слой 12 → 1 проход (−230…460 МБ модели).
Риск: средний-высокий (полнота ключа; вторую ступень включать по умолчанию только после недели сверки `=2` у хозяина).

### П8. Дальний каскад теней через кадр (2 ч) — почти точно, по классу GPU

Если П3 покажет, что «новые по константам» — настоящая анимация (ветер): динамическую часть каскада 2 (351 draw) обновлять раз в 2 кадра, каскада 1 — каждый кадр. Слой кэша уже хранит статическую часть; динамическая рисуется в свой слой и копируется. Мера отличия: тень качающейся листвы в дальнем каскаде запаздывает на 1 кадр (13–33 мс); неподвижное бит в бит. Переключатель `DM_VK_NATIVE_SHRATE` 1 / 2 / 3; умолчание 1 (каждый кадр) на Adreno 750, 2 на слабых классах (в уровне «Средний» страницы хаков, рядом с `DM_HACK_SHFAR`), не точное → не в общие умолчания.
Выигрыш [м]: 750 поток −0.7 мс, GPU −0.25 мс; Snapdragon 7 −2 мс потока; G57 −1…1.5 мс.

### Мелочи (по 1–2 ч, только при подтверждённой пользе)

- fp16 (`mediump`) в хвосте поста после LUT на Mali: на Adreno `RelaxedPrecision` даёт +8 % [KB PERF-DOS2-NR], на Mali EASU fp16 −28 % циклов [KB PERF-X23]. - Умолчание масштаба 3D по классу GPU (750: как сейчас; Adreno 6xx / Snapdragon 7: 75 % + EASU; G57: 60 % + DRS) — таблица в `vkn_policy.h`, после первых данных с устройств; 75 % = GPU −31 % [KB PERF-X23].

## 5. Риски

1. **Модель трафика UI — верхняя граница.** Если Mali и PowerVR сами пропускают тайлы без геометрии, П1 даст единицы мс, а не десятки. П1 всё равно дешёв и точен; П2 полезен при любом исходе.
2. **П3 — гипотеза.** Сначала часовой замер; без него 2 часа реализации не начинать.
3. **П2 и П7 — полнота ключа кэша.** Любое поле, не вошедшее в хэш, даёт устаревший текст на экране. Обязателен режим сверки и запрет кэша для блоков с draw движка.
4. **П6.1 — предсказание набора целей.** Меню, смена сцены, смена разрешения DRS: промах предсказания должен стоить только лишнюю очистку; счётчик промахов в журнале.
5. **П10** затрагивает класс совместимости всех конвейеров G-buffer (прогрев ×2, рывки при первом входе) и порядок сегментов команд; без устройства с тайлами принять нельзя.
6. Нагрев и потолки частот: сравнивать только прогоны с равными потолками (`VK-STAGE5-PLAN.md` §7).
7. В `wt-vk` могут работать другие агенты: `vkn_pass.c` правят П0, П1 (подсказка области), П6 — вести их одним куском или строго по очереди.
