# N1 NR-NSHADER — тяжёлые шейдеры: ранжирование настоящими компиляторами Adreno и Mali, что ещё можно снять (ночь 19.11)

Ветка `dos2-nshader` (worktree `wt-nshader`, база `dos2-night1119` 7780b92). Телефона не было: всё ниже — офлайн, на логах / heat-файлах
Mi 14 Ultra (Adreno 750, turnip27, `TU_DEBUG=sysmem`, 3D 2160x972) и на паке шейдеров игрока. **Код игры / движка не менялся, умолчаний
нет, APK = база** (поэтому APK не собирал). Сделан инструмент и измерения, по которым видно, где у шейдеров ещё есть время, а где нет.

## 0. Коротко
- **Новое: офлайн-компилятор Adreno 750.** Тот же Mesa, что у турнипа телефона (`<tools>/src/mesa-full`, main 1c3a936 = turnip27), собран
  под x86_64 Linux (WSL) с kmd kgsl, плюс поддельный `/dev/kgsl-3d0` (`tools/tu_stats/fakekgsl.c`, чип 0x43051401 = FD750): драйвер
  создаёт настоящие пайплайны и отдаёт статистику своего компилятора ir3 (`VK_KHR_pipeline_executable_properties`: инструкции с nop,
  регистры, волны, размер волны, ожидания `(ss)/(sy)`), `IR3_SHADER_DEBUG=disasm` даёт дизассемблер. GPU не нужен. До сих пор у
  проекта был только `malioc` (Mali); для Adreno — «оценка». Инструменты: `tools/tu_stats/` (§2).
- **Переведённый код на Adreno уже почти не стоит лишнего.** NIR турнипа снимает почти всю «накладную» транслятора: нативные перепис
  NR-04 / NR-33A против переведённых (после той же цепочки загрузки, что на телефоне) — **−18 … +16 % статических слотов**, у большинства
  ±5 % (таблица §3). Это объясняет замер NR-04 «≈ −0.1 мс на Mi 14».
- **Системных SPIR-V-проходов для Adreno не нашлось** — все проверены компилятором (§4): NR-27 UBOVEC 0 инструкций, NR-32 XLQ 0, NR-IDVS
  −0.6 % VS, `RelaxedPrecision` везде +8 % (половинных регистров турнип не берёт). Цепочка загрузки, которая уже стоит на телефоне
  (`LDC_FOLD` / `FORWARD_TEMPS` / `LDC_CANON`), — вот она дала своё: VS скиннинга 722 → 397, VS теней со скиннингом 470 → 141, VS Форта
  за кадр 416 → 316 М инструкций (−24 %).
- **Перепись материалов не нужна**: G-buffer FS 106–175 слотов, 16 волн (кроме 4-MRT упора в 8 регистров), depth FS 30–93; ALU прохода
  G-buffer ≈ 0.2–0.3 мс из его 3 мс — его время в полосе / геометрии / цене draw, не в шейдере.
- **Где шейдер ещё упирается в ALU на 750:** `ClusteredLightingWithSSAO` в сценах с многими светами (TUT: 2.65 мс; ≈ 100 слотов на свет;
  768 нитей из 2048), F1A (Sight ∘ LUT ∘ FXAA', 0.81 мс, ≈ 80 % пика ALU). Проверил точные перестройки цикла света (§5): выпрямление
  ветвлений −5 %, развёртка ×2 −6 %, «одинаковый кластер у волны» −3 % — **меньше 5 %, не делал**. F1A нативно: Sight/LUT/FXAA — чистая
  арифметика, `-O`/`-Os` не меняет ни бита у обоих компиляторов → не делал.
- **Главный оставшийся рычаг — не текст шейдера, а слияние проходов освещения:** DeferredSky и ClusteredLighting читают один и тот же
  G-buffer дважды и гоняют через память промежуточные Sp / Df. Прототип слитого FS (Sky ∘ Clustered, с эмуляцией квантования R11G11B10)
  — Adreno 1590 слотов против 300 + 1434, Mali G57 18.75 против 3.85 + 17.0 циклов, т. е. ALU не растёт; полоса −46…59 МБ/кадр →
  **оценка Mi 14 −0.45…0.6 мс GPU (4–5 %)**, слабые Adreno / Mali больше (§6). Нужна плановая часть хоста (как NB-18b для поста) —
  следующий шаг, не сделан этой ночью.

## 2. Инструмент `tools/tu_stats` (что сделано)
| файл | что |
|---|---|
| `build_host.sh` | рецепт в WSL (Ubuntu-22.04, без root, ничего не качает): копия `mesa-full` в `$HOME/n1mesa`, сборка турнипа хоста (`-Dvulkan-drivers=freedreno -Dfreedreno-kmds=kgsl`, без платформ / LLVM; zlib — заголовки NDK + `libz.so.1` хоста; правка **только копии**: `tu_autotune` `unordered_map` с неполным типом → `unique_ptr`, libstdc++ 11), затем `fakekgsl.so`, `tu_stats`, `phone_chain` в `$HOME/n1tools`. Сборка турнипа ≈ 10 мин, инструментов секунды |
| `fakekgsl.c` | LD_PRELOAD: `/dev/kgsl-3d0` → свой fd; ioctl GETPROPERTY (DEVICE_INFO chip `FAKEKGSL_CHIP`=0x43051401, GMEM 3 МБ, UBWC 4, VA 40 бит), ALLOC_ID / GET_INFO / FREE, DRAWCTXT, GPU_COMMAND / TIMESTAMP «исполнены сразу»; `mmap` fd → анонимная память; dma-heap / ion — нет |
| `tu_stats.cpp` | грузит ICD напрямую (`vk_icdGetInstanceProcAddr`), устройство с `pipelineExecutableInfo`; на строку манифеста `<имя> <vs.spv> <fs.spv\|-> [VkFormat цвета… \| 0 = без цвета]` — раскладка дескрипторов / входы вершин / цели из отражения SPIR-V, динамический рендеринг, пайплайн с `CAPTURE_STATISTICS`; печать всех статистик драйвера + `Subgroup_size` по стадиям (VS, FS, Binning VS) |
| `phone_chain.cpp` | SPIR-V, который телефон отдаёт `vkCreateShaderModule`: боевые проходы `xbg_spirv_ldc/temps/peep/ubovec` + копия `nan_minmax_swap` (как `tests/vsout_scan.cpp`), буквы как у NR-32: Adreno `nftcp` (по логу Mi 14: NAN_MINMAX+SAT, FOLD, TEMPS, CANON, F2I), Mali `nftcpu` (+ UBOVEC) |
| `tu_stats.py` | обёртка: `run jobs.tsv` (ключ пака / `.spv` / `.xgs` / `pack:<xgspack>:<ключ>` — нативные и слитые бандлы, XGF1 тоже) |
| `tu_survey.py` | ранжирование: JSON heat-инструмента → цепочки Adreno / Mali → `tu_stats` по каждой паре (VS, FS, цели) прохода → `malioc` (ядра на выбор) → таблица и TSV; где на телефоне стоит нативный / слитый бандл, меряется он |
| `ir3_loops.py` | модель слотов выдачи по дизассемблеру ir3: всего и на тело каждого цикла (обратный переход), nop с `(rptN)` считаются |

Запуск (≈ 2 мин на уровень):
```
wsl -d Ubuntu-22.04 -- bash <tree>/tools/tu_stats/build_host.sh          # один раз
python tools/dos2_shader_heat.py <logs>/*heat*.tsv --pack <work>/shaders-vk/shaders.xgspack --min-passes 20 --json heat.json
python tools/tu_stats/tu_survey.py --heat-json heat.json --level FJ_FortJoy_Main --native-pack <work>/native-nr33a/native-nr.xgspack \
    --fused-pack <work>/shaders-native-post-a/fused.xgspack --malioc <...>/malioc.exe --cores Mali-G57 --out survey.tsv
```
Оговорки: статистика — статическая (всего в модуле, обе стороны ветвлений; для «исполнено» — `ir3_loops.py` по телу цикла); нити =
`Max_Waves_Per_Core × Subgroup_size` (ir3 сам выбирает волну 64 / 128: при < 8 волнах по 128 — 64); проверка на турнипе 27 телефона,
сборка того же коммита; GMEM / sysmem на компиляцию не влияют. Самопроверка: `python tools/tu_stats/tu_stats.py selftest` (переведённый
PPFXAA и пустой VS собираются, статистика FS есть).

## 6. Следующий шаг с реальным выигрышем: слить DeferredSky → ClusteredLighting (→ CascadedPCF) в один проход
- **Почему:** оба прохода полноэкранные, в полосе; Clustered заново читает G0 / нормаль / глубину / базу, которые только что читал Sky, и
  читает выход Sky (Sp, R11G11B10F) + грузит Df. Слитый FS читает G-buffer один раз и пишет только Df.
- **Прототип (для цены, не для пака):** `Sky` быстрым путём как функция внутри нативного Clustered, `amb = q11(spec Sky)`, выход
  `q11(diff Sky) + …` (эмуляция записи R11G11B10F с округлением к чётному), ресурсы Sky на своих привязках. Adreno: **1590 слотов, 16 рег,
  768 нитей** против 300 + 1434; Mali G57: **18.75 цикла, 64 рег** против 3.85 + 17.0 — ALU не растёт (общие выборки / декод).
- **Оценка:** Mi 14 полоса −46…59 МБ/кадр (G0 4 + норм. 4 + глуб. 2 + база 4 Б второго чтения, запись+чтение Sp 8, запись Df Sky 4) ≈
  −0.55…0.7 мс, минус ALU Sky, который сейчас прячется под его полосой (≈ 0.2) → **−0.45…0.6 мс GPU в Форте, ≈ −0.4 мс в TUT** (4–5 % кадра
  11.7 мс). С PCF ещё −0.05…0.1 (R8 S запись+чтение, вторая глубина). Слабые Adreno (полоса 25–35 ГБ/с) ×2–3: −1…1.5 мс. Mali G57 MC2:
  −2.1 цикла/пикс ALU ≈ −1.3 мс при DRS 75 % + тайловые загрузки / выгрузки Sp / Df (то, что NR-ONCHIP хочет подпроходами, но одним проходом).
- **Точность:** НЕ бит в бит по построению: в цепочке Sp / Df проходят через R11G11B10F (6 / 5 бит мантиссы) и через блендер; слитый
  точнее (≤ 1 ступень R11 на пиксель, видимой разницы нет). Эмуляция `q11` даёт совпадение, если округление записи у GPU — к ближайшему
  чётному (Vulkan оставляет режим реализации) → проверяется одним прогоном `=2` (рисовать как сейчас, сравнивать) на телефоне. До этого —
  класс «точнее, но не бит в бит», умолчание 0.
- **Что нужно (≈ 4–6 ч агента):** план NB по образцу NB-18b F1 (`nb_plan.c` пост-план: классы FS Sky / Clustered, условия «Sp читает
  только Clustered», «Df не читается между», один размер, без DRS-частей), backend `xbg_nb_post.inc`-стиль: тайник привязок Sky (как LUT
  в F1), бандл `F5.<ключ Clustered>` в fused-паке, Df этого прохода → CLEAR вместо LOAD; переключатель `DM_NR_LIGHTFUSE` 0 / 2 / 1 / 3;
  доказательство на `spv_interp` (Sky → q11 → Clustered против слитого, бит в бит при RNE-модели записи).

### 11.1 Предскиннинг (compute раз за кадр → VS читают готовые позиции / нормали) — **не делал: на Mi 14 выигрыша нет**
