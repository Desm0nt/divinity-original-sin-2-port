# NR-08b `DM_NR_UBODYN` — дескрипторы PowerVR: dynamic UBO только для читаемых блоков кольца (сегмент S4), 17.11.2026

Ветка `dos2-nr08b` (worktree `wt-nr08b`) от `dos2-nr08` (40461f6). Продолжение NR-08 (`docs/dos2/nr/NR-08.md` §2 п. 1, §6, §8) и NR-19
(`git show dos2-nr19:docs/dos2/nr/NR-19.md` §1 «Цена на PowerVR»). **На телефоне не исполнялось.**

## 1. Почему у PowerVR в политике нет dynamic UBO
- `xbg_vendor_policy.h` `xbg_ubo_dynamic_default`: `f!=XBG_GPU_POWERVR`; комментарий ссылается на PPSSPP `PVR_UNUSED_DYNAMIC_UBO_OVERRUN`.
- PPSSPP 73559d15aa (Moto G54, **PowerVR BXM-8-256** — тот же GPU и драйвер, что у нашего игрока DOOM moto g64): при draw драйвер пишет
  адрес + диапазон **каждого dynamic UBO, видимого стадии**, в таблицу размером «по UBO, которые стадия **читает**». Объявленный, но не
  читаемый dynamic UBO пишет 16 байт за конец таблицы → page fault в `vkCmdDrawIndexed`, когда таблица кончается на границе страницы
  (F1 2009: 5 из 5 прогонов по 10 с падали, после фикса 0 из 5). PPSSPP dynamic UBO не выключил, а заставил стадию читать блок
  («declaring it isn't enough» — нужна настоящая загрузка).
- То есть это **не** лимит 0 и **не** медленный путь: BXM-8-256 1.15 (лог игрока DOOM `pvr-1111/…/boot.log`) сообщает
  `ubDyn=4294967295`, `stageUB=16`, расширения `VK_KHR_push_descriptor`, `VK_KHR_descriptor_update_template`. Правило превентивное:
  у нас падение не воспроизводилось ни разу (D16 B&F §2.50), устройства с PowerVR у нас нет.
- D16 (PVR-06, 09.11): `DM_GFX_UBO_DYNAMIC=2` по умолчанию на PowerVR — dynamic только у блоков, которые SPIR-V стадии читает
  (`xbg_spirv_reads.h`). На реальном PowerVR в игре **не подтверждено**: прогон moto g64 с `ubo_dynamic=2` (0.5.0, pvrdiag1) упал раньше,
  на заставке Bink, по причине zero-copy (§2.58). У D16 при сбое есть безопасный режим (0.5.2: ступень 1 возвращает `UBO_DYNAMIC=0`);
  в нативной части DOS2 счётчика сбоев / ступеней я не нашёл (Java `SafeMode` есть, нативного `gfx-safe-mode` нет).
- Модель D16 на Mi 14 (`SIM_GPU=powervr`, CPU-упор): `UBO_DYNAMIC` 0 → 1 = 32.8 → 44.9 fps, submit 19.0 → 12.9 мс — цена «без dynamic»
  реальна. В DOS2 она больше: константы из кольца → ключ мемо с адресом промахивается почти всегда + правило VK-UBO-MEMO запрещает
  мемо статических блоков игры → **полная сборка набора на каждый draw** (NR-19: +11…22 мс CPU транслятора на кадр [оценка]).

## 2. Замер по всем бандлам DOS2 (то, на чём стоит решение)
`tests/nr_ubodyn_test.c` с каталогом (12 329 модулей, 6 130 пар VS + FS из `programs.tsv`), правило «читается» = загрузка в функции
точки входа, **результат которой используется** (строже D16):

| uniform-привязки | объявлено | не читается стадией |
|---|---|---|
| source 1, support-блок | 12 329 | **10 668** (87 %) |
| source 2, блоки игры (кольцо констант NR-06) | 27 211 | **0** |
| source 4, константы c1 | 8 327 | 0 |
| driver-блоки (5 / 6) | 0 | — |

- Все 12 329 модулей разобраны (1 155 с двумя-тремя функциями: правило считает чтения только в функции точки входа — все их блоки игры
  читаются там же; чтения только в вызываемой функции безопасно считаются «не читается»). Флагов у uniform-привязок в бандлах нет (бит 29 / 28
  свободны). Ни одного блока игры, у которого все загрузки мёртвые.
- Вывод: опасный случай PPSSPP у DOS2 — **только support-блок**, а он в режиме 2 `dyn_mode_for` и так статический. Блоки игры —
  ровно те, что меняются на каждом draw, — читаются всегда.

## 3. Что сделано
`DM_NR_UBODYN=1` там, где политика выключила dynamic UBO (PowerVR, `SIM_GPU=powervr`, `DM_GFX_UBO_DYNAMIC=0`):
1. **Скан модуля** (`nrubd::mark`, `load_shader_key`): финальные слова модуля после всех переписываний (bindless, gscull, lone, quad,
   warp, …) → `nr_spv_binding_reads`; uniform-привязке ставится `XBG_BIND_SCANNED`, нечитаемой ещё `XBG_BIND_UNREAD`. Модуль, который
   скан не понял (не одна точка входа, обрезка, плохой заголовок), — все его блоки статические + красная строка.
2. **`dyn_mode_for`**: как при включённых dynamic, но не выше режима 2 (только блоки на draw — игры и драйвера; support / c1 никогда), режим 3
   (сплит NR-08) — как был. **`UBO_DYN`**: при правиле dynamic только привязка `SCANNED` без `UNREAD` (не сканированная — статическая).
3. **Оптимизатор** (`DM_GFX_SPV_OPT`, `bundle_module`): копия, которая читает меньше привязок, чем просканированный модуль
   (`nr_spv_reads_kept`), не используется — создаётся оригинал (счётчик, красная строка). Варианты alpha / retype читать меньше не могут
   (добавляют код); вариант alpha NEVER (убивает все фрагменты — драйвер может выбросить все чтения) считается и даёт красную строку
   (в логах DOS2 есть только GREATER 0.5).
4. Что это даёт без NR-08: блоки игры — dynamic → старый `descriptors()` снова попадает в мемо (VK-UBO-MEMO отказывает только статическим
   блокам игры), как на Mali. С NR-08 (`DM_NR_DESC=1`): у 6 130 из 6 130 пар нет ни одного статического слова кольца → набор пишется
   **один раз** на запись, как на Adreno (вместо одного `vkUpdateDescriptorSetWithTemplate` на draw).

Классы (`nr_ubodyn_test`, план NR-08 `nr_dplan_build`):

| класс | режимы 0 / 1 / 2 | пар без статических блоков кольца (набор пишется один раз) | статических слов |
|---|---|---|---|
| PowerVR сейчас (`DM_NR_UBODYN=0`) | 6130 / 0 / 0 | 1 | 1–11, медиана 4–5 |
| PowerVR BXM (`ubDyn` 0xffffffff), `=1` | 0 / 0 / 6130 | **6130 (100 %)** | 0, до 11 dynamic-смещений |
| SIM powervr на Adreno (16), `=1` | 0 / 0 / 6130 | 6130 | 0 |
| PowerVR с лимитом 8, `=1` (без сплита) | 147 / 0 / 5983 | 5983 | 9–11 у 147 пар (со сплитом NR-08 — режим 3, 1–3 слова) |

### Что НЕ стал делать (и почему)
- **Push descriptors** (`VK_KHR_push_descriptor` у BXM есть): заменили бы «взять набор + шаблон + bind» одним `vkCmdPushDescriptorSet…`,
  то есть столько же вызовов на draw, сколько NR-08 сейчас; при правиле наборы не переписываются вовсе, и push дал бы только лишнее
  (копия всех ~8 дескрипторов в командный буфер на каждый draw). Плюс новые раскладки (флаг PUSH) = все пайплайны новые на медленном
  компиляторе IMG, `maxPushDescriptors` BXM неизвестен, в ETR push был вреден (PERF-E18), на стоковых драйверах «игнорируются / медленны»
  (field notes). Без устройства — не оправдано.
- **Физические два набора** (текстуры + малый UBO-набор из кольца): при правиле статических блоков кольца нет — делить нечего; без правила —
  всё равно одна запись на draw, плюс перестановка `DescriptorSet` в SPIR-V и пересборка всех пайплайнов (NR-08 §2 п. 1).
- **Шаблоны** (`vkUpdateDescriptorSetWithTemplate`): NR-08 уже пишет статические кортежи шаблоном; при правиле перезаписей нет.
- **Блоки, которые стадия не читает, убрать из раскладки** (вместо статических): другая раскладка support-блока ничего не даёт (он не меняется).

## 4. Переключатели (умолчание 0; игрокам не выдаются)
| | значение |
|---|---|
| `DM_NR_UBODYN` | **0** — ничего (нет скана, нет битов; `UBO_DYN` / `dyn_mode_for` — по одной непринятой ветке). **1** — правило там, где dynamic выключены политикой или `DM_GFX_UBO_DYNAMIC=0`; где они включены (Adreno / Mali / Xclipse) — «nothing to do», раскладки бит в бит прежние (модули сканируются и считаются). **2** — сухой прогон: скан, биты, счётчики, красные строки; раскладки как при 0 (на любом телефоне показывает, что сделала бы 1). **3** — нет (красная строка, выкл.). Не требует `DM_NR` / `DM_NR_BUF`. |
| `DM_GFX_UBO_DYNAMIC=2` | написание D16 (PVR-06) того же правила: включает его на любом семействе (A/B на Mi 14 без SIM). `=1` при `DM_NR_UBODYN=1` — «всё dynamic» (выбор пользователя важнее), `=0` — правило включается. |
| умолчание | `xbg_nr_ubodyn_default` = 0 на всех; кандидат — 1 на PowerVR после прогона на устройстве PowerVR |

Строки: `[nr] DM_NR_UBODYN=… (NR-08b: on / dry run / off; DM_GFX_UBO_DYNAMIC=…, family … default …): …` сразу перед `NVN gpu policy`
(там `ubo_dynamic=1` при правиле); `[nr] ubodyn: DM_NR_UBODYN=… (rule in force | dry run); modules M (not understood N …), X us a scan;
uniform bindings: per-draw read R (dynamic | would be dynamic), per-draw NOT read U (fixed), support / c1 read …, not read …; optimized
copies checked …, refused …; alpha NEVER variants under the rule …; red …` — не чаще раз в 10 с, пока грузятся модули, и при сохранении
кэша пайплайнов; `[nr] ubodyn: shader … declares N per-draw uniform block(s) it never reads …` (первые 8); красные `【红】[nr] ubodyn: …` (16).

## 8. Риски (честно)
1. **Главный: правило «читается» — наше, драйвер решает сам.** Если компилятор IMG выбросит загрузку, которую SPIR-V делает (значение
   уходит только в мёртвые вычисления, ветка, которую он докажет недостижимой, alpha NEVER), стадия станет «не читает» для драйвера →
   переполнение таблицы → page fault в `vkCmdDraw*`. Скан отсекает только тривиально мёртвые загрузки. У D16 тот же риск (не подтверждено
   на устройстве), но там есть безопасный режим; **у DOS2 нативного отката после падения нет** — поэтому умолчание 0, и включать на
   PowerVR только тестовой сборкой.
2. Новые раскладки для PowerVR → игроку с уже прогретым кэшем пайплайнов (при `UBO_DYNAMIC=0`) все пайплайны соберутся заново (компилятор
   IMG медленный; один раз). Записи прогрева со старыми раскладками строятся, но не используются.
3. Модули, загруженные до `init` (повторная инициализация устройства / смена драйвера), не сканированы → при правиле их блоки статические
   (безопасно, но медленно; бит `SCANNED`).
4. Хвост `UBO_DYN` меняет общий макрос ядра `dm/` (при `ro=false` поведение прежнее); `ubo_memo_snapshot_test.py` (NR-19) режет макрос
   первой строкой — после слияния ему понадобятся заглушки `nrubd::ro` / `XBG_BIND_*` (и `nrdesc::split_has` от NR-08).
5. Сухой прогон (`=2`) на Adreno не проверяет драйвер PowerVR — только наш скан и счётчики.

## 9. Не сделано
- Умолчание по детекту (нужен PowerVR); push descriptors / физическое деление (§3, не нужны); быстрый путь хазарда RT-образов (NR-08 §8).
- Перенос в другие порты: у D16 уже есть свой `UBO_DYNAMIC=2`; для KB — запись после подтверждения (KB правит главная сессия).

## 10. Прогоны телефона (главный агент, по разрешению хозяина)
Бэкап `files/save`; keyguard снят; без лимита кадров; `DM_NB_MT=0`; сцены: палуба 60 с + Форт Радость / бой.
1. **R-NR08b-a, сухой прогон (Mi 14, без SIM):** `DM_NR_UBODYN=2`. Ждём `[nr] DM_NR_UBODYN=2 (NR-08b: dry run …)`; `[nr] ubodyn: … modules N
   (not understood 0) … per-draw NOT read 0 … refused 0 … red 0`; картинка и `submit_cpu_ms` как без флага.
2. **R-NR08b-b, правило в модели PowerVR (ABBA × 2, 60 с):** `DM_GFX_SIM_GPU=powervr` против `DM_GFX_SIM_GPU=powervr DM_NR_UBODYN=1`.
   Ждём `[nr] DM_NR_UBODYN=1 (NR-08b: on …)` и `NVN gpu policy: … ubo_dynamic=1`; `NVN PERF setcache … memo_hits` ≈ draw (было ≈ 0),
   `ubosnap` ≈ 0 (было ≈ draw); `NVN PERF desc_ns_per_frame`, `submit_cpu_ms` — разница (оценка: −8…−15 мс на X4); скриншоты равны.
3. **R-NR08b-c, с NR-08:** `DM_GFX_SIM_GPU=powervr DM_GFX_ZEROCOPY=0 DM_NR=1 DM_NR_BUF=1 DM_NR_UBODYN=1 DM_NR_DESC=2` (сверка, `bad 0`), затем
   `DM_NR_DESC=1`: `[nr] DM_NR_DESC=1 … dynamic uniform buffers on … every block a dynamic offset`, `[nr] desc: … sets: reused ≫ written`
   (в R-NR08d без правила было `written ≈ draws`), `ns a served draw`, картинка равна.
4. **R-NR08b-d, реальный PowerVR (тестер, тестовая сборка «test issue»; игрокам флаги не выдаются):** сборка с `xbg_nr_ubodyn_default(POWERVR)=1`.
   Доказывают: нет `CRASH … vkCmdDraw*` / page fault за 10+ минут игры в бою и городе; `[nr] ubodyn: … red 0`; fps / `submit_cpu_ms` против
   той же сборки с `DM_NR_UBODYN=0`. Падение → откат умолчания на 0 и разбор (какой модуль: `crash pass` / последние ключи шейдеров).
