# NR-04 `DM_NR_SH` — движковые шейдеры по имени (сегмент S1b)

Ветка `dos2-nr04` (worktree `wt-nr04`, база `dos2-nr02` c8b43fc). План: `NATIVE_RENDERER_PLAN.md` §3 NR-04, §2 S1. Опирается на NR-02
(ключ пака DOS2 = `xbg_shader_program_key`, control + код; имя ↔ ключ). **По умолчанию 0 — поведение байт в байт прежнее.** На телефоне
не исполнялось (телефона не было); всё ниже — ПК: тесты, сборка `libdm.so`, а также **старые прогоны телефона с теми же SPIR-V** (§4).

## 2. Переключатели
`DM_NR_SH` (не нужен `DM_NR`; `DM_NR=1/2` добавляет сверку имён):
- **0 / не задан** — ничего: пак не открывается, одна проверка целого на чтение бандла; строки `p->nr_sh` / `nrpass::choose` не срабатывают.
- **1** — замена: post (5) и light (2), доказанные бит в бит; тени — по `DM_NR_SH_PCF` (0 = транслированные, **по умолчанию**; 1 = exact;
  2 = mobile). Бандл берётся только при: голова = транслированной байт в байт, входы / выходы равны, все дескрипторы в таблице; иначе —
  транслированный + красная строка. Вне проверенного прохода — транслированный модуль для этого пайплайна.
- **2** — проверка: всё то же (чтение пака, голова, интерфейс, дескрипторы, проход каждого пайплайна), исполняются транслированные.
- **3** не существует (любое другое значение — красная строка и «выкл»): замены post / light бит в бит, «травить» нечего; факт попадания в
  кадр и так дают строки `→ … used` и строки проходов.
- Строки: `[nr] sh DM_NR_SH=…` при первом чтении; `[nr] sh <имя> -> x.<имя> (proven bit for bit): head byte for byte (<fnv>), inputs … outputs …,
  SPIR-V N -> M words` (или `check:` в режиме 2) — один раз на запись; `[nr] sh <имя> pass <hash>: colours [..] depth .. samples .., WxH - the
  verified pass` — один раз на пару; сводка раз в 10 с (из подачи, если что-то изменилось): `entries replaced K of 10 … refused … missing …
  kept translated … off by a name contradiction … engine names agreeing … pipelines in the verified pass … outside it … red lines …`.
  Красные `【红】[nr] sh …` — первые 16, считаются все.

## 5. Ожидаемый выигрыш по классам
Исполнено на пиксель (интерпретатор, масштаб 1): Clustered 744 → 428 (сцены: без света 463 → 345, 1 точечный 576 → 392), Fade 175 → 82,
Fog 115 → 72, Outline 93 → 53, LinearizeDepth 40 → 22, DownSampleLog2 97 → 40, PCF 3x768 exact 427 → 249 (mobile — 4 gather вместо 9 выборок).
- **Mi 14 / Adreno 750:** −0.1 мс GPU (замер §4), 0 CPU в кадре (пак читается по разу на шейдер). Это тепло, не fps.
- **S7 (Adreno 710–730) [м]:** те же проходы ≈ 2.4 мс на 750 → ≈ 8.5 мс при ×3.5; если ALU-упор у 20–50 % их времени — −0.7…2 мс, плюс
  тени exact −0.1…0.4 → **−0.5…2.5 мс из ~30**. Это меньше «−3…5» плана: тени mobile (ещё −0.2…0.5) только после взгляда хозяина.
- **Mali (MTK) [м]:** по плану там упор в CPU транслятора → fps не сдвинется, пока упор в CPU; в тяжёлых по GPU сценах — как S7. Копий /
  zero-copy NR-04 не добавляет. Плоский `textureGather` (mobile) не требует `shaderImageGatherExtended`.
- **PowerVR (BXM) [м]:** слабый ALU — скорее верх диапазона; формат / сэмплер не меняются (тот же сэмплер игры).
- **Слабый CPU:** 0.

## 6. Частицы ½ и хвост поста (`TILE_SHADER_CANDIDATES`)
- **Частицы:** кандидат 1 уже закрыт флагом движка `DM_DOS2_PARTICLES_FULL=1` (по умолчанию, цепочки DownsampleDepthMax / ½ LinearizeDepth /
  CrossBilateralUpsample нет). NR-04 его не трогает и не регрессирует (`LinearizeDepth` проверен в обоих размерах с одним форматом).
  Открытый вопрос — **слабые GPU**: полный размер = overdraw частиц ×4 пикселя; цепочка стоила на Mi 14 ≈ 0.3 мс (CrossBilateral 0.19 +
  DownsampleDepthMax 0.07 + LinearizeDepth½ 0.04, gp1) + свой проход. На S7 в бою с эффектами ½ может оказаться дешевле — это A/B флага,
  а не шейдер; кандидат в политику по семейству после замера (просьба ниже). Своего шейдера для цепочки не делал: пока она выключена,
  выигрыша 0.
- **Хвост поста:** LUT ∘ Sight ∘ FXAA / Vignette ∘ CombineUI уже слиты NB-18 (`native-post.xgspack`, маршрут A, по умолчанию). Остальные
  записанные проходы хвоста с переписанным шейдером — EoCFog (carry маршрута A), EoCOutlineCombine, FadeBlending, PPDownSampleLog2 — теперь
  в NR-04. Без переписи остаются FXAA мини-конвейера портрета 80x100 (у iPad FXAA тяжелее, `TILE_SHADER_CANDIDATES` «не брать») и bloom /
  luminance (те же шейдеры у iPad).

## 7. Риски и чего нет
- **Пиксели на GPU не сравнивались.** Бит в бит — на скалярной семантике SPIR-V (интерпретатор); драйвер оптимизирует оба модуля сам, так что
  на GPU возможны расхождения на ulp. Прогоны §4 — без снимков экрана в логах.
- Тени exact: до 1.2e-4 и 1 LSB R8 в 1 из 1200 пикселей (сравнение при ref ≈ depth); mobile — другой вид (ровнее край, возможны «призраки»
  края при большом радиусе, см. `DOS2_PORT.md` «Мобильный резолв теней»). Оба — только по взгляду хозяина.
- Имя движка на телефоне ещё не видели (NR-01 не исполнялся): если формат Get-имени не совпадёт с базой таблицы, будут красные строки
  `name … the table does not know` — они ничего не выключают (решают ключ и голова).
- Draw с NVN alpha test берёт alpha-вариант названного модуля в любом проходе (у шейдеров таблицы alpha test не встречается).
- Вне проверенного прохода в режиме 1 — второй пайплайн с транслированным модулем (одна лишняя сборка). Прогрев строит пайплайны с
  названными модулями (как и раньше `DM_GFX_NATIVE_SHADERS`).
- `tools/spv_interp.py` изменён → хэш инструментов `native-post.xgspack` другой: setup один раз пересоберёт и его (1–2 мин, байты те же).
- Игроку нужен повторный запуск setup (стадия 8), иначе `[nr] sh no …native-nr.xgspack` и транслированные шейдеры (только при `DM_NR_SH≠0`).
- Не сделано: тени бит в бит (нужен разбор порядка операций транслированного 1445-инструкционного модуля); 978 материальных бандлов из GLSL
  игры (`dos2_native_shaders.py`: код игры → только через setup, доля в кадре неизвестна, к S1b не относятся); `CombinePPUI`, SSAO-набор iPad
  (SSAO в кадре нет); альтернатива ½ частиц; умолчания по семействам (все 0); APK.
- Общие файлы: `xbg_game.cpp` (+31 строка, остальное в `.inc`), `hle_dos2_nr.c` (+14), `setup_dos2.py`, `source_structure_test.py`.

## 8. Прогоны на телефоне, которые это подтвердят
Перед любым: бэкап `files/save`; APK этой ветки; пак: `python tools/dos2_nr_sh_pack.py --pack work/shaders-vk/shaders.xgspack --out
work/native-nr --programs work/shaders-jobs/programs.tsv` → `work/native-nr/native-nr.xgspack` (180 КБ) в `dm/shaders/` (или стадия 8 setup).
1. **Проверка:** `DM_NR=1 DM_NR_SH=2` (можно вместе с R1 / NR-02: `DM_NR=2 DM_NR_KEY=2 DM_NR_DUMP=1`). Меню → сейв → палуба / кампания 2–3 мин.
   Ждём: `[nr] sh … native-nr.xgspack: 13 bundles`; 7 строк `[nr] sh <имя> check: x.<имя> (proven bit for bit): head byte for byte`; для теней
   `translated kept (DM_NR_SH_PCF=0…)`; строки проходов `… - the verified pass` и **ни одной** `not the verified pass`; сводка `entries passing
   every check 7 of 10 … refused 0 … missing in the pack 0 … outside it 0 … red lines 0`; `engine names agreeing` ≥ 7, нет `sh name check`.
2. **Замена, A/B GPU (ABBA, без лимита кадров `DM_DOS2_FPS=0`, `DM_GFX_PASS_PROF=300,180,0`):** база ↔ `DM_NR_SH=1`. Сводка `entries replaced
   7 of 10`; `python tools/dos2_gpu_breakdown.py <log> --gpass` — медианы проходов §4: FadeBlending ≈ 0.27 → 0.15 мс, остальные ±0.02;
   снимки экрана = базе (бит в бит).
3. **Тени (глазами хозяина):** `DM_NR_SH=1 DM_NR_SH_PCF=1`, затем `=2`; одна сцена кампании, солнце, камера близко и далеко (край тени, акне,
   шов каскадов). exact должен совпасть с базой; mobile — решение хозяина.
4. **Слабые (любой тестер S7 / Mali / PowerVR):** то же, что 2, + сцена боя с эффектами для `DM_DOS2_PARTICLES_FULL=1` ↔ `0` (вопрос §6).
   Сводная строка `[nr] sh …` и `[quality] GPU frame time` — всё, что нужно из лога.
После 1–2 без красных строк кандидат в умолчание — `DM_NR_SH=1` на всех семействах (`xbg_nr_sh_default`), тени — после 3.
