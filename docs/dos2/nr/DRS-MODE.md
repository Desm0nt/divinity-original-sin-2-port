# DRS-MODE — динамическое разрешение привязано к режиму Docked / Handheld (17.11)

Ветка `dos2-nrdrs` от `dos2-nr-all` (b8ec92a), worktree `wt-nrdrs`. Только Java + строки; нативный код не менялся
(`hle_dos2_quality.c` уже умеет всё нужное: `DM_DOS2_DRS=<min>:<max>`, `DM_DOS2_DRS_TARGET_MS`, живой `dm_dos2_drs_live`).

## Решение хозяина (17.11)
DRS не включается по умолчанию «для слабых GPU». Он привязан к режиму Switch, который в порте уже есть:
- **Docked** (режим по умолчанию, картинка, которую хозяин оставляет): полное разрешение, DRS выключен, как сейчас (`DM_DOS2_DRS=off`).
- **Handheld**: DRS **включён** по умолчанию, пол 75 % окна — собственный DRS игры (после фикса TIMESTAMP_TOP NB-18b-11/12 он реально
  регулирует).

## Как было устроено до этого
- Режим: секция `Tl2Gear.Mode` (pref `handheld`, `DM_OPMODE` 1 / 0) — в шестерёнке «при следующем запуске»; пункт режима в меню паузы
  переключает **сразу** (`DmActivity.setDocked` → `nativeSetOpmode` → `hle_oe.c dm_set_opmode`, уведомления 30 / 31; игра сама меняет
  окно: `hle_dos2_wide.c`, handheld = 4/5 окна дока при 900 / 1080, при 720p handheld = docked).
- DRS: одна строка `dos2Drs()` (pref `dos2_drs`, по умолчанию off, + цель 30 / 45 / 60 fps, pref `dos2_drs_fps`), одна на оба режима;
  на старте `DM_DOS2_DRS=off` или (вкл.) `DM_DOS2_DRS` не задан + `DM_DOS2_DRS_TARGET_MS = 1000 / fps × 0,95`; при Save — живой
  `nativeSetDos2Drs(on, fps)`.
- Натив: `DM_DOS2_DRS` не задан = DRS игры (min 75 %), `off` = контроллер с целью 100 мс (никогда не опускает, поднимает до полного окна),
  `<min>:<max>`; живое вкл. / выкл. работает из любого режима, кроме `skip` (нужна наша копия цели).

## Что сделано
`Tl2Gear.java`:
- **Умолчание по режиму.** Docked → off; Handheld → on, `DM_DOS2_DRS=75:100` (пол 75 % явно; патч не нужен — это и есть `fmov #0.75`
  игры, лог пишет `DRS min 75.00 %`) и `DM_DOS2_DRS_TARGET_MS` от лимита кадров.
- **Цель в Handheld по умолчанию = лимит кадров**, `1000 / fps × 0,95`, как у строки: 30 → 31,67 мс, 60 → 15,83, 90 → 10,56,
  120 → 7,92 мс. **Без ограничения → 60** (15,83 мс): без лимита у хоста нет «периода кадра», а гнаться за частотой экрана
  (120 / 144 Гц) — значит держать DRS на полу постоянно; 60 — частота порта по умолчанию. 90 / 120 добавляются в варианты цели строки
  только когда это лимит (или явный выбор игрока), иначе строка как раньше — 30 / 45 / 60.
- **Строка DRS — переопределение для каждого режима отдельно.** Prefs `dos2_drs_dk` / `dos2_drs_hh` (-1 = умолчание режима, 0 выкл,
  1 вкл) и `dos2_drs_fps_dk` / `dos2_drs_fps_hh` (0 = цель по умолчанию, иначе fps). Строка показывает и правит режим, выбранный в
  строке режима выше (переключение радиокнопки режима в том же окне перерисовывает строку DRS, правки другого режима сохраняются).
  Выбор, равный умолчанию режима, хранится как «умолчание» — он и дальше следует за режимом и лимитом кадров. Явный выбор игрока
  (отличный от умолчания) побеждает в своём режиме.
  Почему по режиму, а не одна глобальная галочка: иначе смена цели в Handheld (45 вместо 60) включала бы DRS и в Docked.
- **Миграция старой строки** (`dos2_drs`, `dos2_drs_fps`): «вкл.» там был выбором игрока (умолчание было выкл.) → вкл. с его целью в обоих
  режимах; «выкл.» было лишь старым умолчанием (каждый Save шестерёнки писал его) → Handheld получает новое умолчание (вкл.), Docked — выкл.
- **Когда применяется — как режим:** старт — по режиму, в котором игра стартует (pref `handheld`; строка режима в шестерёнке = следующий
  запуск); Save шестерёнки — живьём для режима, в котором идёт игра (`after()` → `dos2DrsLive`, `a.startedHandheld`); переключение
  режима из меню паузы — живьём DRS нового режима (`DmActivity.setDocked` → `Tl2Gear.dos2DrsLive`). Живая цель по умолчанию берётся
  от лимита кадров, с которым игра стартовала (`dos2RunFps`; лимит кадров меняется только при запуске). `dm/env` по-прежнему побеждает.
- Строка в логе на старте и на каждое живое применение: `[java] dynamic resolution at start, handheld: DRS on, floor 75 %, target 60 fps`,
  `[java] dynamic resolution docked: DRS off (full window) (pause menu mode switch), live` (или `, not live: next launch`).

`DmActivity.java`: одна строка в `setDocked` (только DOS2).

Строки (EN + RU; строки DOS2 в шестерёнке — ресурсы порта, не `GearText`, других языков у них нет): `dos2_mode_handheld`
(подпись «В руках: WxH, с динамическим разрешением (легче для GPU)»), `dos2_drs_for_docked`, `dos2_drs_for_handheld`, `dos2_drs_mode_note`.

## Что видит игрок
- Шестерёнка, строка режима: «В доке: 2400×1080» / «В руках: 1920×864, с динамическим разрешением (легче для GPU)».
- Ниже, секция DRS: заголовок «Динамическое разрешение в режиме «В руках» (по умолчанию включено, 3D не ниже 75 % разрешения)» или
  «…в режиме «В доке» (по умолчанию выключено: всегда полное разрешение)», галочка, цель fps, пояснение «У каждого режима своя
  настройка…». Переключил радиокнопку режима — секция DRS сразу показывает другой режим.
- В игре: Docked — как сейчас (полное окно). Handheld — окно handheld и DRS игры между 75 и 100 % по GPU-времени; переключение
  из меню паузы меняет и DRS, без перезапуска.

## Риски
- Игрок, у которого Handheld уже был выбран и старая галочка DRS была выкл. (= старое умолчание), после обновления получит DRS в Handheld —
  это и есть решение хозяина; вернуть — снять галочку в режиме «В руках».
- Цель 90 / 120 в Handheld при таком лимите на слабом GPU держит DRS у пола 75 % — ожидаемо (лёгкий режим ради fps). Без лимита — цель 60.
- В Handheld при 720p окно handheld = окну дока (так в `hle_dos2_wide.c`), «легче» только за счёт DRS — подпись это и говорит.
- Если `dm/env` задаёт `DM_DOS2_DRS=skip`, живое переключение невозможно (как и раньше) — в логе `not live: next launch`.

## Прогон на телефоне, который это подтвердит
Без переменных в `dm/env`. Палуба / стартовая зона, 60 fps.
1. Шестерёнка → «В руках», Save, перезапуск. В логе: `[java] dynamic resolution at start, handheld: DRS on, floor 75 %, target 60 fps`,
   `[quality] DM_DOS2_DRS=75:100: DRS min 75.00 % of the window`, `[quality] DM_DOS2_DRS_TARGET_MS=15.83: target 15.83 ms`,
   `[quality] DRS size: max …, min …` (min = 75 % max) и раз в 10 с `[quality] GPU frame time (10 s): … DRS current … %`.
2. Меню паузы → режим «В доке»: `[java] Switch mode -> docked`, `[java] dynamic resolution docked: DRS off (full window) (pause menu mode
   switch), live`, `[quality] live DRS off: target 100.00 ms`; через ~10 с `DRS current … = 100.0 %`.
3. Обратно «В руках» из меню паузы: `… handheld: DRS on, floor 75 %, target 60 fps (pause menu mode switch), live`, `live DRS on: target 15.83 ms`.
4. В «В руках» снять галочку DRS, Save: `… handheld: DRS off (full window) (gear), live`; перезапуск — `DM_DOS2_DRS=off` в логе.
5. Шестерёнка: переключить радиокнопку режима — заголовок и галочка секции DRS меняются (Docked: выкл., Handheld: вкл.).
