# NR-LIGHTFUSE `DM_NR_LIGHTFUSE` — DeferredSky → ClusteredLightingWithSSAO одним draw (N1, раунд 2, ночь 19.11)

Ветка `dos2-nshader` (после слияния `dos2-night1119` ad71a70). Телефона не было: доказательство — интерпретатор и офлайн-компиляторы
(`tools/tu_stats` Adreno 750, `malioc`), сборка APK. **Умолчание 0 на всех семействах.**

## 1. Зачем (NR-NSHADER.md §6)
На Mi 14 (`TU_DEBUG=sysmem`) оба прохода полноэкранные и упираются в полосу: Sky читает G0 / глубину / нормаль / базу и пишет Sp + Df (2 × R11G11B10F),
Light читает те же G0 / нормаль / глубину / базу ещё раз, читает Sp обратно и смешивает (ONE, ONE) в Df. Слитый draw читает G-buffer один раз,
Sp вообще не ходит через память, Sky ничего не пишет.

### Проверки у draw Light (все — и в `=2`)
роль Light после тайника Sky этой же подачи; бандл ClusteredLightingWithSSAO, только VS + FS, без discard / alpha test / a2c; одна цель = Df Sky, без
глубины; цвет 0 — ONE, ONE, ADD, RGB пишутся; VS — бандл, байт в байт равный VS Sky (у игрока `849fbebaf82aeff3` и `fc568237692ece31` одинаковы),
те же байты его c-буферов (первые 1 КБ) и вершинных потоков (256 Б × 4), тот же диапазон draw, viewport, scissor (луч вида в каждом пикселе — Sky);
те же пулы текстур / сэмплеров.

### Решения (nr_lightfuse.h)
- `=1 / 3`: Sky пропускается (discard) только **после** цепочки, где draw Light прошёл все проверки (выучено), и когда оба двойника есть. Первая
  цепочка сессии — как записано (учёба).
- Sky пропущен, Light прошёл проверки → слитый draw. Sky пропущен, проверка Light не прошла → рисуется записанный Light (в этом кадре нет
  рассеянного IBL Sky: «lost», красная строка), учёба заново. Пропущенный Sky без Light до следующего Sky → тоже «lost».
- `=2`: всё проверяется и строится (двойники, модуль), ничего не меняется, счёт «would fuse».
- `=3`: как 1 + Sp перед слитым проходом заливается пурпурным (в слитой цепочке его никто не читает; если кто-то позже читает Sp Sky — пурпур).

### Взаимодействия (в логе при старте)
- **NR-ONCHIP**: при `DM_NR_LIGHTFUSE != 0` бэкенд onchip выключен (`[nr] onchip DM_NR_ONCHIP=N is superseded by DM_NR_LIGHTFUSE=M ...`), метки
  передний план ставит дальше (публикуется режим `max(onchip, 1)`).
- **NR-GMEM** (`DM_GFX_PASS_GMEM`): проходы слитой цепочки остаются sysmem (`pgm::note_lightfuse`, причина «other»; счёт в строке lightfuse).
- Прогрев: ключи `#lfd` / `#lf` прогрев не строит (как `#oc2` у onchip) — оба пайплайна собираются в кадре один раз за сессию.

### Строки
`[nr] lightfuse DM_NR_LIGHTFUSE=N (...)` (старт), `[nr] lightfuse <sky> -> <sky>#lfd`, `[nr] lightfuse fused module for ...`, `[nr] lightfuse <light> ->
<light>#lf (... bindings)`, `[nr] lightfuse vertex shaders A / B: bundles equal`, раз в 10 с: `[nr] lightfuse DM_NR_LIGHTFUSE=N: a frame: Sky draws,
Light draws, checked chains / passed, Sky skipped, fused Light draws; learned; lost; refused: <причины>; passes kept sysmem; poison; red lines`.

## 3. Доказательство (`python tools/dos2_lightfuse.py --bundles <shaders-vk> --n 400`)
Генераторы `tools/dos2_light_mobile.py` (G-buffer со всеми моделями, небо, 48 светов + кластеры, фиксированные сценарии), Sky читает тот же
G-buffer; масштаб рендера 1 (значение хоста). Цепочка в интерпретаторе: нативный Sky → `q11` → нативный Light (tAmbient = q11(spec)) → блендер
`q11(q11(diff) + light)`.
**400 / 400: выход слитого шейдера до записи бит в бит = `q11(diff) + light` цепочки; после записи (RNE) 400 / 400; отрицательный контроль (цепочка
без округления Sp) отличается в 303 из 303 освещённых.** Исполнено на пиксель: Sky 179 + Light 516 → слитый 745.
Граница: Vulkan оставляет режим округления записи R11G11B10F реализации; если GPU округляет иначе (к нулю), пиксель может отличаться на одну
ступень формата (6 / 5 бит мантиссы, ≤ 1.6 % / 3.1 % значения) — слитый тогда точнее цепочки; блендер цепочки тоже мог считать не в fp32.

## 9. Раунд 3: DeferredFog внутрь слитого draw (`DM_NR_LIGHTFUSE_FOG`, 19.11) + пак-варианты необязательные
**Цепочка в кадре** (дампы ra1 / rb1 / rc1, 34 / 34 кадра): Light пишет Df → Fog читает Df + линейную глубину, пишет C (это G-buffer c0 = эмиссия,
которую Light только что читал; перед Fog его чистят) → FadeBlending читает C (2×2 соседей в полосе фейда), пишет Df → … → копия Df → C. **Во всех
34 кадрах единственный читатель C до его следующей записи — FadeBlending**, операций, читающих C, нет (скрипт по дампам, §9 ниже).
Поэтому слить Fog «в лоб» нельзя: писать C в draw, который читает C как эмиссию, — петля обратной связи; писать туман в Df нельзя — Fade читает C и
пишет Df. **Решение без потерь:** слитый draw пишет туман вторым выходом в **Sp** (в слитой цепочке Sp никто не читает, формат / размер те же —
проверяется), draw Fog пропускается (его проход не начинается), а draw, которые до следующей записи C сэмплируют C, сэмплируют Sp (тот же пул, тот же
сэмплер; окно закрывается записью C — копия / очистка / C как цель — и концом подачи).
| Часть | Что |
|---|---|
| Шейдер | `-DLIGHTFUSE -DLFFOG` (`lightfuse_sky.glsl` `lf_fog`): быстрый путь `DeferredFog_mobile.frag` операция в операцию над `c = (q11(Df), 1)` (тексель Df, который прочёл бы Fog), та же глубина, тот же луч; c16[4..6] / c15[12] — банки Light. Пак-вариант `g.ClusteredLightingWithSSAO` |
| Доказательство | `dos2_lightfuse.py`: выход 1 == нативный DeferredFog над записанным Df **400 / 400 бит в бит**; контроль (Fog над неокруглённым Df) отличается в 335 / 400; слитая часть (выход 0) 400 / 400 как в §3 |
| Хост | `DM_NR_LIGHTFUSE_FOG` 0 (умолч.) / 2 проверка / 1 (нужен `DM_NR_LIGHTFUSE` 1 / 3). У draw Light (прошёл проверки) запоминается, что видит Light: образ глубины, Sp и его дескриптор, байты c16[4..6], c15[12]. У draw Fog проверки: форма — отдельный счётчик на каждое условие (стадии VS + FS; одна цель без глубины; без бленда; маска: R G B пишутся, A — если у цели есть альфа, `nr_lf_fog_mask_ok`; привязки 16 / 10 / 22 / 28), цель C того же формата / размера, что Sp, читает Df Light, глубина та же, байты c16[4..6] / c15[12] те же, тот же VS-бандл / константы / вершины / диапазон / viewport / scissor, тот же пул. Учёба: Fog прошёл проверки → со следующей цепочки слитый Light пишет [Df, Sp] (MRT: цель 1 = Sp без бленда, `state.rt` / бленд / маска на один draw, Guard возвращает) и Fog пропускается. **Провал проверки после слитого Light — Fog рисуется как записан (точно: Df хранит результат Light)**, учёба заново. `=3`: при пропуске C заливается пурпурным (читатель мимо окна виден) |
| Пак / setup | `LF_VARIANTS = 'fg'`, **оба необязательные**: не собрался / не доказался — вариант не кладётся (строка в equivalence.txt), setup принимает пак с ними и без (проверено: полный 28, без f./g./5. — 24, без g. — 27 бандлов: PASS). Хост без варианта — красная строка и обычные проходы |
| Цена | Adreno 750: `g` 1812 слотов против `f` 1666 + Fog 111 (+35: q11 текселя Df); G57 21.38 против 19.75 + 1.25 |
**Ожидание Mi 14 [м]:** снимается проход Fog: чтение Df 4 + глубины 2 + запись C 4 Б/пикс, слитый пишет Sp 4 → −6 Б/пикс ≈ −12.6 МБ ≈ −0.15 мс + пол
прохода ≈ −0.05 → **−0.15…0.25 мс** поверх §5 (Fog 0.28 мс в Форте). Слабые Adreno ×2–3; Mali / PowerVR: тайловые load / store прохода Fog.
**Телефон 19.11 (N_lf2 / N_lf3): каждый Fog отказан «Fog shape».** Причина — маска записи: игра рисует DeferredFog только в R G B (маска 7)
в цель B10G11R11_UFLOAT (VkFormat 122, альфы нет) — видно в списке конвейеров `play-1118/vk-pipeline-list.bin` (запись `d0136477…+d8aeec64…`:
бленд выкл., глубины нет, `colorWriteMask` 7). Модель предполагала RGBA (15); проверка Light уже принимала `(mask & 7) == 7`. Остальное у Fog
совпадает с моделью (VS-бандл `d0136477…` байт в байт равен Sky / Light, привязки 16 / 10 / 22 / 28, цель 2160×972 формат 122 как Sp).
Исправление (ветка `dos2-fogfix`): R G B без A принимается, только если у цели нет альфы (`nr_lf_vk_no_alpha`), выход 1 слитого Light пишет Sp
с выученной маской Fog (тот же формат → те же тексели); проверка формы разбита на счётчики (стадии / цели / бленд / маска / привязки), раз за
запуск строка `[nr] lightfuse fog: first Fog draw: … write mask …`.
**Прогоны:** `DM_NR_LIGHTFUSE=1 DM_NR_LIGHTFUSE_FOG=2` (строка `[nr] lightfuse fog`: passed ≈ 1 / кадр, refused none) → `=1 FOG=1` с `DM_NR_LIGHTFUSE=3`
(пурпура нет, «Fog skipped ≈ 1», «draws redirected to Sp» ≈ 1 / кадр — FadeBlending) → ABBA `FOG=0 / 1` (GPASS Fog-прохода нет, `gpu_ms`).
**Не сделано (раунд 3):** EoCFog в F1A — тот же приём возможен (туман в свободную цель того же формата — цель выброшенного прохода LUT — и
перенаправление читателей цели EoCFog), но он сплетается с перенаправлениями маршрута A NB-18b (`la` / `al`, carry-проходы) — отдельный шаг,
оценка −0.15…0.2 мс; Bloom-мипы и проход Sky без начала (нужен план NB) — не начаты.
