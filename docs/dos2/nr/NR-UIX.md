| 3. | 2. Разрывы | `DM_NR_UIX_RB` | только счёт: разрывы по чтению → следующий проход та же цель (`same`) или другая; любые повторные начала только что закрытой цели — по строке исходника, которая её закрыла (`end_open_pass(line)`) |
| 4. UI-кэш | `DM_NR_UIX_CACHE` | только счёт: хэш потока UI кадра (проходы Iggy: шейдеры, состояние POD от `attrib` до `bounds`, привязки текстур, байты вершин / индексов диапазона draw, байты UBO VS / FS, текстуры + поколение содержимого; текстуры, записанные проходом Iggy этого кадра, — только идентичность), сравнение с прошлым кадром: strict и loose (текстуры, которые рисуют другие проходы — портреты, — считаются неизменными: сколько дал бы кэш с отдельным слоем портретов) |
| 5. UI в меньшем разрешении | — | не сделано (решает хозяин), §6 |

### Значения

| | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| `DM_NR_UIX_DS` | ничего | detach по `hist2` | решает старая история, новая считается: would detach / would miss / kept | стресс: каждый проход Iggy без DS, draw с DS → re-attach (картинка должна быть та же — проверка пути re-attach) |

Все части требуют `DM_NB_UIAREA` (в DOS2 по умолчанию 1): они расширяют его учёт проходов. Строки раз в 10 с:
`[nr] uix ds DM_NR_UIX_DS=…`, `[nr] uix area …`, `[nr] uix rb …`, `[nr] uix cache …` + старая `[nb] uiarea …` (applied: DS detached,
smaller area, restarts, DS re-attached). Старт: `[nr] uix (NR-UIX): DM_NR_UIX_DS=… …`.

## 2. Почему корректно

- **DS.** Проход без DS — отдельный render pass + framebuffer + варианты конвейеров (NB-18b-6, ≈10 штук, кэш). Пока DS отцеплен, его никто
  не пишет и не читает; draw, которому DS нужен (depth / stencil / bounds test), получает проход с DS (хост закрывает без-DS и начинает с
  DS и LOAD). Ошибка предсказания стоит одного лишнего store + load цвета, не картинки. Новое — только какой проход отцепить.
- **Область.** Vulkan не трогает вложения вне `renderArea`: для LOAD / STORE это то же, для DONT_CARE — подмножество разрешённого. CLEAR-load
  в `nbrp_begin` не бывает (`nb_rp_twin(&dn,0,…)`: план чистит до прохода или clear-путём); `vkCmdClearAttachments` вне области — перезапуск
  (`before_clear`). Коробка консервативна: floor/ceil + 1 px (линии 4 px, точки и прочее — без коробки), вершина с w ≤ 0 / NaN → без коробки,
  UBO под сдвигом UI хоста или с ещё не вернувшимся результатом GPU → без коробки, GPU-indirect → без коробки, draw не Iggy → viewport ∩ scissor.
  Программа позиции — та же, что NR-10b сверял с `spv_interp` по всему паку (`nr_cover_census.py`). Перезапуск: STORE в области, новый
  begin с полной областью и LOAD. С ядовитыми режимами (`STORE_HIST=3`, `DM_NB_RP=3`, `DM_NR_RP=3`) область не ставится.
- **0 байт в байт**: каждый крючок — `if(uix::…_mode)`; в `uiarea` при `DS=AREA=0` — та же история, тот же счёт кадров
  (`frame_sync` = прежние три присваивания), `nbrp_begin` не меняет `t.mask`; `first0 / prim0` — только копии.

## 5. Части 2 и 4: решение по цифрам (не построено)

- **Разрывы / feedback loop.** По логу why=6 — это вклейки фильтров и цепочки мипов, читающие результат *прошлого* прохода другой цели:
  проход закрывается и без чтения. `VK_EXT_attachment_feedback_loop_layout` сократил бы только проходы `same` (чтение своей цели), и то лишь для
  чтений в той же точке (размытие читает соседей — feedback loop для него запрещён). Строить — если `[nr] uix rb` покажет `same` ≥ 5 / кадр.
  То же для слияния подряд идущих проходов одной цели: хост уже продолжает пустые переключения RT (NB-05b `cont`); строка покажет, какие
  строки `end_open_pass` ещё рвут ту же цель (ожидаю: перезапуски uiarea, загрузки текстур в проходе, запросы окклюзии).
- **UI-кэш.** Сначала `DM_NR_UIX_CACHE=2`. Если `strict` ≥ 30 % кадров исследования — строить (пропуск всех проходов Iggy кадра, #57/#58 из
  прошлого кадра; выигрыш до 1.4–1.7 мс GPU + 0.4 CombineUI не входит, + 2–3 мс CPU потока трансляции). Если высок только `loose` — сначала
  отделить портреты (они перерисовываются каждый кадр). Ограничение счёта: clear внутри проходов UI в хэш не входят; draw, обслуженные
  полосой NR-12 (`DM_NR_UI`, по умолчанию выкл.), не хэшируются.

## 6. Часть 5: UI в меньшем внутреннем разрешении (решает хозяин)

Слой UI = размер окна (2400x1080), `CombineUI_NoFetch` читает его `texelFetch` 1:1 (NB-18a §2). Меньший слой требует: размер окна для Iggy
в HLE (только для UI-целей), масштаб viewport / scissor Iggy, вариант Combine с билинейной выборкой. Выигрыш на тайлере ≈ доля пикселей
главного прохода p21 и Combine (0.81× при 2160x972: ≈ −0.1 мс Combine на Adreno, больше на Mali), фильтр-проходы уже снимает `AREA`;
цена — мягкий текст. Оценка: 4–8 ч агента + прогоны. Рекомендация: не делать, пока `DS + AREA` не измерены на Mali.
