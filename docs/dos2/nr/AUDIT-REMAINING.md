# DOS2: что осталось вне NR-01…13 и NB — аудит пути кадра и загрузки (17.11.2026, ветка `dos2-nraudit`)

Только аудит: код не менялся, телефон не трогался. База `dos2` 94d287d + ветки NR (nr02…nr11, документы `docs/dos2/nr/NR-*.md` на ветках,
`nr-status.md`). Цель хозяина: заменить слой NVN и слой трансляции нативным Android / Vulkan **там, где это даёт выигрыш**, для Mi 14 и
особенно для слабых (Snapdragon 7, Mali, PowerVR). Всё, что уже покрыто NR-01…13 / NB-01…22, здесь не повторяется; добавлено только то,
чего в планах нет, плюс то, что NR/NB сделали лишним.

## 3. Не делать (потеря или нет выигрыша — с числами)
| Вариант | Почему |
|---|---|
| Свой аудио-рендерер / правки audren | 0.05 мс средн., catch-up только на старте (rd1) |
| ФС на кадре, WriteTexels, ввод | `[stall]` 0, `waited 0.0 ms`, опросы ввода ~120 / с |
| Выбросить пре-пасс / гибрид `DM_DOS2_PREPASS=1` / перестановка ради LRZ | пре-пасс не зависит от разрешения (m7 = m9), `nolrz` ничего не меняет (m5): цена в draw и штампах — их снимают NR-14 / NR-21 |
| Варианты теней `DM_DOS2_SHADOWS=0/2` как рычаг | c4sh0 / c5sh2 против c0base — в шуме (8.66 / 8.40 против 8.50 мс) |
| Нативная подача на потоке игры (шаг 5 `NATIVE_PLAN`, один поток вместо двух) и параллельная запись списков (шаг 6) | Mi 14 и слабые GPU упираются в GPU; второй поток бесплатен; secondary CB / MX уже отвергнуты (NB-20b, PERF-E18) |
| HLE-замена `memcpy` / LZ4 / zlib / аллокатора игры «на глаз» | LZ4 не векторизуется, `memcpy` SDK уже под aarch64, куча гостя в его адресах — высокий риск; только если `simpleperf` NR-16 покажет ≥ 10 % в одном листе |
| `DM_GFX_SPV_OPT=1` на телефоне | компиляция на CPU игрока при каждой новой стадии; если брать — в setup (NR-25) |
| Перенос RomFS в `Android/data` | правило хозяина: игровые файлы на телефон больше не заливаем; ФС в кадре не стоит ничего (только загрузки — смотреть `DM_FS_STATS` в NR-16) |
| `DM_GFX_COND_RENDER=2/3/4` как путь | заменён NR-03; режим 4 включает счёт сэмплов на всех draw (меряет не ту сцену), режим 3 судит чужой объект (адрес пары каждый кадр другой) |
| Кэширование портретов 80x100 / цепочек яркости | логика игры, 0.1–0.3 мс на 750 |
| Убрать учёт объектов NVN (Create* / Initialize) | только загрузка, движок всё равно их зовёт; в кадре 0 |
| Present thread выкл. / свои правки пейсинга | NR-11: регресса нет, это фаза 90 Гц |

## 4. Вне NR, но главный рычаг слабых GPU (для решения хозяина, не шаг NR)
- **Разрешение 3D.** ≈ 65 % GPU пропорционально площади 3D (`GPU_BREAKDOWN.md`); после NB-18b-11 регулятор DRS игры работает, но
  `DM_DOS2_DRS_TARGET_MS=100` = выключен. На S7 / Mali (≈ 36–48 мс на 100 % [м]) бюджет 33.3 мс с минимумом 75 % дал бы больше, чем все
  шаги этой таблицы вместе. Это решение о качестве («docked-вид», правило хозяина), а не замена слоя.
- `DM_DOS2_PARTICLES_FULL=1` на слабых в бою: +1…3 мс GPU [`GPU_BREAKDOWN` §3] — политика по семейству после `gp2`-прогона в бою.

## 5. Один сеанс прогонов для NR-14…19 (главный агент, по разрешению хозяина)
Бэкап `files/save`, проверить keyguard (`dumpsys window`), палуба + 1 тяжёлая сцена (бой / город), без лимита кадров, force-stop после логов.
1. ABBA ×2, по 60 с: `DM_GFX_SAMPLES_TS=1` (база) ↔ `=0` ↔ `=4`. Смотреть `NVN PERF v= gpu_ms`, `samplets … stamps=`, GPASS пре-пасса
   (`DM_GFX_PASS_PROF=300,180,0 DM_GFX_PASS_VALUES=0` отдельным прогоном), картинку (скриншоты одной точки).
2. ABBA: умолчания ↔ `DM_NB_RELOC=0 DM_NB_ORDER=0 DM_NB_TRANSIENT=0 DM_GFX_HIT_FAST=0`. Смотреть `[nvn] 主线程 … 每帧 CPU`, `[nb] own … valid`,
   `[nb] post … elided`, `[nb] rp … plan applied`, скриншоты.
3. Один прогон замера: `DM_NVN_PROF=1 DM_SLEEPSTAT=1` (+ новые счётчики NR-16) — `[nvn] 翻译层耗时前 5`, строки ворот / потоков;
   параллельно `simpleperf record -g -p <pid> --duration 20`; `dumpsys SurfaceFlinger` (тип композиции слоя игры) для NR-20.
4. `DM_GFX_SIM_GPU=mali` (NR-18 картинка ASTC-кэша) и `DM_GFX_SIM_GPU=powervr` (NR-19: нет «взрывов» геометрии).
