# NR-33C `DM_NR_SH_SURF` — поверхностные материалы (лужи / кровь / масло / яд / огонь / тени облаков / дождь): ранний выход целой волной

Ветка `dos2-nr33c` (worktree `wt-nr33c`, база `dos2-nr-all` 75e2179). Телефон не трогался (adb не запускался). **По умолчанию 0 — поведение
байт в байт прежнее** (одна проверка целого на загрузку шейдера и на draw). Области других агентов (nrcpu / nrtile / nrui) не затронуты.

## 1. Что на самом деле дорого (разбор SPIR-V игрока, play-1118, Форт)

Проход forward-поверхностей 2160x972 fmt 122, 2 вложения — 2.84 мс выборочного кадра; по модели heat (время прохода × доля статической
цены) в нём: Fire_Ground 0.63, FlowingWater 0.53, Oil 0.30, CloudShadow 0.21, Rain 0.08 мс (+ DeferredSky 0.55 — не поверхность).
Blood_ST_DEF 0.52 и Poison_ST_DEF 0.19 мс — **в G-buffer-проходе** (5 вложений), не в forward. Ocean_infinite 0.016, Particles_Emissive_02
0.019 мс — в Форте не стоят ничего.

Цена по `malioc` 2026.5 (FS после `spirv-opt -O` + телефонная цепочка загрузки NAN_MINMAX / LDC_FOLD / TEMPS / LDC_CANON / F2I / UBOVEC,

Вывод разбора:
- **Подчистка ничего не даст** (NR-32: −0…1 % на этих материалах). Проверил и fp16: `RelaxedPrecision` на всей «только цветовой» арифметике
  (всё, что не кормит координаты выборок, условия, индексы и alpha) — **0 циклов** на G57 / G715 (`malioc` 16 % арифметики в fp16, bound
  тот же: цветовая часть скаляризована и перемешана с highp-освещением, конверсии съедают выигрыш). Уровень «fp16» — снят по цифрам.
- **Настоящая цена — работа, которую никто не видит.** Это декали-коробки поверх земли: фрагменты вне коробки / на склоне / вне клеток
  поверхности убиваются kill в первых 10–25 % кода. Но **kill не останавливает волну**: Turnip (`ir3_legalize.c kill_sched`: «kill doesn't
  actually kill the thread», убитые линии идут дальше как helper, прыжок в конец ставится только в циклах), Mali / PowerVR — только если
  мертва вся quad / warp и компилятор сам поставил проверку. Каждая убитая линия платит остальные 75–90 % шейдера. Плюс в forward-шейдерах
  alpha цвета 0 часто ровно 0 (`FClamp` / `FMax(0, …)` покрытия сетки и мягкого края по глубине) — смешивание SRC_ALPHA / ONE_MINUS_SRC_ALPHA
  оставляет пиксель как был, а шейдер считает всё освещение.
- Значит менять надо **алгоритм исполнения**, а не текст: волна, в которой ни одна линия ничего не запишет, не должна исполнять остаток.

## 2. Что сделано

После последнего kill каждой «кучки» верхнеуровневых kill (и/или после того, как известна alpha цвета 0) в структуру модуля вставляется:
```
live = !(все верхнеуровневые условия kill до этой точки) [&& !(alpha мертва)]
if (subgroupAny(live)) { остаток шейдера — без изменений } else { kill }
```
Ветвление равномерно в подгруппе (волне), поэтому производные / implicit-LOD выборки внутри видят те же quad, что и раньше; живые линии
исполняют **ровно те же инструкции** транслятора. Для точки alpha срез вычисления alpha (чистые инструкции: входы, uniform, выборки)
поднимается к точке ветвления — тот же код в том же порядке, только раньше (выборки остаются в равномерном потоке управления).
Никакого GLSL игры, никакого кода игры в git / APK: инструмент преобразует **SPIR-V игрока у него на ПК** по структуре.

### Когда вариант точен
- **k** — всегда: пропускается только волна, где каждая линия уже убита kill транслятора (или helper). Ничего не пишется ни там, ни там.
- **a** — для draw, у которого (гейт `nr_surf_alpha_gate`): цвет 0 смешивается SRC_ALPHA × src + (ONE_MINUS_SRC_ALPHA | ONE) × dst, ADD;
  alpha — dst × (ONE | ONE_MINUS_SRC_ALPHA), ADD; другие включённые вложения шейдер не пишет; нет записи глубины / трафарета; нет
  счёта сэмплов (occlusion query — фрагмент с alpha 0 в игре проходит тест глубины); нет alpha to coverage / logic op; NVN alpha test
  выключен (иначе — шейдер игры). Тогда фрагмент с alpha ±0 оставляет всё как было. Отличие от игры — только где игра смешала бы
  inf / NaN цвет с alpha 0 (там NaN, у нас старый пиксель). Гейт не выполнен → k.
- **m** — тот же гейт; не рисуется край с alpha < 1/255: разница на пиксель < (1/255)·|src − dst| (ниже одной ступени RGBA8 до тонмаппинга;
  в HDR-цели — до ~1/255 яркости источника). Это видимый (в принципе) допуск — решение хозяина.
- Требование к устройству: subgroup vote во фрагментных шейдерах (`VkPhysicalDeviceSubgroupProperties`); без него — выключено с красной
  строкой (иначе хост дал бы lone-lane форму, и ветвление перестало бы быть равномерным).

## 3. Переключатель
`DM_NR_SH_SURF` **0** (по умолчанию) — ничего. **1** — точно: `a`, где гейт выполнен, иначе `k`. **2** — мобильный: `m` / `k`.
**3** — яд: `p` / `k` (пропущенные волны с мёртвой alpha — пурпурные: видно, где ранний выход срабатывает). **4** — проверка: все решения
считаются (`would swap`), рисуются шейдеры игры. (Брифовое «2 = check» здесь занято мобильным уровнем по постановке задачи — проверка = 4.)
Строки: `[nr] surf DM_NR_SH_SURF=…` (старт, размер подгруппы), `[nr] surf <shaders>/native-nr33c.xgspack: N bundles`, первые 4
`<key>: variants k a m p`, первые 4 `<key> -> <key>#s<v>`, сводка раз в 10 с: `draws of surface shaders S: swapped N (k, a, m, p), kept:
NVN alpha test, variant missing; alpha gate refused by blend / another written attachment / depth write / stencil write / alpha to coverage /
logic op / sample counting; twins; red lines`. Красные `【红】[nr] surf …` (первые 16): нет пака, запись для другого SPIR-V / битая, вариант
не от этого бандла (голова), модуль не создан, нет subgroup vote.

## 6. Ожидаемый выигрыш [оценка — главное неизвестное: доля мёртвых волн в кадре]
Выигрыш = доля f работы этих шейдеров, пришедшаяся на волны без живых линий, × ~0.9. Модель heat: перечисленные FOR ≈ 1.74 мс + DEF ≈ 0.71 мс
выборочного кадра Mi 14 ⇒ **≈ f × 2.2 мс GPU**. Коробки декалей на изометрии закрывают и землю вне поверхности (5-й kill — «в 4 соседних
клетках нет этой поверхности»), alpha = 0 у краёв.
- **Mi 14 / Adreno 750 (Turnip, волна 64 / 128 пикселей):** нужна целая мёртвая волна, f ≈ 0.15–0.4 ⇒ **−0.3…−0.9 мс** в тяжёлых окнах
  Форта (из 17–21). Живые волны: +0 (Adreno сам сливает ветвление; на G715 видно +2–4 %, на G57 CloudShadow +12 %).
- **Mali (Valhall, warp 16):** мёртвые warp чаще, f ≈ 0.25–0.5; те же шейдеры дороже ×6–10 (G57 MC2–MC3 / G68) ⇒ **порядка −2…−8 мс** на
  классе G57 / G610 в окнах с лужами / огнём / кровью; G715 / G720 — ≈ −0.5…−1.5 мс. Точка безубыточности CloudShadow на G57: f ≈ 13 %.
- **PowerVR / Xclipse:** механизм тот же (волна 32 / 64), выигрыш между Adreno и Mali; PowerVR-подгруппы vote в FS — проверяется на старте
  (иначе выкл).
- **Слабый CPU:** +1 чтение состояния смешивания на draw поверхности (~200 / кадр, < 0.02 мс); первый draw каждой пары (шейдер, проход) —
  сборка пайплайна близнеца в кадре (дальше прогрев знает `#s<v>`).

## 7. Риски и чего нет
- Пиксели на GPU не сравнивались; доказательство — семантика SPIR-V (интерпретатор) + правила Vulkan про равномерное по подгруппе ветвление.
  Если драйвер не следует «helper»-семантике kill для производных у краёв (как не следовал бы и для игры) — вид совпадает с игрой, т. к.
  живые quad исполняют тот же код.
- Неизвестна доля мёртвых волн → выигрыш может оказаться ≈ 0 на Adreno (волна 128) и быть заметным только на Mali. Режим 3 и A/B ниже
  отвечают на это за один прогон.
- `_DEF_NX` без alpha-точки (каждое вложение со своей alpha); Ocean / Emissive_02 без k (нет kill). fp16 и «меньше выборок» — не сделаны
  (§1, §5). Пак ≈ 10 МБ (386 вариантов; можно сузить списком программ Форта, если хозяину важен размер).
- `tools/spv_interp.py` изменён → хэш инструментов NR-04 / NR-33B / NB-18 паков другой: setup один раз пересоберёт их (байты те же).
- Общие файлы: `xbg_game.cpp` (+12 строк: include, поля Shader + деструктор, 2 объявления, 4 хука), `setup_dos2.py` (блоки `NR-33C`),
  `source_structure_test.py` (`nr33c_check`), `xbg_vendor_policy.h` (+1 функция), `spv_interp.py`.
