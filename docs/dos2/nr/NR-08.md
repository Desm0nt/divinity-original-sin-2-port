# NR-08 `DM_NR_DESC` — дескрипторы draw без ключа мемо, снапшотов блоков и пути чтения на каждый образ (сегмент S4), 17.11.2026

Ветка `dos2-nr08` (worktree `wt-nr08`): база `dos2-nr02` + слитые `dos2-nr05` и `dos2-nr06` (два merge-коммита, все их тесты проходят).
План: `NATIVE_RENDERER_PLAN.md` §2 S4, §3 строка NR-08. Основа: NR-02 (раскладка бандла, наборы текстур), NR-06 (кольцо констант одним
буфером: `nrbuf::ring_vk / ubo`), NB-11 / NB-12 (мемо дескрипторов, `hitfast`). **На телефоне не исполнялось.**

## 1. Где сидят 2.8–3.5 мс `desc` (логи Mi 14 Ultra, палуба / кампания)
- `g0base` (без NB, 1 159 draw): `desc_ns hit_total` 2.89–3.52 мс при `memo_hits = 1159.0, misses = 0` → **≈ 2.8 мкс на попадание**;
  `d1prof` (908 draw): `desc` 2.63–3.76 мс. Сборок наборов нет вовсе — стоит сам путь попадания.
- Из чего он состоит: ключ мемо (вектор ~20 слов + сравнение / хэш), `uniform_snapshot` на каждый динамический блок
  (`set_binds = 1007, offsets_per_bind = 7.7`), сортировка, `support_block()` (поиск в `std::map`), и на каждый образ записи —
  `get_image` + `prepare_read` со всеми хуками.
- NB-11 (`DM_NB_DESC=1`, по умолчанию вкл.) снимает только ключ и только у 51 % draw (`h1def`: reuse 531 912 из 1 036 709; «texture rebind»
  405 120). NB-12 `DM_NB_UBO` — 2.30 М из 5.84 М блоков. **`DM_GFX_HIT_FAST` в сборке по умолчанию не пропускает ничего**: `h1def`:
  `958464 memo hits, 4762053 images, skipped 0 … hook 4762053` — при включённом NB всегда «вооружён» хук чтения, и все 4.97 образа
  на draw идут полным путём.

## 2. Что сделано
Draw движка, чей набор шейдеров читает только блоки игры, support-блок, константы c1 и текстуры по слотам, обслуживается из **записи**
(`dm/gfx/vulkan/engine/xbg_nr_desc.inc`, решения — `dm/gfx/nr/nr_desc.{h,c}`, чистый C):

| Часть | Как |
|---|---|
| **Текстурная часть** («набор 1» плана) | ключ = (5 шейдеров, размер вьюпорта, пулы, хэндлы текстур / сэмплеров **только слотов, которые шейдеры читают**). Поиск: **по поколению** — тот же набор шейдеров, счётчики `tex_gen` его стадий, пулы и вьюпорт как на его прошлом draw → та же запись без ключа и хэша; иначе хэш слов + сравнение слов. Запись делается один раз **захватом старой сборки**: `descriptors_build` отрабатывает до конца и отдаёт свои `VkWriteDescriptorSet` вместо выделения набора — виды, сэмплеры, null-текстуры считает тот же код, что и раньше. Набор пишется один раз в собственный пул `nrdesc` |
| **Блоки** («набор 0» плана) | каждый блок игры = смещение в буфере кольца NR-06 (`nrbuf::ubo`: на месте через zero-copy или зеркало): **динамическое смещение**, набор не переписывается. Блок, который раскладка не смогла сделать динамическим, — слово **статического кортежа**: кортеж выбирает вариант набора (2 последних на запись), новый кортеж = один `vkUpdateDescriptorSetWithTemplate` в набор из **рециклера** |
| **Рециклер наборов** (`nr_dfifo`) | список наборов раскладки в порядке последней привязки; набор можно переписать, когда его последняя привязка ≥ 2 подач назад (правило двух слотов кадра, то же, что у зеркала NR-06). Раскладки без статических слов отдают только наборы записей, простаивающих ≥ 600 подач (или сброшенных) |
| **Хазарды** | `get_image` + `prepare_read` — только для образа, в который GPU когда-либо писал (RT, storage, цель копии: `gpu_written / last_write / storage_write / opw`), и для первого использования образа в подаче (проверка содержимого / проба NR-05 идёт как раньше). Материальная текстура, уже проверенная в этой подаче, — 5 чтений полей (`nr_dimg_skip`) |
| **Отказ** | по набору шейдеров навсегда: storage / image / driver-блоки / массивы / texel-буферы / превышение лимита устройства на стадию; по draw: блок вне кольца, «hold» зеркала, другой размер привязки, нет буфера кольца, ворота мемо (capture, provenance, UI-сдвиг, граф проходов) — старый `descriptors()` целиком, счётчик по причине. 64 промаха набора шейдеров подряд → 600 подач без попыток |

### Решения, которые просил шаг
1. **Два набора — логически, один `VkDescriptorSet` физически, на всех классах.** Второй физический набор добавил бы вызов: смещения меняются
   на 1 007 привязках кадра, текстурная часть — на 626 из них (`offsets_only = 381`) → 1 633 `vkCmdBindDescriptorSets` вместо 1 007 (+62 %;
   на Mali 1.2–1.8 мкс за `vkCmd*` = +0.75–1.1 мс), плюс перестановка `DescriptorSet` в SPIR-V и пересборка всех пайплайнов (прогрев
   14–24 с). Выигрыша нет: наборы и так пишутся один раз. Единственный класс, где физическое деление что-то даёт, — «без динамических
   UBO» (PowerVR): там переписывался бы только набор блоков, а не блоки + ~4 образа. Не сделано: это отдельные пайплайны для одного
   семейства без единого устройства для проверки; число записей (одна на draw) не меняется.
2. **Слово раскладки бандла (`xbg_shader_header.reserved`) NR-08 не нужно — пак и setup не тронуты.** Раскладка выводится на загрузке из
   таблицы привязок бандла (`nr_dplan_build` над `Shader::bindings`, те же 8 u32). Проверено на всех бандлах (`nr_desc_test` с каталогом):
   **6 130 из 6 130 пар VS + FS годны**, в среднем 3.8 текстуры и 4.4 блока, максимум 31 дескриптор / 20 текстур / 11 блоков.
3. **Поколение текстур — счётчики бэкенда, а не id наборов NR-02.** Id NR-02 считаются на потоке игры по id пула всех 64 слотов (в том
   числе тех, что шейдер не читает), не различают перерегистрацию id и до транслятора не доходят (нужно поле записи). Здесь ключ — хэндлы
   читаемых слотов на потоке трансляции, а «ничего не перепривязано» дают `tex_gen` (их двигает каждый писатель `state.tex / samp`,
   разбор NB-11). Для NR-09: id NR-02 может ехать в `OP_X_NR_DRAW` и стать передним ключом этой же таблицы; режим 2 тогда сверит его
   так же, как сейчас сверяет поколение с хэшем.
4. **Второй путь для > 8 динамических UBO** (`DM_NR_DESC_SPLIT`, вкл. с `DM_NR_DESC=1`): у 147 пар (2.4 %) 9–11 блоков игры. Старая
   раскладка для них на устройстве с лимитом 8 — режим 0 (всё статическое → мемо отказывает → **полная сборка на каждый draw**). Новый
   режим 3 `dyn_mode_for`: 8 блоков, чей адрес менялся чаще всего (счётчик по (стадия, слот) со всех уже обслуженных draw; при равенстве —
   меньший номер), остаются динамическими, 1–3 (19 / 118 / 10 пар) — статические слова. Набор такой записи переписывается раз на смену
   кортежа (покадровые блоки получают новый адрес раз в кадр), а не раз на draw. Раскладка у пары своя и постоянная; пайплайны этих пар
   собираются под неё (только с `DM_NR_DESC=1`, только на устройствах с лимитом < числа блоков).
5. **Лимиты устройства.** Раскладки по-прежнему делает старый путь; NR-08 их не меняет (кроме режима 3). Набор шейдеров, превышающий
   `maxPerStageDescriptorSamplers / SampledImages / UniformBuffers` или `maxDescriptorSetUniformBuffersDynamic`, NR-08 не берёт
   (`nr_dplan_limits`, причина `device limit`): у 18 пар во FS больше 16 текстур (минимум спецификации), по UBO на стадию > 12 — 0 пар.
   Сами лимиты на стадию движок раньше только печатал (`NVN caps limits`), не проверял — это осталось как было.

Классы устройств (все 6 130 пар, `nr_desc_test <shaders-vk> <programs.tsv>`):

| Устройство | все UBO динамические | динамические блоки игры (support / c1 статические) | деление (режим 3) | всё статическое | статических слов |
|---|---|---|---|---|---|
| 16 динамических (Adreno) | 6 130 | 0 | 0 | 0 | 0 |
| 8, старые раскладки (`SPLIT=0`) | 3 828 | 2 155 | 0 | 147 | 9–11 |
| 8 + деление (Mali / Xclipse) | 3 828 | 2 155 | 147 | 0 | 1–3 |
| без динамических (политика PowerVR) | 0 | 0 | 0 | 6 130 | 1–11, медиана 4–5 |

## 3. Переключатели (умолчание 0; игрокам не выдаются; нужны `DM_NR=1|2` и `DM_NR_BUF=1|3`)
| | значение |
|---|---|
| `DM_NR_DESC` | **0** — ничего: `descriptors()` платит одну загрузку и непринятый переход (`nrdesc::Scope`), `descriptors_build` и `dyn_mode_for` — по одной; ни таблиц, ни пулов. **1** — вкл. **2** — старый путь исполняется и рисует; запись ищется обоими способами (поколение = хэш), её раскладка, смещения и статический кортеж сравниваются с результатом старого пути; «ни одному образу не нужен путь чтения» сверяется с тем, что сделал старый путь (закрыл проход / записал барьер / тронул образ); каждый 8-й draw (`DM_NR_DESC_CMP`) собирается ещё раз захватом, и каждая запись набора (вид, сэмплер, буфер, смещение, диапазон) сравнивается с записью. Красные строки `【红】[nr] desc: …` (первые 16) + сводка. **3** — не существует: набор пишется целиком, травить нечего (красная строка, выкл.) |
| `DM_NR_DESC_SPLIT` | 1 (по `xbg_nr_desc_split_default`: там, где динамические UBO включены) / 0 — старые раскладки, каждый блок таких пар — статическое слово |
| `DM_NR_DESC_MAX` | записей (4 096; полная таблица сбрасывается) |
| `DM_NR_DESC_CMP` | режим 2: каждый N-й draw пересобирается (8) |
| `DM_GFX_SIM_GPU=…,ubdyn8` | новый токен симуляции: `maxDescriptorSetUniformBuffersDynamic = 8` (Mali / PowerVR / Xclipse); в профили `mali / powervr / xclipse` **не** входит (их прежние прогоны не меняются) |

Строки: `[nr] DM_NR_DESC=… (NR-08: …) … device: N dynamic uniform buffers a set, … -> …` на старте; раз в 10 с
`[nr] desc: DM_NR_DESC=…; D graphics draws, served S (entry by generation G, by hash H, made M, remade R); old path: gate …, shader set not
eligible … (type / source / driver / array / slot / rows / device limit), no ring buffer …, block unbound …, block size …, block not served by
the ring …, capture …, layout …, no set …, backing off …; images I: skipped K, read path: first in submission …, GPU-written …, layout …,
hook …; U ring blocks a draw; sets: reused …, written …, (new …); P shader sets (E eligible), N entries, … sets made / … recycled, flushes …;
checks C (B rebuilt and compared), bad X (generation / layout / offsets / hazard / image / buffer / rows / tuple); T ns a served draw`.

## 6. Ожидаемый выигрыш (оценка, не замер)
Цена обслуженного draw: поколение (11 сравнений) или хэш (~0.1 мкс), 4.4–7.7 × `nrbuf::ubo` (20–40 нс), 3.8–5 образов × 5 полей,
копия ≤ 15 смещений → **≈ 0.3–0.5 мкс против 2.8**. Строка сводки даёт её сама (`ns a served draw`).

|---|---|---|

## 7. Риски (честно)
1. Не исполнено на устройстве ни строчки; NR-01 и NR-06, на которых шаг стоит, — тоже. Доля блоков, которые `nrbuf::ubo` реально
   обслуживает, неизвестна (в NR-06 это «M of K uniform binds in the ring»): если блоки draw часто вне кольца — draw идёт старым путём
   (`block not served by the ring`), выигрыша нет, после 64 промахов подряд набор шейдеров отдыхает 600 подач.
2. **Пропуск пути чтения** держится на «в образ GPU никогда не писал». Писатели, не ставящие ни `gpu_written`, ни `last_write`, ни
   `storage_write`, ни `opw`, пропуском не увидятся; режим 2 это ловит только косвенно (старый путь закрыл проход / записал барьер, когда
   запись сказала «ничего не нужно»). Пропущенные чтения материальных текстур не доходят до хуков `nbtr / nbchk / hist / draw_reads`:
   для образов, не бывших вложениями, они ничего не решают, но счётчик `[nb] check: host reads not in the IR` по материалам занизится.
3. **Поколение.** Если найдётся писатель `state.tex / samp`, не двигающий `tex_gen`, запись «по поколению» будет чужой. Режим 2 сверяет
   поколение с хэшем на каждом draw (`bad … generation`).
4. Режим 2 **не привязывает** наборы NR: их запись в пул и рециклер исполняются, но первый draw через них — режим 1. Варианты
   статических кортежей на попаданиях в режиме 2 не переписываются (только при создании записи).
5. Захват полагается на порядок `VkWriteDescriptorSet` старой сборки = порядок строк плана; несовпадение — отказ (`capture`), после 8
   подряд набор шейдеров остаётся на старом пути с красной строкой. Проверяются привязка, тип, буфер кольца, смещения.
6. Режим 3 меняет раскладку 147 пар (только `=1`, только при лимите < числа блоков): новые пайплайны для них на первом draw (хитч
   сборки, если прогрев собрал старые). Выбор динамических блоков зависит от истории draw до первого появления пары — у разных запусков
   может отличаться (картинка та же, меняется только число перезаписей).
7. Ложный «hold» / гонка зеркала и ожидающие GPU-результаты поверх блока → старый путь для draw; счётчики NR-06 покажут.
8. Режим 2 дороже: каждый 8-й draw — полная сборка (≈ +2–3 мс на кадр на Mi 14), повторные `prepare_read` могут переполнить
   `draw_reads` (32) → меньше `first_draw_covers` в прогоне сверки.
9. Общие файлы: `xbg_game.cpp` (5 точек, из них `UBO_DYN` и `dyn_mode_for` — общий код ядра `dm/`: при `split_on = false` поведение
   прежнее), `xbg_vendor_policy.h`, `xbg_nb_mx.inc`, `source_structure_test.py`, `vendor_policy_test.cpp`.

## 9. Прогоны телефона, которые это подтвердят (главный агент, по разрешению хозяина)
Бэкап `files/save`; keyguard снят; без лимита кадров; `DM_NB_MT=0` в `dm/env` (иначе `draw_sections` не меряются). Сцены: палуба 60 с +
Форт Радость / бой / город (палуба одна не представительна), инвентарь и карта.
1. **R-NR08a, сверка (Adreno, на месте):** `DM_NR=1 DM_NR_BUF=1 DM_NR_DESC=2`. Ждём `[nr] DM_NR_DESC=2 … device: 16 dynamic … every block a
   dynamic offset`; в `[nr] desc:` — `would serve` ≥ 90 % графических draw, `entry by generation` ≈ половина, `images … skipped` ≫ `read
   path`, **`bad 0`** по всем восьми видам, `not eligible` ≈ только UI / пост, `block not served by the ring` мало. Картинка — как без флагов.
2. **R-NR08b, сверка зеркала:** то же + `DM_GFX_ZEROCOPY=0`. Те же ожидания + строки NR-06 `race 0`, `hold` ≈ 0.
3. **R-NR08c, лимит 8 (Mali / Xclipse):** `… DM_NR_DESC=2 DM_GFX_ZEROCOPY=0 DM_GFX_SIM_GPU=ubdyn8` (сверка: у 147 пар 9–11 статических
   слов, `bad … tuple 0`), затем `DM_NR_DESC=1` с тем же: строки `[nr] desc: shader set … has N uniform blocks, the device allows 8 …`,
   `sets: reused ≫ written`, картинка равна.
4. **R-NR08d, политика PowerVR:** `… DM_NR_DESC=1 DM_GFX_ZEROCOPY=0 DM_GFX_UBO_DYNAMIC=0`: `sets: written` ≈ draw, `new` перестаёт расти
   через несколько секунд (рециклер), картинка равна, мерцаний нет.
5. **Цена (ABBA × 2, 60 с):** `DM_NR=1 DM_NR_BUF=1` против `+ DM_NR_DESC=1`; то же с `DM_GFX_ZEROCOPY=0`. Смотреть `draw_sections_ms_per_frame
   desc` (цель ≤ 0.6 мс), `parts_ms_per_frame`, `submit_cpu_ms`, `ns a served draw`, скриншоты равны, `set_binds` не вырос.
Умолчание (по детекту в `xbg_vendor_policy.h`) — только при `bad 0` во всех сверках и выигрыше; для MTK / Mali / PowerVR нужен лог
игрока / тестера тестовой сборки.
