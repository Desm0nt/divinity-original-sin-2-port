# VK-NATIVE, карта интерфейса рендерера, часть 1: ресурсы

Статический разбор сорока функций низкоуровневого рендерера игры (образ `main.raw`, сборка для Switch). Игру не запускали, ничего не меняли. Объект рендерера ниже называется `r` (глобальный указатель лежит по адресу `[main+0x2bbdc68]`), обёртка устройства — `dev = [r+0xb70]`.

Пометки достоверности:

- **[бин]** — прочитано прямо из разобранного кода или из таблиц в `main.raw`;
- **[выв]** — вывод или догадка, в коде прямо не видно.

Исходные материалы:

- разобранный код: `scratchpad\vk\re\out\<адрес>.c` (каталог сессии);
- соответствие ячеек таблицы вызовов и имён: `dos2-port/src/work/re-nr-nrend/nvn_slot_map.tsv`;
- какие вызовы делает каждая функция: `dos2-port/src/work/re-nr-nrend/nvn_by_function.txt`;
- форматы движка и состояния по умолчанию: `engine_formats.tsv`, `default_states.txt` там же;
- четыре таблицы перечислений (фильтр, множители смешивания, действия трафарета, число выборок) прочитаны из `dos2-port/work/exefs-update/main.raw` по адресам `0x1f585e8`, `0x1f585fc`, `0x1f58624`, `0x1f586e0`.

## 1. Общие структуры

### 1.1. Описатель и таблица описателей [бин]

Описатель — 64-битное число: младшие 32 бита — номер ячейки, биты 32..53 — поколение. Нулевое поколение означает пустой описатель.

Все таблицы устроены одинаково и стоят в `r` с шагом `0xC0`. Поля таблицы `T`:

| Смещение | Смысл |
|---|---|
| `T+0x00` | массив указателей на страницы записей |
| `T+0x08` | массив указателей на страницы поколений (по одному `u32` на ячейку) |
| `T+0x10` | число ячеек на страницу (`u32`) |
| `T+0x18` | список свободных номеров |
| `T+0x60` | блокировка чтения-записи (`u32` состояние; `+0x64` поток-владелец, `+0x68` глубина повторного входа) |
| `T+0x78` | массив указателей на живые записи |
| `T+0x80` | упакованное слово: биты 0..22 — ёмкость, бит 23 — признак, биты 24..47 — число живых, биты 48..63 — шаг роста |

Как описатель превращается в запись:

1. `idx = (u32)h`, `page = idx / T[0x10]`, `slot = idx % T[0x10]`;
2. описатель годен, если `(h >> 32) & 0x3fffff` не ноль и равен `gen[page][slot]`;
3. запись лежит по адресу `pages[page] + slot * размер_записи`.

Освобождение: поколение ячейки увеличивается на единицу, запись убирается из массива живых, номер уходит в список свободных (`0x915870`).

### 1.5. Запись выделения `A` (размер `0x20`) [бин]

Заполняется функцией `0x932900(out, видПула, размер, выравнивание)`, освобождается `0x933890(A)`. Обе берут общую блокировку `0x2bbee38`.

| Смещение | Смысл |
|---|---|
| `+0x00` | указатель процессора на выделенный участок (в `0x919090` в него копируется код шейдера) |
| `+0x08` | смещение в пуле (его передают в `SetStorage`) |
| `+0x10` | `u32`, размер |
| `+0x14` | `u16`, выравнивание |
| `+0x16` | `u8`, вид пула; не ноль означает «запись действительна» |
| `+0x18` | блок пула (`NVNmemoryPool` по `блок+0x50`) |

Виды пулов: 2 — код шейдеров; 3 — текстуры-цели отрисовки и глубины; 4 — обычные текстуры и статические буферы; 5 — буферы с признаком использования 3. Вид 1 в этих сорока функциях не встречается.

### 3.2. Состояния [бин]

**Фильтр выборщика** (значение движка 1..5 → фильтр уменьшения `NVN`): 3, 3, 5, 3, 5 (3 — линейный с ближайшим уровнем, 5 — линейный с линейным переходом между уровнями), фильтр увеличения линейный. Значение 0 → уменьшение «ближайший с ближайшим уровнем» (2), увеличение «ближайший».

**Повтор текстуры**: 0 — повтор (`NVN` 1), 1 — прижатие к краю (7), 2 — зеркальный повтор (6), 3 — прижатие к границе (5).

**Функция сравнения** (выборщик, глубина, трафарет; движок n → `NVN` n+1): 0 — никогда, 1 — меньше, 2 — равно, 3 — меньше или равно, 4 — больше, 5 — не равно, 6 — больше или равно, 7 — всегда. Выборщик включает режим сравнения только при ненулевом значении.

**Множитель смешивания** (движок → `NVN`):

| Движок | Смысл | `NVN` |
|---|---|---|
| 0 | ноль | 1 |
| 1 | единица | 2 |
| 2 | цвет источника | 3 |
| 3 | единица минус цвет источника | 4 |
| 4 | цвет приёмника | 9 |
| 5 | единица минус цвет приёмника | 10 |
| 6 | альфа источника | 5 |
| 7 | единица минус альфа источника | 6 |
| 8 | альфа приёмника | 7 |
| 9 | единица минус альфа приёмника | 8 |
| 10 | насыщение альфой источника | 11 |

**Действие смешивания для альфы** (при выставленном бите 0 флагов): 1..4 → `NVN` 2..5 (вычитание, обратное вычитание, минимум, максимум), иначе сложение (1). Для цвета всегда сложение.

**Действие трафарета** (движок → `NVN`): 0 — сохранить (1), 1 — обнулить (2), 2 — заменить (3), 3 — инвертировать (6), 4 — увеличить с переходом через край (7), 5 — уменьшить с переходом через край (8), 6 — увеличить (4), 7 — уменьшить (5).

**Число выборок сглаживания** (аргумент 2..8 → число выборок): 2 → 2, 4 → 4, 8 → 8, остальные → 1.

## 4. `0x91e2a0` `CreateTexture`

**Аргументы** [бин]: `x0` r, `x1` описатель, `x2` `void** начальныеДанные`, `w3` формат движка, `w4` ширина, `w5` высота, `w6` глубина, `w7` число уровней. Через стек по порядку: байт (→ `запись+0x19`), число слоёв, число выборок, `u16` флаги, `u8` признак использования, флаги `NVN` (`-1` — подобрать самим), формат `NVN` (0 — взять по формату движка), указатель на готовую запись `A` (0 — нет).

**Флаги** [бин] (смысл части из них — [выв]):

| Бит | Смысл |
|---|---|
| `0x1` | sRGB (передаётся в `0x919c20`) |
| `0x2` | кубическая текстура |
| `0x1c` | влияет только на выбор выборщика по умолчанию для целей глубины |
| `0x60` | цель отрисовки цвета |
| `0x300` | цель глубины |
| `0xc00` | изображение для вычислительного шейдера |
| `0x2000` | брать общую память целей отрисовки (`r+0x18e8` → `r+0x18d8` → `r+0x18c8`) |

Признак использования: `& 3` — линейная текстура (раскладка для доступа процессора).

**Поведение** [бин]:

- Если число уровней равно 0, текстура — цель отрисовки цвета и не кубическая, число уровней считается от `max(ширина, высота)` функцией `0x1bf6690` ([выв] двоичный логарифм). Иначе ноль заменяется единицей.
- Заполняет запись текстуры (формат, флаги, признак, уровни, байт, выборки, слои).
- Цель `NVN` по форме: одномерная 0, двумерная 1, трёхмерная 2, массив одномерных 3, массив двумерных 4, со сглаживанием 5, массив со сглаживанием 6, кубическая 8, массив кубических 9. `nvnTextureBuilderSetSize3D(ширина, высота, глубина или 1)`.
- Флаги `NVN`, когда подбираются сами: цель отрисовки или глубины → 8; линейная → `0x10` (или `0x40`, если это цель отрисовки); плюс 4, если изображение; плюс `0x100`, если цель глубины и формат движка равен `0x31`.
- Число выборок: по таблице из раздела 3.2; `SetSamples` вызывается только при числе выборок не 1.
- Цель глубины: `nvnTextureBuilderSetDepthStencilMode(0)`. Линейная: шаг строки из `nvnDeviceGetInteger(0x38 или 0x39)` и `SetStride`.
- Память: пул 3 для целей отрисовки и глубины, иначе пул 4; либо готовая запись `A` из аргумента; либо общая память по флагу `0x2000`. Затем `SetStorage(блок+0x50, смещение)` и `nvnTextureInitialize`.
- Объект текстуры (`0x108`) выделяется из пула `0x2bb5828` либо общей кучей.
- Берёт номер из битовой карты (`dev+0x5a38`, курсор `dev+0x25a3c`; при номере не меньше `0x100000` — аварийный останов), `nvnTexturePoolRegisterTexture(dev+0x57f8, номер, текстура, 0)`, для изображения ещё `RegisterImage` с тем же номером. Если слоёв не один или текстура кубическая: на каждый слой (для кубической — на 6 граней) отдельный номер с видом (`SetLayers(i, 1)`, цель двумерная), номер кладётся в `объект+0xc4+4*i`.
- Начальные данные (только не для целей отрисовки и глубины, и если `*начальныеДанные` не ноль): цикл слой (`nvnTextureGetDepth`) → уровень → грань (6 для кубической); `nvnTextureWriteTexels` с областью ширина × высота × 1; указатель источника сдвигается на ширина·высота·байт на точку (из `0x91eea0`).
- `объект+0x100` = номер выборщика по умолчанию: глобальный описатель `0x2bbda98` (цель отрисовки или изображение), `0x2bbda70` (цель глубины с флагами `& 0x1c`), иначе `0x2bbdab0`. Номер берётся из записи выборщика в `r+0x540` по `+0x10`.

**Замена на Vulkan:** `VkImage`, вид на всю текстуру и виды на слои; загрузка через промежуточный буфер в том же порядке; у текстуры хранить выборщик по умолчанию; битовую карту номеров заменить индексами описателей или прямыми видами.

## 5. `0x91f2e0` `CreateTextureFromImage`

**Аргументы** [бин]: `x0` r, `x1` описатель, `x2` изображение, `w3` sRGB.

**Структура изображения** [бин]:

| Смещение | Смысл |
|---|---|
| `+0x00` | формат движка |
| `+0x04` | флаги (бит 1 — кубическая) |
| `+0x08` | формат `NVN` (`-1` — взять по формату движка) |
| `+0x0c` | упакованная раскладка, 8 байт (`-1` — данные не упакованы заранее) |
| `+0x18` | ширина |
| `+0x20` | высота |
| `+0x28` | глубина |
| `+0x30` | значение для `запись+0x19` |
| `+0x38` | число уровней |
| `+0x40` | число слоёв |
| `+0x48`..`+0x70` | поля готовой записи `A` (`+0x48` указатель, `+0x50` размер, `+0x60` байт действительности, `+0x68` смещение, `+0x70` блок пула) |
| `+0x78` | обратный указатель на `r` |

**Поведение** [бин]:

- Цель: кубическая 8; глубина не меньше 2 → трёхмерная; высота 1 и глубина 1 → одномерная; иначе двумерная. `SetSize3D(ширина, высота, max(слои, глубина))`, `SetLevels(уровни)`.
- Бит sRGB меняет пары форматов `NVN`: `0x25` ↔ `0x38`, `0x41`..`0x44` ↔ `0x45`..`0x48`, `0x6d` ↔ `0x37`.
- Данные не упакованы: память из пула 4; загрузка через `0x941b00(изображение, уровень, слой)` по слоям и уровням; грани кубической с 1 по 5 берутся со сдвигом `k × (0x943050(изображение, 0, уровни, формат) / 6)`.
- Данные упакованы заранее: используется память самого изображения и `nvnTextureBuilderSetPackagedTextureLayout`; **`nvnTextureWriteTexels` не вызывается** — данные уже лежат в плиточной раскладке Switch.
- Флаги записи = `(флаги изображения & 2) | 4`, число выборок 1. Кубическая получает 6 номеров граней (`объект+0xc4`..`+0xd8`). Выборщик по умолчанию — `0x2bbdab0`.

**Замена на Vulkan:** как у `CreateTexture`, но на пути с упакованными данными перед загрузкой нужно разворачивать блочно-линейную раскладку Tegra.

## 6. Запись в буферы

- Среди этих сорока функций нет функции блокировки и разблокировки буфера. [бин] При создании буфер отображается один раз (`nvnBufferMap`), указатель процессора остаётся в `запись+0x10` (и у вершинного, и у индексного), поэтому динамические данные пишутся прямо в память пула по этому указателю. Функция, которая выдаёт указатель движку, находится в другом месте.
- [бин] Второй путь: `0x9218c0` копирует из промежуточного пула в целевой буфер на стороне видеопроцессора, в текущем контексте команд.
- [выв] Метки «кадр последнего использования» (вершинный буфер `+0x38`, индексный `+0x18`, текстура `+0x08`) пишет код привязки и отрисовки, которого в этом наборе нет; уничтожение на них опирается. Для текстур метку ставит ещё `0x920460` [бин].

## 7. Отложенное уничтожение

- [бин] Правило везде одно: освобождать сразу, если `метка + 2 < dev[0x51f0]`; иначе переносить запись в соответствующую таблицу ожидания и сразу освобождать внешний описатель.
- [бин] `0x91ad20(r, принудительно)` разбирает шейдеры, вершинные и индексные буферы, третий вид буферов и таблицу `r+0xe80`. В принудительном режиме уничтожается всё независимо от метки.
- [бин] Текстуры в ожидании (`r+0x1180`) туда кладёт `0x920460`; кто их оттуда разбирает, в этом наборе не видно.

## 8. Открытые вопросы

- Назначение `0x915170` и таблицы `r+0xb80`.
- Тип объекта, который передаётся в `0x91a040`.
- Таблица ожидания `r+0xe80` (запись `0x80`, уничтожает `0x91d450`).
- Байт записи текстуры по `+0x19`.
- Флаги А и Б состояния растеризации.
- Выражение размера грани кубической текстуры в `0x91f2e0` (общий размер / 6) выглядит странно, но записано именно так.
- Что передают в аргумент «глубина» `CreateTexture` для массивов и кубических текстур (число слоёв или 1) — по этому коду не определить.
