# NR-22 fix — сверка `DM_NR_TEXSTREAM=2`: 214 «несовпадений» были байтами выравнивания между мипами, 18.11.2026, ветка `dos2-nr22fix`

База `dos2-nr-all` (a589fc6). Телефон не трогался.

## Симптом (Mi 14 Ultra, Adreno, zero-copy, палуба; `src/work/logs/nr17_ts2`, `DM_NR_TEX=1 DM_NR_TEXSTREAM=2`, `DM_GFX_DESWZ_DIRECT=1`)
`NVN nr-texstream verify: claims 709, create info / kind mismatches 0, memory requirement mismatches 0, staged byte compares 709, mismatches 214;
red lines 214`, красные строки вида `serial=829 fmt=0x42 820x820 levels=10: the worker's deswizzled staging (450032 B) differs from the old
path's (450024 B)` — всегда +8 Б у рабочего, только 8-байтовые BC-блоки (0x42 / 0x46 / 0x49), размеры 52..1640, полные / почти полные цепочки мипов.

## Причина (с доказательством)
1. **+8 Б — это не раскладка, а округление среза.** Рабочий поток пишет ровно `nr_tex_layout` (= раскладка DESWZ_DIRECT старого пути: каждый
   подресурс с 16-байтовой границы), длина `j->bytes` = длина старого пути. `nrts::slice()` округляет **срез** до 16, а красная строка
   печатала длину среза (`pre->bytes`). Для BC1 820×820×10: уровни 336200 / 84872 / 21632 / 5408 / 1352 / 392 / 72 / 32 / 8 / 8 Б с
   выравниванием начала на 16 → 450024 (≡ 8 mod 16, последний мип — один 8-байтовый блок) → срез 450032. Все 11 форм из лога дают ровно
   числа лога (тест ниже: 450024/450032, 1944/1952, 28120/28128, 113816/113824, 113800/113808, 7336/7344, 28104/28112, 451896/451904).
2. **«Байты различаются» — это промежутки выравнивания, которые никто не пишет и никакая копия не читает.** Уровень, чей размер не кратен 16
   (BC1 / BC4: 13×13 блоков = 1352 Б, хвостовой мип в 1 блок = 8 Б, у простых форматов — 2×1 / 1×1 и нечётные размеры), оставляет перед
   следующим подресурсом 8 (или 4 / 12) байт дыры. Старый путь (`DM_GFX_DESWZ_DIRECT=1`) берёт `stream_buffer(total, nullptr)` — в дырах
   старые байты кольца; срез рабочего — старые байты своего чанка (или нули свежей памяти). Старая сверка (`nrts::compare`) делала **один
   `memcmp` всего диапазона** → любая текстура с дырами = красная. У сверки NR-05 (`nrtex::compare`) этой ошибки нет: она сравнивает по
   подресурсам — поэтому `DM_NR_TEX=2` был чистым, а `DM_NR_TEXSTREAM=2` нет.
3. Вывод: данные подресурсов, регионы копий и раскладка у двух путей **одинаковы**; различаются только байты, которые
   `vkCmdCopyBufferToImage` не читает (регионы: `bufferRowLength = bufferImageHeight = 0`, смещение = начало подресурса, экстент = мип). Картинка
   `=1` глазами равна старой (nr17_ts1) — согласуется.

## Что сделано (только `DM_NR_TEXSTREAM=2`; при 0 и 1 копии / байты / раскладка не менялись, кроме п. 3)
1. **Ядро `dm/gfx/nr/nr_tex.{h,c}` (чистый C):**
   - `nr_tex_cmp_staged(d, L, a, a_cap, b, bn, &at, &off)` — два staging одной раскладки так, как их читают копии: `SAME` (весь диапазон
     равен), `PAD` (все подресурсы равны, различаются только дыры — **не** несовпадение), `DIFF` (подресурс `at`, первый байт `off`),
     `LAYOUT` (`bn` ≠ длине раскладки, срез меньше неё, раскладки нет);
   - `nr_tex_regions_match(d, L, regions, n, &at)` — список регионов копии старого пути против регионов раскладки (то, что пишет `=1` через
     `nrtex::copies_of`): смещение от начала staging, `row_len` / `img_h` 0, уровень, слой, `layerCount` 1, смещение в образе 0, экстент.
2. **Движок `xbg_game.cpp namespace nrts`:** `compare_desw(t, g, staged, n, copies, base)` вместо `compare` для деswizzle-объекта: регионы
   копий старого пути (`VkBufferImageCopy` минус смещение кольца) → `nr_tex_regions_match` (красная строка `copy region i of N is not …`,
   счётчик `copy region mismatches`), байты → `nr_tex_cmp_staged` (+ проверка `g.n == n`): `PAD` считается в `alignment gaps only`, красная
   строка только для `DIFF` (с подресурсом и байтом) и `LAYOUT` (длины рабочего / среза / старого пути). ASTC-сверка осталась сплошной
   (`xbg_ac_level_bytes` пакует уровни без дыр, регионы обоих режимов строит один код `astccache::upload`), но стала строгой по длине
   (`n > slice` → красная; раньше допускалось +15) и печатает длину среза.
3. **Режим 1, страховка:** staging рабочего берётся только для образа **не** `subst` (ASTC-оверлей `[nonadreno]`: образ в формате-заменителе).
   Сейчас недостижимо (рабочий отказывает BC при `astc_ov_mask`), но `claim` мог взять объект для такого образа, а ветка `=1` вида не
   проверяла; при `=0` ветка не исполняется (`ts_got.pre` пуст).
4. Строка сводки `=2`: `NVN nr-texstream verify: claims …, create info / kind mismatches …, memory requirement mismatches …, staged byte compares
   …, mismatches … (alignment gaps only, no copy reads them: P), copy region mismatches R; red lines …`.

## ASTC (Mali) и не-BC форматы — то же правило хвостовых мипов
- Деswizzle-путь один для всех форматов «как есть» (BC на Adreno, простые, ASTC гостя 0x79…): раскладка `nr_tex_layout` = DESWZ_DIRECT,
  дыры возникают у любого подресурса с длиной не кратной 16 (простые 2×1 / 1×1, нечётные ширины; ASTC 16-Б блоки дыр не дают) — новая
  сверка покрывает их одинаково (тест: RGBA8 8×2×4, 300×77×4, 1-D 128×8 уровней, куб BC 0x46, 3-D, массив, ASTC гостя 0x79).
- ASTC-кэш (Mali / PowerVR / Xclipse, `NRT_TS_ASTC`): блоки записи читаются одним сплошным куском в обоих путях, регионы строит один код —
  дыр нет, раскладки совпадают по построению; округление среза до 16 сравнение не затрагивает (сравниваются `data_bytes`).
- Старый путь без DESWZ_DIRECT (`=0`, `linear` — вектор): дыры там нули, у рабочего — что было в чанке; та же ложная красная была бы и там —
  новая сверка от этого не зависит.

## Риски
- Сверка теперь не видит различий в дырах выравнивания — по построению: их не читает ни одна копия (регионы проверяются тем же вызовом).
- Пункт 3 (`!im.subst` в `=1`) меняет только режим `=1` на гипотетическом образе-заменителе: там теперь старый деswizzle вместо staging рабочего.
