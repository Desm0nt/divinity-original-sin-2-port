# NR-09U `DM_NR_UBO` — блоки констант (UBO) draw движка нативным кодом (ночь 18.11.2026, ветка `dos2-nr09u`)

Worktree `wt-nr09u`, ветка `dos2-nr09u` от `dos2-nr-all` 12961a5. Телефона не было (adb не запускался): всё доказано на ПК — эмулятором
на машинном коде игры, тестами, сборкой. **На устройстве не исполнялось ни строчки.** Всё за `DM_NR_UBO`, умолчание 0.

## 0. Коротко
- **Что заменено.** Каждый draw движка перед сбросом текстур зовёт две функции: `0x926f90(r)` (глобальные блоки, под read-замком `r+0xbe0`) и
  `0x925740(r)` (блоки шейдера стадий 0 / 1 / 5) — вместе 7.1 КБ кода с аллокатором кольца констант устройства и спин-замком. При
  `DM_NR_UBO=1` для взятого direct draw (NR-09R) **обе не исполняются как машинный код игры**: модель `dm/gfx/nr/nr_ubo.h` делает их работу
  нативно — те же атомики на тех же словах (read-замок r, writer-замок кольца, fetch-add головы), те же копии теней в кольцо (тот же порядок
  загрузок / записей, тот же цикл копирования), те же поля блоков; её вызовы `BindUniformBuffer` идут **через тело точки входа** первыми в
  той же одной смене стека, что у direct draw (`nrd_job`) — без thunk-а, обёртки и своей смены стека на вызов.
- **Доказательство.** Unicorn на `main.raw`: 6 000 случайных состояний (рендерер, запись шейдера, 0–6 блоков на стадию, 0–4 глобальных блока
  с повторами, голова кольца у конца / в переполнении u32 / случайная, чужие читатели на замке r, владелец замка, нарочно испорченные
  указатели, размеры, тени в кольце, наложения блоков) через **машинный код обеих функций** и через модель: **те же вызовы NVN по порядку
  со всеми пятью аргументами, та же память арены 12 КБ байт в байт, те же поля устройства (голова, замок, база), те же байты кольца
  (CRC окна у головы и окна переноса)**; 10 мутаций модели — 10 пойманы (§4). `DM_NR_UBO=2` на телефоне сверяет то же на живых draw.
- **Потоки и спин-замок — безопасно, без подмножества.** Игра исполняется нативно, гостевая память = память хоста: нативные атомики C и
  `ldaxr / stlxr` игры на одном адресе — один замок. Модель говорит ровно протоколом игры (§1.2), поэтому другие потоки игры, которые
  пользуются кольцом / замком r (функции `0x1bed3b8…`, 20+ мест), видят то же, что от машинного кода. Тест с потоками (§4): писатель
  кольца, читатели кольца, писатель замка r против модели — выделения не пересекаются, замки свободны в конце, все ветки ожидания пройдены.
- **Выигрыш честно.** Телефон (play-1118, 150 окон): блоки движка стоят **541 / 625 / 733 нс на direct draw** (p25 / медиана / p75).
  Большая часть — работа, которую обязана сделать и модель (копия теней в кольцо, атомики, промахи кэша по блокам и кольцу). Убирается:
  2.7–4 вызова `BindUniformBuffer` на draw через thunk + обёртку + смену стека (≈ 17–47 нс каждый) и вход в две функции игры; модель
  добавляет свои проверки (≈ 10–20 нс ПК). **Ожидание: −30…170 нс на draw → −0.05…0.28 мс на потоке игры в Форте Радость (1 630 draw /
  кадр, Mi 14)**, ×2–3 на in-order ядрах (A520 / A55 / A510): −0.15…0.8 мс. GPU — 0 (поток команд байт в байт тот же). Точное число —
  одна строка `DM_NR_UBO_AB=1` (§7). Это меньше «~1 мс» цены функции: **заменить можно вызовы, а не память** (бит-в-бит).

## 1. Разбор машинного кода (capstone `main.raw` v786432; r = рендерер, dev = `[r+0xb70]`, ctx = `[dev+0x5248]`, cb = ctx + 0x38)
### 1.1 Что делают функции
| | `0x926f90` (глобальные блоки) | `0x925740` (блоки шейдера) |
|---|---|---|
| вход | owner `r+0xbe4` ≠ −1 → `nn::os::GetCurrentThread` (PLT `0x1bf4590`), сам владелец — без замка; иначе **read-замок `r+0xbe0`**: ждать, пока ≥ 0x100000 (`0x918050`), +1; пришёл писатель — −1, снова | S = `[r+0x17e0]` (0 — выход) |
| список | n = биты 24..47 `[r+0xc00]`, указатели `[r+0xbf8]` (читается один раз под замком) | массивы `[S+0x20] / [S+0x28] / [S+0x30]` по 0x40 Б, счётчики `S+0x38..0x3a`, стадии NVN 0 / 1 / 5 (первые 3–4 блока развёрнуты, дальше цикл) |
| пересборка | блок грязный (`+0x34`) или штамп `+0` ≠ `[dev+0x51f0]` → REBUILD + `BindUniformBuffer(cb, 0 / 1 / 5, слот +0x35, адрес +0x10, размер +0x30)` (без проверки слота; не пересобранный — не привязывается) | фаза 1 (стадии 0, 1, 5): слот ≤ 7 и (грязный или старый) → REBUILD, затем `+0x2c = +0x28`, `+0x28 = 0`; фаза 2: `+0x18 ≠ 0` и слот ≤ 7 → `BindUniformBuffer` — **каждый** такой блок, пересобран он или нет |
| выход | −1 на замке r (или ничего, если владелец) | — |

**REBUILD(b):** размер = `b+0x30` (u32). Writer-замок кольца `dev+0x25aa8`: пока ≥ 0x100000 — `yield` × 400, затем `nn::os::YieldThread`
(PLT `0x1bf45a0`), снова; +0x100000; если писатель уже был — −0x100000 и снова; затем ждать, пока читатели (биты 0..19) уйдут (`0x9156a0`).
h = (`[dev+0x25a60]` + 0xff) & ~0xff (32 бита); h + размер > 0x137ffff → h = 0; **обычная запись** головы = h; old = **fetch-add**(голова,
размер); −0x100000. `b+0x10` = `[dev+0x25aa0]` + old (GPU), `b+0x18` = `[dev+0x25a98]` + old (CPU); копия размера байт из `[b+0x20]` (тень)
по CPU-адресу (вперёд, шаги 32 Б парами ldp / stp, хвост 16 / 8 / 4 / 2 / 1); `b+0x34` = 0; штамп `b+0` = `[dev+0x51f0]`.

### 1.2 Потоки
Кольцо констант общее для устройства: кроме этих двух функций в него пишут 20+ мест (`0x1bed3b8 … 0x1bf1468`, тот же writer-замок), читатели
кольцевого замка — младшие биты. Замок `r+0xbe0` — read-сторона; писатели — те, кто меняет список глобальных блоков. Модель берёт **те же
замки тем же протоколом на тех же словах** (C `__atomic` = `ldar` / `ldaxr`+`stlxr` / LSE; на одном адресе это один и тот же замок с кодом
игры на других потоках). Отличия от машинного кода (и почему они безопасны):
- после 400 спинов — `sched_yield()` вместо гостевого `YieldThread` (HLE-SVC с эвристикой back-off): это тот же уступ ядру; ветка
  достигается только при удержании замка другим потоком (в тесте — единицы раз на тысячи draw);
- `owner ≠ −1` → модель отказывает (draw идёт машинным кодом): ветку «сам владелец» без `GetCurrentThread` не повторить. При выходе движок
  перечитывает owner; модель всегда делает −1: при взятом нами read-замке писатель (другой поток) owner = нашему потоку стать не может.
- вызовы `BindUniformBuffer` — после всех записей пакета (у движка глобальные — между пересборками). Тело вызова пишет только поток
  команд (тап NB, тень NB-09 / запись `OP_BIND_UBO`), блоки и кольцо не читает; аргументы модель берёт **в момент, когда их взял бы движок**
  (под замком r для глобальных).

## 2. Что сделано
- `dm/gfx/nr/nr_ubo.h` (чистый C): `nru_draw(r, s, sim)` — `sim = 0`: исполняет обе функции (замки, голова, копии, поля), отдаёт вызовы
  (`nru_call` × до 96); `sim = 1` (`=2`): ничего не пишет, замков не берёт, предсказывает на копиях блоков (байты блоков, голова, копии,
  вызовы). `nru_check` — сверка `=2`. `NRU_CODE_TABLE` (FNV-1a: обе функции + два хелпера ожидания), `NRU_SLOT_BIND = 0x2bbfa80`.
  **Проверки до записи** (§0, отказ = функции движка, нетронуто): нет dev / ctx / базы кольца, owner ≠ −1, > 16 блоков на стадию / > 16
  глобальных, нулевой указатель массива / списка / блока, размер > 64 КБ или нулевая тень при размере, а ещё — блоки, которые могут
  писаться, и кольцо не должны лечь на слова, которые модель читает **один раз**, а движок перечитывает (dev `r+0xb70`, S `r+0x17e0`,
  замок + owner `r+0xbe0`, ctx `dev+0x5248`, голова..замок `dev+0x25a60..0x25aac`, заголовок записи шейдера), массивы / глобальные блоки — не
  на кольцо и друг на друга (кроме тождественных глобальных: второй к тому времени чист, как у движка). Всё остальное исполнение перечитывает
  ровно там, где перечитывает машинный код, поэтому тень в кольце или внутри глобального блока исполнение воспроизводит **как движок** (оракул
  сравнивает и такие случаи); симуляции `=2` нужно больше (она отказывает и не сравнивает такие draw). Список глобальных проверяется под
  read-замком r (как его читает движок); отказ там отдаёт замок назад (+1 −1, других записей нет).
- `dm/gfx/nvn/nvn_nr_ubo.{h,inc}`: исполнитель `nvn_nru_exec` = тело `h_nvnCommandBufferBindUniformBuffer` на каждый вызов; `nvn_nru_ready`
  — точка входа кончается этим телом; захват `=2`: строка `NUB(...)` первой в теле (без `=2` — загрузка + непринятый переход).
- `dm/host/hle_dos2_nr_ubo.inc`: переключатель, хэши кода, проверка указателя движка (раз, первый draw), `nru_take` (из `nrd_draw_take`
  вместо `fill(r); bind(r)`), `nru_job_calls` (первым в `nrd_job`, до сброса текстур — порядок движка), `=2`, A/B, строки.
- изменено: `hle_dos2_nr_direct.inc` (вызов модели вместо двух функций, вызовы в `nrd_job`, строка отчёта), `hle_dos2_nr.c` (объявления,
  `#include`, `nru_arm` / `nru_install` после NR-09R), `hle_nvn.c` (2 `#include`, строка `NUB`), `tests/source_structure_test.py` (блок NR-09U).

## 3. Переключатели (умолчание 0; игрокам не выдаются; `jni_android.c` и `xbg_vendor_policy.h` не тронуты — от GPU не зависит)
| | |
|---|---|
| `DM_NR_UBO` | **0** — ничего: `nrd_draw_take` зовёт `0x926f90` / `0x925740` движка как раньше, строка `NUB` — загрузка + непринятый переход. **1** — блоки direct draw нативно (нужен `DM_NR_DIRECT=1` с частью `DRAW` — умолчание DOS2; иначе красная строка и выкл.). **2** — исполняются функции движка; симуляция модели до них на том же состоянии; после — сверка байт блоков, головы, скопированных байт кольца и вызовов (красные строки, первые 16, итоги раз в 10 с; чужое выделение между ними — `raced`, смещения не сравниваются). **3** — нет: `=1` делает те же записи и вызовы |
| `DM_NR_UBO_AB` | `1` (только с `=1`): блоки по 64 draw чередуются «модель / движок», оба замеряются (1 из 64) — A/B в одном прогоне |

Строки (раз в 10 с, вместе с `[nr] direct`):
- старт: `[nr] DM_NR_UBO=1 (NR-09U): the uniform blocks of a direct draw (main+0x926f90 global + main+0x925740 shader blocks) run as native code …`;
  первый draw: `[nr] ubo: the engine's nvnCommandBufferBindUniformBuffer pointer (main+0x2bbfa80) is the thunk of the body …` (иначе красная, блоки — движку);
- `=1`: `[nr] ubo (DM_NR_UBO=1, NR-09U, N frames): direct draws with uniform blocks D a frame, native X …, C BindUniformBuffer calls a frame through
  the body (c a draw, none through a thunk …), blocks rebuilt into the ring a frame: global g, shader s; left to the engine a frame: …; lock waits … YieldThread y`;
  `[nr] ubo, ns a draw (1 in 64 timed): native (the model + its calls through the body) X (n)[, the engine's two functions … Y (m): Z us a frame saved …]`;
- `=2`: `[nr] ubo check (DM_NR_UBO=2 …): … compared C a frame (raced r …), bad B (blocks …, ring bytes …, calls …); not compared …; totals: N compared, raced R, bad 0, …`;
  красные `【红】[nr] ubo check: …`.
- При `=1` строка NR-09R `ns a direct draw … the engine's uniform blocks A` меряет только модель (её вызовы ушли в `flush and record`).

## 5. Замер (ПК) и ожидание
ПК (`nr_ubo_test`, лучший из 5, арены на своих гостевых адресах — `NRU_PTR` тождество, как в HLE): draw «как в Форте» (1 глобальный блок,
пересборка раз в кадр; 2 + 2 блока шейдера, 1.5 пересобираются за draw, 64–256 Б; 4 вызова) — **модель 61 нс на draw** (атомики ≈ 15,
проверки ≈ 20, копии и поля — остальное), симуляция `=2` — 104 нс. Машинный код игры на ПК не исполнить (ARM64) — «до» даёт телефон:

Почему не «−1 мс»: копия теней в кольцо (то, что NR-06 отдаёт бэкенду на месте), атомики протокола и промахи кэша по блокам / теням —
**эффект функции**, его модель обязана повторить бит-в-бит. Следующие рычаги (на этой основе, не делались): (а) не слать перепривязку
блока, чей слот уже держит этот диапазон (фаза 2 перепривязывает все блоки на каждом draw, пересобирается из них меньшая часть; долю даст строка `=1`: вызовы на draw против пересборок на draw) —
зеркало как TEXF NR-09R, со сверкой бэкендом; (б) вызовы — сразу в тень NB-09 без тела (`nbd_take_bind` напрямую, как S2 NR-09S).

## 6. Риски
- **Не исполнено на устройстве.** Сначала `=2`.
- `owner ≠ −1` (ветка рекурсии движка) отдаётся движку; если в игре это частый случай, строка `left to the engine: r's lock owned by a thread`
  покажет — тогда нужен `GetCurrentThread` HLE (не делался).
- `sched_yield` вместо гостевого `YieldThread` в ветке после 400 спинов: без back-off-эвристики HLE (DM_YIELD_BACKOFF); сработает только
  при удержании замка другим потоком дольше 400 `yield` (счётчик `YieldThread` в строке).
- Счётчики NVN (`[nvn] 帧 N：…`, `DM_NVN_PROF`, `DM_NVN_TRACE`) не видят вызовы `BindUniformBuffer` direct draw при `=1` (≈ 4 тыс. на кадр
  меньше — признак работы).
- Другая сборка игры: хэши не совпадут — переключатель выключится сам (красная строка). Модель стоит только за вызовы из direct draw NR-09R
  (draw 36 / 37); остальные 22 места вызова двух функций (`0x929130`, `0x92f9b4`, …) — машинный код, как были.
