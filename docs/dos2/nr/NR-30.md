## 2. Что сделано

### 2.1 Решения (чистый C, `dm/gfx/vulkan/engine/xbg_prepass.h`)
Кандидат пре-пасса — как раньше: проход без цветных целей, глубина ≥ 640×360 и не квадрат; FS пустой (одна функция, только OpLabel/OpReturn)
или нет; test + write; без stencil, alpha test, rasterizer discard, подсчёта сэмплов (`count_samples` или открытая пара NR-03); indexed.
Новые **ворота** (каждое — причина «оставить», в строке):

| Ворота | Правило |
|---|---|
| `first` | первый draw пре-пасса на этой глубине в кадре рисуется всегда (он начинает проход и его сложенную очистку) |
| `mixed` | ключ уже рисовался в пре-пассе в этом кадре (kill / фейд) — не пропускать |
| `new` (история, `DM_DOS2_PREPASS_HIST=1`) | ключ пропускается, только если **в прошлом кадре** он был чистым: все его draw пре-пасса — кандидаты, ни одного «природного» оставленного, ровно столько G-buffer-заявок, сколько кандидатов, ни одного отказа, ни одной опасности до его последней заявки |
| `new` (допуск, `DM_DOS2_PREPASS_ADMIT=32`) | ключей, впервые ставших чистыми, в кадр допускается не больше N (уже пропускавшиеся не считаются): вход в зону не даёт разом сотню новых вариантов пайплайна LEQUAL+write и скачок overdraw |

**Заявка** (G-buffer-draw получает LEQUAL + запись) — только в первом цветовом проходе на этой глубине, первые N draw ключа, и только если
draw — полная замена: EQUAL (любая запись) или LEQUAL без записи; без настоящего blend и с полной маской цвета на всех целях; FS без kill,
alpha test ALWAYS, без A2C; без stencil / depth bounds; тот же растр, что у пропущенного draw (cull / front / mode / offset, bias, clamp,
viewport, scissor — хэш). Иначе — отказ (`refused func / blend / kill / raster / stencil`), ключ не чист.

**Опасность** (`hazards`): пока у кандидатов есть незаявленные draw, всё, чей результат зависит от глубины **в этот момент** и что не чинит
последующая заявка: stencil test, depth bounds, функция вне NEVER / LESS / EQUAL / LEQUAL, blend вместе с записью глубины, draw другого
цветового прохода, чтение образа глубины (выборка шейдером — `image_read_hook`, источник копии — переход в TRANSFER_SRC, `copy_texture`,
`copy_texture_buffer`). Значима первая опасность: ключ, последняя заявка которого позже неё, «unsafe».

**Плохой ключ** кадра (сверка): пропущен, но кадр показал `unmatched` (заявок меньше пропусков), `ambiguous` (оставлен в том же кадре или
заявок больше кандидатов), `refused` (включая `lost`: подмену получил draw, который хост потом не записал — пропуск по шейдеру, viewport…),
`unsafe`. Такой кадр в режиме 1 нарисован неверно **для этих мешей и один раз**: история их тут же снимает.

**Откат:** больше 30 кадров с плохими ключами за 600 кадров → режим 1 становится 2 до конца сессии (красная строка). Правило хозяина
«игрокам флаги не ставим»: на Mali / PowerVR всё по умолчанию и с самостраховкой.

### 2.2 Почему остальное точно
Глубина: после всех заявок буфер = min(оставленные draw пре-пасса, подменённые G-buffer-draw, записи LESS / LEQUAL других draw) = та же
глубина, что у игры (DEP- и DEF-позиции бит в бит равны — на этом игра и держит EQUAL; повторные/лишние записи `z ≥ min` минимум не меняют;
не-min записи — опасность). Цвет: draw, прошедший раньше заявки «лишний» раз (глубина ещё больше итоговой), закрашивается подменённым draw
того объекта, который задаёт итоговую глубину пикселя, — он полная замена и идёт на своём месте в порядке игры; EQUAL-draw оставленных
объектов в такой момент проходят только там, где проходят и у игры (их глубина уже записана их draw пре-пасса). Ломают это ровно опасности
выше. Два допущения модели (оба — свойства любой корректной игры; проверка — глазами на телефоне):
- **A1:** внутри G-buffer объект рисует свою геометрию полной заменой не больше одного раза (второй draw — слой: blend / маска / kill /
  другая функция). Иначе при втором экземпляре меша, который есть только в пре-пассе, счёт заявок сойдётся, а глубина пропадёт незаметно.
- **A2:** объект без draw в пре-пассе показывает себя в G-buffer с записью глубины и не через EQUAL (иначе он был бы невидим у самой игры).
- Точные совпадения глубины разных объектов (z-fighting) зависят от порядка и у игры — модель берёт различные `z`.

### 2.3 Полоса NR-09 (`xbg_nr_draw.inc`, `dm/gfx/nr/nr_draw.h`)
- `lane()` принимает `F_PP` (подмена) для draw движка (не UI): группы NB-13b для него читаются `groups_pp()` — `state.ds` на время
  `groups()` заменяется игровым (`prepass::live->saved`) и возвращается; так id групп никогда не описывают подмену (исправление скрытой
  ошибки §1).
- Вариант = игровые id групп + бит `NR_DRAW_VAR_PP` (бит 30 слова 4 — был свободен; тест: ни одно поле варианта его не задевает). Подмена —
  функция только группы depth-stencil, значит (id, бит) называет состояние глубины пайплайна точно. Промах — старый хвост с подменой,
  `done()` учит таблицу именно этим пайплайном; `DM_NR_DRAW=2` его сверяет.
- NR-21 такие draw в сегмент не берёт (C6: цвет пишется) — пишутся сразу, как раньше.
- Строка `[nr] draw: …` + `pre-pass override (DM_DOS2_PREPASS LEQUAL + write variant): asked N, served M`.

### 2.4 Политика (`xbg_vendor_policy.h`)
`xbg_dos2_prepass_default(family)` = 1 на `xbg_tile_family` (Mali, PowerVR), 0 на Adreno / Xclipse / Maleoon / прочих. Только в сборке
DOS2 (`#ifdef DM_GAME_DOS2` в `prepass::config`; другим играм — только env). JNI не трогал: `dm/env` `DM_DOS2_PREPASS=` по-прежнему
главнее. `DM_GFX_SIM_GPU=mali` / `powervr` включает режим 1 на Mi 14 (проверено в `vendor_policy_test`).

## 3. Переключатели

| Значение | Поведение |
|---|---|
| `DM_DOS2_PREPASS` не задан | семейство: Mali / PowerVR → 1, остальные → 0 (строка `NVN DM_DOS2_PREPASS=… (family default; policy family …)`) |
| `0` | ничего: ни таблиц (300 КБ не выделяются), ни строк, ни хуков (одна загрузка `prepass::mode` на draw / чтение) |
| `1` | гибрид с воротами §2.1, откат в 2 при частых плохих кадрах |
| `2` | сверка: все решения 1 (с историей и допуском), ничего не меняется; в конце кадра решения сверяются с самим кадром → `【红】NVN PREPASS frame …: N bad keys (…) - mode 2 would have drawn this frame wrong`, первые 16 |
| `3` | яд: пропуск как 1, **без** подмены в G-buffer — всё, что режим 1 берёт, исчезает (EQUAL не проходит): видно, что решения доходят до draw |
| `DM_DOS2_PREPASS_HIST` | 1 (умолч.) — ворота истории; 0 — старое правило «в этом же кадре» (только для A/B, см. риски) |
| `DM_DOS2_PREPASS_ADMIT` | новых чистых ключей в кадр (умолч. 32; 0 — без предела) |
| `DM_DOS2_PREPASS_LOG` | кадров между строками `NVN PREPASS` (300) |

Строка (раз в `LOG` кадров, по последней таблице кадра):
`NVN PREPASS mode= gate= frame= pre_draws= cand= skip= pre_verts= cand_verts= skip_verts= keep_verts= keep kill= fs= state= stencil= alpha= counting= notindexed= late= full= first= mixed= new= admitted= occ_after_skip= | gbuffer draws= other_pass= dw= df never..always= override= refused func= blend= kill= raster= stencil= lost= vbdiff= hazards stencil= bounds= func= pass= blendw= read= | keys= ok= unsafe_keys= bad= unmatched= ambiguous= refused_keys= unsafe= | total skipped= override= bad_frames= bad_keys= fallbacks=`.
`vbdiff` — заявки, у которых поток вершин 0 не совпал с пропущенным draw (диагностика ключа без VB; если массово — у DEP другой поток позиций).

| PowerVR | как Mali по вершинам; HSR убирает overdraw G-buffer целиком (опак без kill) | как MTK | IMG-компилятор последовательный: допуск 32 / кадр нужен именно ему |
| S7 / Adreno 7xx | 0 (умолч. 0) | 0 | кандидат на A/B, если GPASS Mi 14 с `=1` покажет выигрыш |

Честно: на Adreno аудит (`AUDIT-REMAINING.md`) считал гибрид бесполезным (цена пре-пасса — draw и штампы, их снимают NR-14 / NR-21);
на тайлерах рычаг другой — геометрия дважды через бининг и трансляция draw на слабом CPU. Если `=2` покажет долю опака < 10 % или массовые
`unsafe_keys` / `refused`, выигрыша нет, и умолчание надо вернуть в 0.

## 9. Риски
- **Допущения A1 / A2** (§2.2) не проверяются кодом. Нарушение = объект без глубины на всё время, пока нарушение держится (не один кадр).
  Проверка — глазами: `=3` (яд) показывает, что именно режим трогает; `=1 SIM mali` — листва, фейд стен, террейн, персонажи, декали.
- **Синхронная сборка** вариантов LEQUAL+write при первом входе в зону на свежей установке (Mali / PowerVR): допуск ограничивает до 32
  новых ключей в кадр, но не число новых пайплайнов в кадре; список прогрева запомнит их к следующему запуску. Если хитчи — `ADMIT=8`.
- **Overdraw G-buffer** на Mali, если FPK срабатывает плохо (порядок draw игры не спереди назад) — может съесть выигрыш; решает только лог
  Mali-тестера (`gpu_ms`, GPASS).
- Ключ без вершинного буфера: два экземпляра одного меша неразличимы; совместный ключ «опак + фейд» — `mixed`, смена ролей — один плохой
  кадр. `vbdiff` покажет, если DEP привязывает другой поток.
- Хуки чтения глубины покрывают выборку, переход в TRANSFER_SRC и две функции копий; другие пути чтения (если есть) — не видны. На палубе
  между пре-пассом и G-buffer нет ни одной операции, кроме очисток целей G-buffer (IR-дамп).
- Память: 300 КБ на тайлерах (таблица кадра 229 КБ + две истории по 37 КБ); кадр без пре-пасса (меню) не чистит их.

## 10. Не сделано
- Выбор варианта «без kill» для DEP-материалов (PREPASS.md §3 a) — дорогая часть пре-пасса (kill-материалы) не тронута.
- Перестановка draw пре-пасса (опак первым) — NR-21 `=3` как источник данных.
- Асинхронная сборка вариантов LEQUAL+write заранее (по кадру, где ключ ещё «new») — понадобится, если `ADMIT` не хватит.
- Умолчание для Xclipse / Maleoon / Adreno — только после A/B.

## 11. Прогон телефона (главный агент, по разрешению хозяина)
Бэкап `files/save`; keyguard снят; без лимита кадров; сцены: палуба 60 с, Форт Радость (лес / листва), бой, исчезающие стены при наведении
камеры; `DM_GFX_PASS_PROF=300,180,0` во всех.
1. **R-NR30a, факты (Mi 14):** `DM_DOS2_PREPASS=2`. Ждём `NVN DM_DOS2_PREPASS=2 (env; policy family adreno default 0): compare …`;
   строки `NVN PREPASS mode=2 …`: `cand / pre_draws`, `skip_verts / pre_verts` (доля выигрыша), `keep … mixed= new= admitted=`, `refused …`,
   `hazards …`, `unsafe_keys`, `bad=` ≈ 0 вне смены ролей, `total bad_frames` мал; `【红】NVN PREPASS` — только единицы при движении камеры.
   Картинка как без флага.
2. **R-NR30b, режим по семейству (Mi 14):** `DM_GFX_SIM_GPU=mali` (без `DM_DOS2_PREPASS`). Ждём `NVN DM_DOS2_PREPASS=1 (family default;
   policy family mali default 1)`, `mode=1`, без `NVN PREPASS fallback`; скриншоты (листва, фейд, террейн) как в R-NR30a; GPASS пре-пасса /
   G-buffer против `DM_DOS2_PREPASS=0` с тем же SIM.
3. **R-NR30c, полоса:** как 2 + `DM_NR=1 DM_NR_BUF=1 DM_NR_DESC=1 DM_NR_DRAW=2`, затем `=1`: `[nr] draw check … bad 0`,
   `pre-pass override … asked N, would serve / served M` (M ≈ N после прогрева).
4. **R-NR30d, яд:** `DM_GFX_SIM_GPU=mali DM_DOS2_PREPASS=3` — опак-объекты исчезают (видно, что берётся), листва / фейд остаются.
5. **Выигрыш** — только лог Mali / PowerVR тестера с тестовым пререлизом (CAUTION): `parts_ms`, `gpu_ms`, `NVN PREPASS` строки.
