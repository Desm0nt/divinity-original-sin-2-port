# VK-NATIVE — текущее состояние (ветка `dos2-vk`, дерево `dos2-port/wt-vk`)

Задача: убрать NVN из пути рендера DOS2 целиком. Движок рисует через наш бэкенд Vulkan, поставленный на уровень его собственного
рендерера (`r = [main+0x2bbdc68]`), переключатель `DM_VK_NATIVE`. Проект и карта — `VK-NATIVE.md`, `VK-NATIVE-MAP-1…3.md`. Этот файл —
чтобы новый агент мог продолжить с места остановки.

## Режимы сейчас
- `DM_VK_NATIVE=2` («рядом»): старый путь рисует; текстуры, сэмплеры, шейдеры, объекты состояния и форматы вершин создаются в бэкенде по
  событиям движка; буферы только считаются. Строки `[vkn] …` раз в 10 с. Это и есть прогон этапа 2.
- `DM_VK_NATIVE=1`: то же, плюс буферы вершин и индексов уже принадлежат бэкенду (тела `0x917630 / 0x9179d0 / 0x91db40 / 0x91d890`
  заменены, копия `0x9218c0` — `memcpy`). **Картинки не будет до этапа 3**: старый путь читает буферы по адресу NVN, которого больше
  нет. Запускать `=1` до этапа 3 незачем.

## Открытые вопросы этапа 2 (подтвердит только телефон)
- Массивы и массивы кубов в `CreateTexture`: число слоёв берётся из записи движка.
- Упакованные 16-битные форматы (`0x95`, `0x3c`, `0x98`, `0x39`): порядок бит — догадка; транслятор их не знал, игра, вероятно, не использует.
- Глубина D24 заменяется на D32F там, где D24 нет: смещение глубины растеризации надо масштабировать (`units_x` в `vkn_state`).
- Трёхкомпонентные 8 / 16-битные атрибуты вершин без поддержки устройства читаются как четырёхкомпонентные.
- Не открыты через выход шейдеров: обрезка выходов вершинного шейдера (`DM_NR_XLQ`) и модуль без размера точки (`DM_NR_IDVS`).
- Таблица хэндлов состояний рассчитана на индексы до 4096 (сверх — красная строка).

Отладочные переключатели, которые это нашли, остаются: `DM_VK_NATIVE_DUMP=k1,k2` (цели k-го кадра уровня в PPM 480x216 + строки

`DM_VK_NATIVE_UI=0`.
Уроки: (1) вывод «соглашения NVN совпали с Vulkan» был верен только про глубину; (2) всё, что движок делает мимо функций рендерера
(прямая запись в память текстур), статический разбор по входам NVN не показывает — показал только дамп целей.

### Серия V5 (20.11, APK `7855a797`, Mi 14 Ultra) и что из неё сделано
- **V5_a**: путь без NVN работает — «game table 515 of 515 entries native, HLE NVN calls since start 0», картинка верная, ролик идёт,
  53–58 fps стоя. Зеркало текстур: 184 МБ вместо 2 ГБ. Две красные строки оказались справочными (игра спрашивает 2 имени вне
  таблицы: 1032 = 2 × 515 + 2) — переведены в обычные.
- **V5_b**: миниатюры сохранений чёрные. По дампам записи вне кадра: сцена доходит до `окно+0x90`, а цель снимка
  «ScreenshotBackBuffer» пуста. Причина: **общая память целей** — рендерер держит таблицу «имя → ключ хранилища» (`0x913170`,
  `r+0x18d8`), несколько имён делят одну память, и движок на это опирается: «ScreenshotBackBuffer» и уменьшенный буфер окна — одна
  память (ключ `0x2bbff80`). Аудит U5 считал, что содержимое через неё не передаётся — передаётся. Сделано: текстуры с флагом
  `0x2000` на одном хранилище и одной формы — один образ (`vkn_tex_create_shared`; `DM_VK_NATIVE_SHARED=0` — как было).
  **На устройстве не проверено.**
- **V5_c** (SIM mali, `DM_GFX_BC_ASTC=1`): картинка верная; самотесты прошли (4 декодера, кодировщик 285 блоков); 4335 текстур через
  GPU ASTC, 245 на процессоре; образы 290 МБ против 600. Пака `astc/` на этом телефоне нет — маршрут пака на устройстве не проверен.
- **V5_d** (условный рендер): `=2` — 765 условных draw на кадр, GPU отсёк бы 402; `=1` — пропавших объектов не видно, но
  **48.7 fps против 54.2**: на Turnip 750 предикат на GPU стоит дороже отсечённого. Умолчание 0 на Adreno остаётся; проверить на
  настоящем Mali / PowerVR.

### Что остаётся от NVN и транслятора при `=1`
- **Загрузчик шейдеров вынесен** (`dm/gfx/vkn/vkn_shlib.{h,cpp}`, `DM_VK_NATIVE_SHLIB`, умолчание 1; 0 — прежние двери в транслятор):
  читатель паков, подмена `native.xgspack`, вся цепочка переписываний SPIR-V в прежнем порядке, варианты порога альфы и типа входа
  вершин. При `=1` `xbg_game_initialize` не исполняется. Хост-тест `vkn_shlib_test` (в него собран настоящий `xbg_game.cpp` против
  подставного Vulkan): 12 330 ключей, 30 960 вариантов альфы, 24 528 вариантов типа входа — **0 различий слово в слово** для Turnip
  750, Mali-G720, PowerVR, модели Mali, подмены нативного пака и файлов россыпью. **На устройстве не запускалось.**
- Из `xbg_game.cpp` при `=1` остаются только чтения счётчиков другими частями порта (`xbg_recent_gpu_ms`, `xbg_nr_mem_usage`) и
  безопасный режим; чистые единицы переписывания SPIR-V (`xbg_spirv_*.cpp`) линкуются как библиотека.
- От `hle_nvn.c`: стек хоста 1 МБ на поток, `g_nvn_present_period_ns`, статические таблицы; игра после старта не зовёт ничего.
- Не сделано: замок сборки модулей для PowerVR в сборках конвейеров бэкенда (компилятор там не потокобезопасен); правило
  `DONT_CARE` для целиком перекрываемых целей на тайловых GPU (только проект).

  устройство). Исправлено: `DM_GFX_SIM_GPU=mali / powervr` заставляет `vkn_tex` декодировать BC на процессоре, как на настоящем Mali.
- **V3_a** (`=1`, UI выключен): 71 из 71 крюков, 9 381 кадр, 22.5 млн draw записано, 0 сброшено, 0 красных строк — и **чёрный экран**.
  Причина: окно вывода ставилось без переворота. NVN с началом координат сверху слева отображает y = +1 в строку 0, Vulkan — y = −1;
  транслятор для этих же шейдеров переворачивает окно вывода (`xbg_nvn_viewport`: `y + h`, `−h`). Без переворота обход вершин
  обратный, и всё, что рисуется с отсечением задних граней, исчезает. Вывод карты «соглашения совпали, переворот не нужен» был
  ошибкой (верно только про глубину 0…1). Исправлено в `vkn_draw.c` и `vkn_ui.c`, коммит `8ff7c5a`.
- Из того же лога: строка `stray NVN calls` — не потеря: draw `main+0xb0aebc` (сведение кадра с UI в окно, функция `0xb0aab0`) и
  остальные прямые вызовы исполняются бэкендом, строка их только перечисляет. `ui: programs 67 (bad 11)` — проверить в прогоне с UI.
- Копии буферов вершин (пакет 0x2e → `0x9218c0`): ≈ 0.3 МБ на кадр, две копии процессором (движок в своё кольцо, мы из кольца в
  буфер). Дёшево (≈ 75 МБ/с = единицы мс в секунду), но одну копию можно убрать на этапе 4 (писать в буфер при исполнении пакета).

## Этап 3: что в работе сейчас
Договор между кусками записан заголовками `dm/gfx/vkn/vkn_frame.h`, `vkn_pass.h`, `vkn_draw.h` (их пишет ведущий; куски реализуют).
Главное решение: исполнитель `0x93e5f0` целиком не переписывается — родной код движка исполняет коды без NVN, а свой обработчик
(`dn_install_rc_take`) берёт только коды, в теле которых NVN зовётся прямо (0x04, 0x07, 0x08, 0x0a, 0x0b, 0x12, 0x13, 0x15, 0x23, 0x2c,
0x37, 0x3d–0x3f); функции рендерера с NVN внутри заменяются крюками. Состояние draw не «привязывается» событиями: крюк draw читает
кэш рендерера `r+0x16f0…` и отдаёт его бэкенду значениями (`vkn_draw_in`).

## Этап 3: куски (каждый 1–2 агент-часа, своё дерево от `dos2-vk`, не больше четырёх разом)
Порядок важен: 3.1 и 3.2 — основа, остальные опираются на их заголовки.
1. **Кадр и показ** (`vkn_frame.c`, `hle_dos2_vkn_frame.c`): кольцо из трёх буферов команд с заборами, замена `0x9215f0`, `0x93d9f0`,
   `0x93ccd0`, `0x93cef0`; текущий буфер команд `vkn_cb()`; показ `dm_present_async`; вне кадра — `(r, 0)` с ожиданием.
2. **Проходы и цели** (`vkn_pass.c`): ленивое начало прохода, свёртка очисток, раскладки образов, замена `0x9279a0`, `0x928ab0`,
   `0x928be0`, `0x920b00`; пакеты 0x03–0x05, 0x16, 0x34, 0x37.
3. **Исполнитель пакетов** (`vkn_exec.c`, `hle_dos2_vkn_exec.c`): свой `0x93e5f0` на 64 кода (таблица — `VK-NATIVE-MAP-3.md`); коды состояния
   пишут кэш `r`; коды без NVN зовут родной код движка.
4. **Draw** (`vkn_draw.c`): сбросы `0x926f90 / 0x925740` в своё кольцо, набор дескрипторов из кэша по слотам, конвейер по ключу, буферы,
   `0x928e80 / 0x928fb0 / 0x9290f0`, пакет 0x23; служебный буфер и `c1`; привязка 3 с шагом 0 для отсутствующих входов.
5. **«Немедленные» draw** 0x26–0x2a (`0x92f730…0x930e90`) и переписывание индексов для веера / четырёхугольников / замкнутой линии.
6. **UI** (`vkn_ui.c`, `hle_dos2_vkn_ui.c`): 11 входов Iggy над тем же буфером команд, обновление текстур UI (пакеты 0x2c / 0x2d и
   `WriteTexels` из блока UI).
7. **«Песок» и счёт оставшихся вызовов NVN** (`hle_nvn.c`: при `DM_VK_NATIVE=1` запись команд — в локальную страницу, счёт по адресу возврата).
8. **Хост-тест этапа 3** (пакеты, записанные с телефона, против подставного Vulkan) — один на этап.
Оценка: 14–20 агент-часов работы агентов + 3–5 серий телефона (первый кадр, сравнение кадров, UI, ходьба).
Нерешённое по пакету 0x30 (применить подготовленную копию буфера посреди кадра): при своих буферах это `memcpy` — проверить на
этапе 3, что порядок с уже записанными draw не нарушается (иначе копия на GPU из блока арены).
