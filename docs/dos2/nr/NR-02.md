# NR-02 `DM_NR_KEY` — идентичность draw (режим счёта), имя ↔ ключ пака, раскладка NR в заголовке бандла

Ветка `dos2-nr02` (worktree `wt-nr02`, база `dos2` 94d287d). План: `NATIVE_RENDERER_PLAN.md` §3 NR-02, §2 S1 / S3 / S4.
Основа шагов NR-04 (шейдеры по имени), NR-07 (пайплайны по хэндлам), NR-08 (дескрипторы). **Ничего не рисуется иначе ни в одном режиме.**
На телефоне не исполнялось (телефона не было); всё ниже — статика `main.raw`, тесты на ПК, сборка.

## 2. Переключатель `DM_NR_KEY` (нужен `DM_NR=1` или `2`; иначе не читается)
- **0 / не задан** — ничего: хука нет, таблиц нет, 8 новых строк тапа в `hle_nvn.c` — загрузка + непринятый переход (как NR-01; при `DM_NR=0` даже без вызова). Обработчик ExecuteRenderCommand — прежний `k_nr_rc`.
- **1 — счёт.** Раз в 10 с две строки:
  - `[nr] draw keys (DM_NR_KEY=1, N frames): engine draws X/frame (in command lists A%, outside the lists B%; по видам мест), NVN draws Y/frame (… after an engine draw, … other = UI / direct NVN), engine draws with no NVN draw …; keys K distinct (… this window, … new), eligible E% of draws (not: shader / compute / pack-key / state / vformat / rt / full-state / lost …%)`
  - `[nr] texture sets (DM_NR_KEY=1): dirty range at D% of draws, set changed at C%, S distinct (…), draws whose set has a render target R% (hazard check needed), an id the registry does not know U%, no set …%; RT format sets …, pool ids mapped …; flush without a draw …/frame, compute flushes …/frame; lost: …`
  - с `DM_NR_DUMP=1` каждые 30 с: `nr_keys.tsv`, `nr_texsets.tsv`, `nr_rtfmts.tsv`, `nr_names.tsv`, `nr_draw_sites.tsv` рядом с файлами NR-01.
- **2 — счёт + сверки** (красные строки `【红】[nr] key check: …`, первые 16, всё в счётчиках, строка `[nr] key checks (DM_NR_KEY=2): …`):
  1. программы, привязанные на командном буфере (этим потоком) в момент draw NVN = VS / FS шейдера из реестра по хэндлу `r+0x17d8`;
  2. запись шейдера движка `r+0x17e0` (+8 VS, +0x10 FS) = реестр;
  3. слоты текстур / сэмплеров **не меняются при чистых грязных диапазонах** (на этом стоит кэш наборов NR-08; при расхождении набор всё равно считается сменившимся);
  4. ключ пака программы на первом draw = ключ на `nvnProgramSetShaders` (код читается позже — так делает и хост).
- **3** не существует: в NR-02 ничего не исполняется по-новому, травить нечего (любое другое значение — красная строка и «выкл»).

## 3. Факты движка (main 4979b200; каждое проверяет `dos2_nr_check.py`)
- Кэш состояния `r` (пишут код 21 `0x93e6ac`, `SetShader 0x9283a0`, `SetBlend 0x9284e0`, `SetRenderTargets 0x9279a0`, коды 7 / 10):
  `+0x16f0` raster (polygon state, таблица `r+0x780` × 0x18), `+0x16f8` blend (таблица `r+0x600` × 0x20; особый хэндл `[main+0x2bbdb70]`),
  `+0x1700` слово маски blend (второй аргумент `0x9284e0`), `+0x1708` depth-stencil (таблица `r+0x6c0` × 0x20), `+0x1710` stencil ref (динамика, вне
  ключа), `+0x1714` примитив движка (байт), `+0x1718` примитив NVN, `+0x1740` формат вершин (таблица `r+0x480` × 0x80: attrib + stream state),
  `+0x1748 / 50 / 58` VB потоков 0–2 (таблица `r+0x180` × 0x68), `+0x17c8` IB (таблица `r+0x240` × 0x58), `+0x17d8` шейдер, `+0x17e0` его запись,
  `+0x17e8 + 8i` цвет 0..7, `+0x1828` глубина, `+0x1860 / 0x185c` условный рендер, `+0x1868` alpha ref (тест включён при ≥ 0).
- Пакет кода 21 (0x70 Б) = «всё состояние draw»: `+8` шейдер, `+0x10/+0x18` depth-stencil + ref, `+0x20` raster, `+0x28` blend, `+0x30` формат вершин,
  `+0x38/40/48` VB, `+0x50` IB, `+0x58` примитив, `+0x60` счётчик условного рендера, `+0x68` alpha ref. Состояния биндятся в NVN **сразу**
  (код 21), draw сбрасывает только UBO и текстуры.
- Текстуры: id `r+0x1558` (VS) / `r+0x15e0` (FS), сэмплеры `r+0x13c0` / `r+0x1448`, 32 слота; грязные диапазоны (i8 мин, i8 макс; чисто = 32, −1):
  текстуры `+0x15dc` / `+0x1664`, сэмплеры `+0x1444` / `+0x14cc`. Писатель — `0x9243d0` (код 15); id = u32 по **объекту текстуры NVN + 0xc0**
  (движок кладёт его туда сразу после `nvnTexturePoolRegisterTexture`: `0x91e9a0`, `0x91f63c`, окно `0x93c6ac / 0x93c960`; виды слоёв / куба —
  `+0xc4 + 4i`, 6 для куба, иначе число слоёв). Отсюда карта id → хэндл → класс (RT / материал) без слежения за пулом.
- 25 вызовов `0x924730`: `0x928f0c` код 36 (DrawElements), `0x92903c` 0x928fb0 (код 37 и `0xb7e020` напрямую), `0x929140` DispatchCompute (код 43),
  5 × коды 38–42 (full-state), `0x93f0f4` код 35 (DrawArrays), `0x93fa28` код 33 (только сброс), `0x941010` / `0xb0ae90` / `0xd1b2ec` DrawArrays вне
  списков, 12 мест — собственные DrawElements двухрежимных функций (`list+0x30 == 0` → NVN сразу). «Мимо списков» считается точно — глубиной
  ExecuteRenderCommand на потоке (тот же обработчик в общей цепочке, `pre`/`post`), а не `pass+0x48`: его не понадобилось.
- Сброс без draw (код 33, compute) обнуляет грязные диапазоны — «грязно» переносится на следующий draw потока (`carry`), иначе набор потерялся бы.

## 4. API для следующих шагов (`dm/gfx/nr/nr_key.h`)
- **NR-07:** `nr_dkey` {shader, blend, depth, raster, vformat (хэндлы), blend_arg, rtfmt, prim, alpha_test} → `nr_key_note` → плотный `id`
  (таблица `pipeline[id]`), `why` (маска `NR_NE_*`: почему не годен). Быстрый путь без реестра: `nr_key_note(k, NULL, …)` находит известный ключ,
  новый возвращает `fresh = -1` (повторить с реестром под его мьютексом). `nr_rtfmt_note` — набор форматов RT по хэндлам.
- **NR-08:** `nr_texset_hash` (id текстур + сэмплеров обеих стадий) → `nr_texset_note` → плотный `id` набора, `nrt` (слоты-RT = единственные, кому нужна
  проверка хазарда), `nmat`, `nunknown`; `nr_texset_count` — draw с тем же набором без хэширования; `nr_texid_put / _get / _tex`.
- **NR-04:** `nr_shader_find_name`, `nr_shader_find_key`, `nr_names.tsv`; офлайн `tools/dos2_nr_names.py`.
- **Бандлы:** `nr_layout_word(bindings, n)` / `nr_layout_valid / _ubos / _textures / _flags / _text`.
- Фронт (`hle_dos2_nr_key.inc`): `t_nk` (на поток: последний набор, его хэш, кэш формата RT, ожидающий draw), порядок блокировок
  `g_nk_mu → g_nr_mu`. NR-09 сможет брать id ключа и набора для `OP_X_NR_DRAW` прямо в `nk_draw`.

## 5. Раскладка NR бандла — числа (офлайн, все 12 329 бандлов `work/shaders-vk`)
Слово `reserved`: биты 28–31 = 0xA, 24–27 версия 1, 20–23 UBO (set 0, динамические смещения в кольцо), 14–19 текстуры (set 1), 0–7 флаги
(c1, support, driver, storage/image, arrays, other, **fits**, clamped). Номера внутри наборов — порядок строк таблицы привязок бандла.

| Стадия | Бандлов | Влезают | UBO на стадию | Текстуры |
|---|---|---|---|---|
| VS | 6 132 | 100 % | 0:4 1:1037 2:3203 3:1888 | 0:5655 1:333 2:144 |
| FS | 6 192 | 100 % | до 8 (7: 132, 8: 15) | до 20, медиана ≈ 3 |
| CS | 5 | 0 % (storage) | — | — |

Пайплайны (VS + FS по `programs.tsv`, 6 130 пар): **≤ 8 динамических UBO на пайплайн — 5 983 (97,6 %)**; 147 пар (2,4 %) — 9–11 блоков.
8 — минимум спецификации `maxDescriptorSetUniformBuffersDynamic` (столько дают Mali / PowerVR; Adreno больше): для 2,4 % на тайлерах NR-08
нужен второй путь (часть блоков статическими UBO или прежний `descriptors()` для этих пайплайнов). Флаги c1 (VS 3 616, FS 4 707) и support
(все) — свои буферы хоста, в set 0 статическими. Офлайн-штамп: `dos2_nr_layout.py --write` по каталогу (проверено на копии 40 бандлов: старый
читатель принимает, слово = C); **в `work/shaders-vk` не ставил** — это новый пак 284 МБ на телефон, решать главной сессии, когда NR-08 начнёт
слово читать (читатель пока его не трогает).

## 7. Ожидаемый выигрыш
NR-02 — основа: **0 fps на всех классах** (Mi 14 / Adreno 750, S7, MTK / Mali, PowerVR). Цена режима счёта (оценка, не замер): `=1` ≈ 0,2–0,4 мкс
на draw (вход хука, ~120 Б чтения кэша, хэш набора только при грязном диапазоне, один мьютекс) → 907 draw ≈ 0,3 мс/кадр на потоке рендера игры;
`=2` ≈ 1–1,5 мкс на draw (второй мьютекс, `process_vm_readv` записи шейдера, хэш каждого draw) ≈ 1–1,4 мс/кадр. Только для прогона-замера.
Что даёт плану: доля годных draw (цель §4 «≥ 90 %»), число различных ключей = число пайплайнов прямой таблицы NR-07, доля «мимо списков»,
частота смены набора текстур и доля RT в наборах (= сколько `prepare_read` останется в NR-08; на Mali / PowerVR это главный CPU-налог `desc`),
подтверждение «чистый диапазон = набор не менялся» (иначе кэш NR-08 по поколению неверен).

## 8. Риски и чего нет
- `nr_key_note` / `nr_texset_note`: два набора с одним 64-битным хэшем считаются одним (не ловится; вероятность ничтожна при ≤ 65 536 наборов).
- Сверка 1 (программы на draw) видит только привязки **этим же потоком** на этом командном буфере; иначе — счётчик `with nothing bound by this
  thread` (не красная строка). Если движок пишет буфер с двух потоков — это и покажет.
- `nr_pack_key` проверяет читаемость только первого и последнего байта кода (пул отображён сплошняком); сверка 4 ловит, если код дописывается
  после `SetShaders`.
- Карта id: виды (`+0xc4..`) берутся только у `CreateTexture` (у `CreateTextureFromImage` их не читаю); id, зарегистрированные мимо хуков (UI
  Iggy `0x1bf2860`), — «unknown» (UI draw через `0x924730` всё равно не идут).
- Окно 10 с: «distinct this window» — ключи / наборы, встреченные в окне, а не за кадр.
- Не сделано: отложенное удаление буферов `0x91d5c0` (из NR-01, к ключу не относится); слово раскладки в реальный пак (§5) и его чтение
  хостом (NR-08); ключ не включает состояние, которое двухрежимные / full-state функции ставят мимо `r` (если такое есть — увидится как
  расхождения NR-07 `=2`).
- Общие файлы: `hle_nvn.c` (8 строк), `hle_dos2_nr.c` (≈ 25 строк, остальное в `.inc`), `source_structure_test.py` (счётчик NR-01 + блок),
  `dos2_nr_check.py`. Ветки NR-03 / 05 / 06 правят те же `hle_dos2_nr.c` / тесты — конфликты слияния ожидаемы, но мелкие.

## 10. Прогон на телефоне, который это подтвердит (один, можно вместе с R1)
- Бэкап `files/save`; APK с этой веткой. Env: `DM_NR=2 DM_NR_KEY=2 DM_NR_DUMP=1` (+ по желанию R1: `DM_GFX_COND_RENDER=4 DM_NB_FOREIGN=1`).
- Сцена: меню (≥ 20 с) → сейв → 2–3 мин ходьбы со сменой локации, бой, инвентарь / карта; ≥ 40 с после загрузки. Затем force-stop.
- Забрать `[nr]`-строки и `nr_*.tsv` (новые: `nr_keys`, `nr_texsets`, `nr_rtfmts`, `nr_names`, `nr_draw_sites`).
- Ждём: `[nr] DM_NR_KEY=2 (count + checks): the renderer's texture flush main+0x924730 hooked (25 call sites known) … command-list depth from the
  ExecuteRenderCommand chain`; в `draw keys` — `engine draws` ≈ 900/кадр в кампании, `engine draws with no NVN draw` = 0, eligible ≥ 90 %;
  в `key checks` — **0** mismatches программ, 0 записи, 0 «slots changed under a clean dirty range», 0 различий ключа пака; `lost` = 0;
  строка NR-01 `programs with unreadable code 0`, `shaders … N keyed` ≈ programs.
- После: `python tools/dos2_nr_names.py --dump <dir>/nr_names.tsv` — имена движка ↔ офлайн-ключи без красных строк (вход NR-04).
- По желанию второй прогон `DM_NR=1 DM_NR_KEY=1` против базы (ABBA, без лимита кадров) — цена счёта по `submit_cpu` / кадру.
