# NR-06 `DM_NR_BUF` — буферы без покадровых снапшотов (сегмент S2b), 17.11.2026, ветка `dos2-nr06`

План: `docs/dos2/NATIVE_RENDERER_PLAN.md` §2 S2b, §3 строка NR-06. Основа: NR-01 (`dm/host/hle_dos2_nr.c`, `dm/gfx/nr/nr_reg.*`), NB-12
(`xbg_nb_hit.inc`, статика кольца констант), zero-copy / snapshot / vcache / wtrack в `xbg_game.cpp`. **На телефоне не исполнялось.**

## 1. Что было (где сидят 1.0 мс `snapshot` и почему на MTK хуже)
- `parts snapshot` = 0.91–1.10 мс / 5 854–5 870 вызовов на кадр (Mi 14, `c0base` / `e0base` / `d1prof`, кампания 907 draw). В DOS2-сборке
  определён `DM_GAME_D3`, поэтому `zcubo::min_bytes = 1`: **каждый** UBO обходит zero-copy и идёт в `uniform_snapshot_cached` (фронт / карта /
  копия в stream-арену), даже на Adreno. ≈ 5 850 привязок UBO на кадр (800 привязок наборов × 7.3 смещения), копируется 0.45 МБ.
- NB-12 (`DM_NB_UBO=1`, включён по умолчанию с NB-22) отдаёт на месте только диапазоны, которые привязала запись `OP_X_NB_DRAW` **этой**
  подачи: в `g1all` 2.31 М из 5.85 М за 10 с; 3.54 М (60 %) — «not a ring range» (не-NB draw, глобальные блоки, привязанные раньше).
- Вершины / индексы: на Adreno — zero-copy view (`zc::view`: поиск чанка + проход sticky-страниц на каждый вызов), 1 413 попаданий,
  345 sticky-промахов → копия. Без zero-copy (Mali, PowerVR, Xclipse, MTK; KB MALI-15: zero-copy через WC dma-buf на G720 — −26 % fps) —
  каждый диапазон: фронт → карта → `pending_view` → `cpu_access` → `vcache` (unordered_map + проверка страниц) → копия.

## 2. Что сделано
### 2.1 Кольцо констант — одно место для всех UBO кольца
Хост (NR-01-хуки) находит кольцо устройства: `dev = [r+0xb70]`, база GPU `[dev+0x25aa0]` (= база CPU `[dev+0x25a98]`: в этом HLE
GPU-адрес = указатель хоста, проверяется, иначе красная строка и путь выключен), голова `[dev+0x25a60]`, `0x1380000` байт; передаёт в движок
(`xbg_nr_ring_set`). `SetRenderTargets` пробует каждые 64 вызова, пока не найдёт; перепроверка раз в 10 с через `[main+0x2bbdc68]`.
Движок (`xbg_nr_buf.inc`, первая строка `uniform_snapshot`, до строки NB-12) берёт любой UBO-диапазон **по адресу** внутри кольца:
- **zero-copy есть (Adreno):** на месте через чанк zero-copy (`nb_ubo_view`: выравнивание, sticky, край чанка) — как NB-12, но для всех
  draw (NB и нет) и для диапазонов прошлых подач; без `zcubo::bypass`, карты, фронта и копии.
- **zero-copy нет (Mali / PowerVR / Xclipse / MTK / Adreno с `DM_GFX_ZEROCOPY=0`): зеркало.** Один `VkBuffer` размером кольца + 64 КБ
  (host-visible, device-local предпочтительно, coherent предпочтительно; иначе flush на копию), те же смещения. Гранула 256 Б (голова
  кольца выравнивается на 256 → гранула принадлежит одному выделению). На грануле (`dm/gfx/nr/nr_buf.h`, `nr_ring_*`):
  `epoch` (сделана годной в этой эпохе снапшотов — ничего не делать), `used` (новейший serial слота, чьи draw могут её читать),
  `hold` (до какого serial идёт старым путём). Первая привязка в эпохе: гранулы, которые никто в полёте не читает (`used + 2 <= serial`:
  слот serial−2 отставлен `recording_slot()` перед записью), **копируются** из гостя; прочитанные записанной / летящей подачей — **сравниваются**
  (равны → годны; отличаются = кольцо обошло под GPU → гранула `hold` до ухода читателей, привязка — старым путём, красная строка). Копия на
  подачу = прирост кольца (то, что подача впервые привязала), без снапшотов, узлов карты и stream-арены.
- Запись CPU в потоке / writeback GPU поверх кольца (`snapshot_invalidate`): гранулы теряют годность; читаемые записанной / летящей
  подачей — `hold` (зеркало не держит две версии на одном смещении; старый путь снимает новые байты, ранние draw читают старые).
- Не берётся (старый путь, счётчики): UI-сдвиг (`g_ui_moff`), pending-writeback GPU, невыровнено, через край кольца, > 8 прогонов гранул.

### 2.2 Статические VB / IB — неизменяемые копии
Хуки `CreateVertexBuffer 0x917630` / `CreateIndexBuffer 0x9179d0` (NR-01) теперь передают в движок каждый буфер движка: хэндл, гостевой
диапазон = NVN-буфер, который инициализировал этот вызов (тап `dm_nr_tap_buffer` получил `mem`), класс (usage 3 = dynamic; static с
`init` = годный; static без `init` = no-init), в режиме 2 — хэш байт сразу после создания; удаления `0x91db40 / 0x91d890` — тоже.
События — в очередь (мьютекс), применяются на потоке трансляции в начале гостевой подачи (`nrbuf::submission`): удаления, финал пула
(`xbg_legacy_pool_del_now → nrbuf::drop_pool`) и «новый буфер поверх живого» (память переиспользована) действуют сразу; слияние новых в
таблицу (`nr_stab_apply`, O(n + k log k)) пакетное: 256 в очереди / 16 подач / четверть таблицы мертва.
Первая строка `snapshot()` для мест 1 / 2 (вершины / индексы, не `snap_no_sync`): диапазон внутри годного статического буфера →
копия буфера (делается при первом draw, в чанках по 16 МБ, бюджет `DM_NR_BUF_MB` = 192), один `VkBuffer` на чанк, смещение внутри.
Страж — трекер грязных страниц (`nvn_dirty.c`, как у `vcache`): метка, защита, потом копия; в первой привязке каждой эпохи
`nvn_dirty_since` — запись после копии → буфер **понижен** на старый путь навсегда (красная строка). Запись CPU в потоке / writeback
GPU поверх → понижение. Pending-writeback над диапазоном → эта привязка старым путём. Над бюджетом → старый путь, повтор через 600 подач.

### 2.3 Политика (`xbg_vendor_policy.h`) — по возможности, не по семейству
`xbg_nr_buf_ring_inplace(zc) = zc`, `xbg_nr_buf_static_default(zc) = !zc`. С zero-copy (Adreno): кольцо на месте, статика выключена
(старый путь и так привязывает гостевую память без копии; копия добавила бы только память). Без zero-copy: зеркало + статика.

## 3. Переключатели (все — умолчание 0 / авто; игрокам не выдаются; нужен `DM_NR=1` или `2`)
| | значение |
|---|---|
| `DM_NR_BUF` | 0 — ничего (строка в `uniform_snapshot` / `snapshot` / `snapshot_invalidate` = загрузка + неиспользуемая ветка; хост не шлёт событий); 1 — вкл. по возможности; 2 — новое строится, рисуется старое, байты сравниваются (кольцо: блок; статика: привязанный диапазон против памяти гостя; ≤ `DM_NR_BUF_CMP_KB` = 1024 КБ на подачу) + хэш создания статического буфера против его байт на первом draw («записан между созданием и первым draw») + что сделал старый путь (zero-copy / sticky / фронт / карта / vcache / скопировано); 3 — как 1, зеркало заполнено 0xFF (NaN), пока гранула не скопирована |
| `DM_NR_BUF_RING` | 0 выкл., 1 авто, 2 зеркало даже с zero-copy (A/B на Adreno), 3 только на месте |
| `DM_NR_BUF_STATIC` | 0 выкл., 1 авто, 2 вкл. даже с zero-copy |
| `DM_NR_BUF_MB` | бюджет копий статики (192) |
| `DM_NR_BUF_CMP_KB` | сверка режима 2 на подачу (1024) |

Строки: `[nr] DM_NR_BUF=… (NR-06: …) ring mirrored|in place|off, static …`, `[nr] buf: constant ring at … handed to the engine` (хост),
`[nr] buf: constant ring … mirrored into one … MB buffer` / `served in place`, раз в 10 с `[nr] buf: DM_NR_BUF=…, N submissions; ring (…): M of K
uniform binds in the ring, served S; old path: …; mirror copied X MB / Y copies per submission, compared …, CPU-write holds …, ring advanced
Z MB per submission; decision … ns; static: … binds, served …; old path: not an engine buffer …, dynamic …, no-init …, demoted …, no budget …;
… copies live in … MB; demoted: CPU write …, dirty …, pool gone …; checks: ring … / … bad, static … / … bad, written before first draw … of …;
old path took …` и хостовая `[nr] buf (DM_NR_BUF=…): ring at …, … buffer events …`. Красные `【红】[nr] buf: …` — первые 16.

## 4. API для NR-08 (дескрипторы с динамическими смещениями)
В шапке `xbg_nr_buf.inc`: `nrbuf::ring_vk()` — тот самый `VkBuffer` (зеркало или чанк zero-copy, если кольцо целиком в одном; иначе null);
`nrbuf::ring_slack(off)` — сколько байт дескриптор может охватить от смещения (у зеркала 64 КБ запаса за концом кольца, т.е. набор
можно писать один раз с `range = 64 КБ`); `nrbuf::ubo(a, copy, z)` — 1: `z.buffer == ring_vk()`, `z.offset` выровнен по
`minUniformBufferOffsetAlignment` = динамическое смещение; 0 — старый путь; 2 — режим сверки. Только поток трансляции.
NR-08 может держать один UBO-набор на раскладку и менять только смещения; набор не нужно переписывать при смене подачи (буфер один на
весь запуск; `memo_epoch` двигается только при пересоздании зеркала — смена кольца, финал его пула).

## 7. Риски (честно)
1. Ни строчки не исполнено на устройстве. NR-01 тоже (хуки — условие NR-06).
2. Статика держится на «статический буфер не пишется после создания» (план §6 п. 4): режим 2 это меряет (`written before first draw`,
   `static … bad`), режим 1 страхует трекером, но трекер страничный: соседняя запись на той же странице (динамический буфер в той же
   странице) понижает буфер ложно — только потеря выигрыша, не картинки. Защищённые страницы — те же VMA-риски, что у `vcache`.
3. Ложная статика при пропущенном удалении (`destroys not found` NR-01): защищают трекер, правило «новый буфер поверх» и финал пула; без
   трекера (нет `nvn_dirty_*`) — только они.
4. Зеркало: при обходе кольца быстрее, чем уходят 2 слота (меню?), гранулы идут старым путём (`race`, `hold` в строке) — правильно, но
   без выигрыша; сравнение «в полёте» читает зеркало (на Mali WC-память, медленное чтение) — объём виден как `compared … MB`.
5. Голова кольца в режиме 2 читается как u32-смещение (`ring advanced`) — только диагностика; если это указатель, число будет бессмысленным.
6. Общие файлы: `hle_nvn.c` (тап буфера получил `mem`: строка `NRT(dm_nr_tap_buffer(o, o->size, o->mem))` + тест), `xbg_game.cpp`
   (7 однострочных точек), `xbg_nb_mx.inc` (+1 предвключение), `nb_tap_test.py`, `source_structure_test.py`. Конфликт возможен с NR-05,
   если тот тоже меняет `nvn_nr_tap.h`.
7. Память: на устройствах без zero-copy +19.5 МБ зеркала и до 192 МБ статики; на слабых 6–8 ГБ телефонах бюджет, возможно, стоит
   уменьшить — `copies live in … MB` в строке покажет реальный объём.

## 8. Что не сделано
- Динамические буферы (класс 5, пишутся в отображение) — остались на zero-copy / снапшоте (по плану).
- Вершины / индексы на Adreno через статику (выключено политикой; `DM_NR_BUF_STATIC=2` для A/B — сколько sticky-промахов уходит).
- Отложенное удаление `0x91d5c0` не перехвачено (как в NR-01).
- APK не собирался (gradle + драйверы); собрана только нативная `libdm.so` (см. отчёт ветки).

## 9. Прогон телефона, который это подтвердит (один заход, главный агент, по разрешению хозяина)
APK из ветки; бэкап `files/save`; keyguard снят; без лимита кадров. Сцена: палуба корабля 60 с + (если можно) Форт Радость / бой —
палуба одна не представительна.
1. **Сверка Adreno-пути:** `DM_NR=1 DM_NR_BUF=2`. Ждём: `[nr] buf: constant ring at … handed`, `served in place`; в `[nr] buf:` —
   `M of K uniform binds in the ring` (доля кольца среди 5.85 тыс.; ожидается ≫ 2.3 тыс. NB-12), `checks: ring N compared / 0 bad`.
2. **Сверка Mali-пути на Adreno:** `DM_NR=1 DM_NR_BUF=2 DM_GFX_ZEROCOPY=0` (или `DM_GFX_SIM_GPU=mali`). Ждём: `mirrored into one 19.5 MB
   buffer`, `ring … 0 bad`, `race 0`, `hold` ≈ 0; `static: … served …, 0 bad`, `written before first draw 0 of N`, `demoted: dirty` мало;
   `mirror copied` ≈ `ring advanced` (≈ 0.45–0.6 МБ на подачу); `old path took … copied … MB`.
3. **Цена (ABBA × 2, 60 с):** `DM_NR=1 DM_GFX_ZEROCOPY=0` против `DM_NR=1 DM_GFX_ZEROCOPY=0 DM_NR_BUF=1`; затем `DM_NR=1` против
   `DM_NR=1 DM_NR_BUF=1` (Adreno как есть). Смотреть `parts_ms_per_frame snapshot` (нужен `DM_NB_MT=0` в `dm/env` — с `MT=3` части
   draw не меряются), `submit_cpu_ms`, `snap_mb_per_frame uniform`, `zerocopy hits`, fps / GPU мс одинаковы, скриншоты равны, мерцаний
   нет. Режим 3 (`DM_NR_BUF=3` + `DM_GFX_ZEROCOPY=0`): картинка как в 1 — пропущенных копий нет.
Умолчание менять (по детекту в `xbg_vendor_policy.h`) — только при `0 bad` и выигрыше; для MTK / Mali нужен лог игрока / тестера.
