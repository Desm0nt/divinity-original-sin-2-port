## 2. Что сделано
### 2.1 UI-полоса NR-09 (`xbg_nr_draw.inc`)
- **Идентичность.** Обычные записи draw (`OP_DRAW` / `OP_DRAW_IDX` в `execute()`) при `DM_NR_UI` ставят `nrdraw::ui_rec` на время своего
  `draw()`; строка полосы в `draw()` (та же единственная строка NR-09 после `create_pass`) спрашивает `ui_pick()`, если у draw нет
  идентичности записи. `ui_pick` берёт draw, чей фрагментный шейдер — программа Iggy (`nb_ui.h`: iggy `d99f1fdb`, заливка `b5afd82f`,
  размытие `5e26ce73`; класс смотрится один раз на шейдер — `Shader::nrui`), и даёт ему **синтетическую идентичность**: ключ 0 (строка 0
  прямой таблицы NR-07 — id ключей NR-02 начинаются с 1), набор текстур 0, место `NRD_SITE_UI` (0xfe; мест NR-02 24).
- **Почему одна строка точна.** Вариант NR-09 содержит всё, от чего зависит пайплайн старого пути (шейдеры, раскладка, проход, слова draw,
  шесть id групп NB-13b), ключ только выбирает строку; строка — список с переносом в начало. Тест: 400 000 draw движка + 13 % UI в
  строке 0 — 0 неверных пайплайнов, попадания движковых строк **те же, что без UI**; мутация «вариант игнорируется» в строке 0 — 19 137
  неверных из 20 000 (ловится).
- **uiarea (`DM_NB_UIAREA`, по умолчанию 1).** NR-09 отдавал старому пути любой draw в проходе Iggy. Теперь `nr_ui_area` (`nr_draw.h`):
  draw Iggy в проходе Iggy, который uiarea ведёт как открытый и который **не начат уменьшенной областью**, обслуживается, и полоса зовёт
  полный `uiarea::pre` — как старый `draw()`: прямоугольник draw входит в объединение прохода (затравка области следующего кадра), заливки
  считаются. Перезапустить проход `pre` может только у уменьшенного прохода — такие остаются старому пути (их в кампании 0.00 / кадр:
  проход UI начинается с clear, фильтры — с первого draw). Для draw движка решение то же, что у NR-09 (тест сверяет все 32 входа).
- **QUADS.** `DrawArrays(QUADS)` Iggy старый путь разворачивает в u32-список `4q + {0,1,2,0,2,3}` (первая вершина уходит в vertexOffset)
  и копирует его в поток на каждый draw — новая привязка индексов на каждый draw. Список от draw не зависит: полоса привязывает **одну
  копию на подачу** (`QP`, растёт удвоением от 6 144 индексов, ≤ 1.5 М; больше → старый путь), кэш привязок убирает остальные. Тест: для
  4 000 длин список `xbg_quad_plan` (слинкован как есть) равен префиксу шаблона байт в байт. Разворот в преамбуле `draw()` остаётся
  (он нужен старому пути при отказе).
- Всё остальное — путь NR-09 без изменений: те же отказы до первой команды (`NRW_*`), те же 8 команд, свёртки индексов / вершин, учёт
  прохода, `nbui`, `condr`, `pass_prof`; старый хвост учит таблицу (`done`). Ранний возврат `draw()` записи UI чистит `ui_end()` (как
  `stale()` после `OP_X_NR_DRAW`), чтобы взведённый `armed` не достался чужому draw.

живут в кольце и буферах GDraw).

Строки: старт `[nr] DM_NR_UI=… (NR-12: …)`; раз в 10 с `[nr] ui: DM_NR_UI=…; N Iggy draws (plain records; fill …, blur …), A asked
nr_draw, served S (…%); old path: <причины>; table row 0: learned …; vkCmd* a served draw X (pipeline, set, vertex, index, viewport, scissor);
QUADS draws Q on the submission's index pattern (P patterns made, KB); folds …; uiarea: full step in Iggy passes F, short …; T ns a served
draw after create_pass`; режим 2: `[nr] ui check: C Iggy draws compared with the old tail, bad B (pipeline, vertex bindings, vertex fetch,
index fetch / quad list, viewport, scissor); predicted but the old tail did not finish the draw …`. Строки печатает `nbdraw::tick` (нужен

## 5. Ожидаемый выигрыш (оценка, не замер)
Цена draw UI на трансляторе сейчас: полный `draw()` ≈ 6.6 мкс (Mi 14; секции `draw_sections` кампании) + разбор 8–10 записей NVN.
Обслуженный draw (после `create_pass`): таблица + 1–2 `snapshot()` + свёртки + 2–3 команды ≈ 1.1–1.4 мкс против ≈ 3.0 (`pipe + vtx +
bind + tail`), у QUADS ещё минус копия списка в поток. `desc` UI (≈ 3.4 мкс) снимает **NR-08**, не NR-12 (UBO UI в кольце).
Обслуживаемых: draw прохода, кроме первого: кампания ≈ 147 − 18 = **≈ 129 из 147** (без уменьшенных проходов: их 0).

Модель `vkCmd*` на draw UI (`nr_ui_test`, 150 draw / кадр, набор с новыми смещениями на каждом draw — как у GDraw):
| Поток | старый хвост | UI-полоса | VB | IB |
|---|---|---|---|---|
| QUADS, вершины в кольце, stride 16 / 8 (zero-copy: кольцо = один VkBuffer) | 4.49 | **2.50** | 1.00 → 0.01 | 1.00 → 0.01 |
| QUADS, stride 20 | 4.49 | 3.46 | 1.00 → 0.96 | 1.00 → 0.01 |
| индексные формы, zero-copy, 4 чанка | 4.47 | 4.00 | 1.00 → 0.76 | 1.00 → 0.76 |
| индексные формы, копии снапшотов (свой буфер у каждой) | 4.51 | 4.46 | 0.97 | 0.97 |

Доля QUADS / индексных draw и stride Iggy неизвестны (печатает `[nr] ui`). Без zero-copy (Mali / MTK / PowerVR) вершины в кольце идут
через арену снапшотов (новое смещение на draw) — свёртка вершин там ≈ ничего не даёт, остаётся выигрыш по IB.

| Класс | Что меняется (кампания, ≈ 129 draw UI) | Оценка |
|---|---|---|
| Mi 14 / Adreno 750 | −1.6…2.0 мкс на draw | **−0.2…0.26 мс** транслятора; fps — нет (упор в GPU): тепло |
| S7 (Adreno 7xx) | то же ×1.5–2 | −0.3…0.5 мс |
| MTK / Mali, Xclipse, PowerVR (без zero-copy) | CPU ×3: −5…6 мкс на draw; команд −1 (IB у QUADS) при 1.2–1.8 мкс за вызов | **−0.7…1.0 мс** [м]; тяжёлые экраны UI (инвентарь, торговля) — пропорционально числу draw Iggy, не мерено |
| GPU, тайлеры | те же проходы и команды | 0 |

С NR-08 (`DM_NR_DESC=1`) UI-draw теряет ещё ≈ 2.8 мкс (Mi 14) / ≈ 8 мкс (MTK) на `desc` — это выигрыш NR-08, в котором UI просто
участвует. Меню 3D-сцены (2 100 draw) — NR-08 + NR-09: по их оценкам транслятор меню 13 мс → ≈ 5–6 мс на Mi 14.

## 6. Риски (честно)
1. **Не исполнено на устройстве.** Ни одна строка `DM_NR_UI` не работала на телефоне.
2. Класс шейдера — по префиксу ключа трёх фрагментных шейдеров Iggy (как у uiarea / nbui). Программа Iggy с другим ключом просто не
   берётся (старый путь). Ошибка в обратную сторону безопасна: вариант точен, а полный шаг uiarea — тот же вызов, что старый `draw()`.
3. Полный `uiarea::pre` в полосе опирается на то, что не уменьшенный проход он перезапустить не может (код `pre` сейчас такой). Если в
   uiarea появится решение по другим проходам / перезапуск без `reduced` — `nr_ui_area` надо поправить (тест и структурный тест укажут место).
4. Шаблон QUADS живёт в арене потока подачи (`slot_serial`); новая подача — новый шаблон (24 КБ записи на подачу, ~1 подача на кадр).
   Список старого пути и шаблон равны по построению (тест) и сверяются в режиме 2 на каждом draw.
5. Полоса повторяет учёт старого хвоста вручную (риск 2 NR-09) — для UI добавлен только вызов `uiarea::pre`.
6. Строка `[nr] ui` печатается из `nbdraw::tick` — без `DM_NB=1` (не умолчание никогда не бывает) строк не будет, работа идёт.
7. Общие файлы: `xbg_game.cpp` (5 мест), `xbg_nr_draw.inc` (поверх NR-09), `nr_draw.h`, тесты.

## 7. Не сделано (и почему)
- Перехват входов GDraw на потоке игры / своя запись UI вместо записей NVN: выигрыш ≈ 0 (вызовы остаются), риск — порядок с записями
  состояния вне скобки (§1).
- Фильтры / RT / барьеры UI: это проходы и барьеры (NR-10); их GPU-часть — uiarea.
- Загрузки и буферы GDraw: событийные, цифр нет — решает `UI block` / места `ui` в `[nb] foreign` (R-NR12a).
- Вершины UI в кольце через зеркало NR-06 на устройствах без zero-copy (одна привязка VB вместо новой на каждый draw QUADS): нужен
  вершинный вид `nrbuf` (сейчас зеркало обслуживает только блоки констант, границы 256 Б); делать, если `[nr] ui` покажет долю QUADS
  большой, а `vertex` ≈ 1.0 в R-NR12b.
- Первый draw прохода, проходы с уменьшенной областью, draw с `gl_VertexIndex` — старый путь (как NR-09). Умолчание по детекту — после
  прогонов (функции политики не добавлял).

   `old path` в основном `not the open pass` (≈ число проходов Iggy) и `table miss` (к нулю за секунды), `uiarea pass` ≈ 0;
   **`[nr] ui check: … bad 0`** по всем видам; `QUADS draws` — доля. `[nb] foreign`: `UI block r/d` и места с тегом `ui` — решают судьбу
   загрузок / буферов GDraw. Картинка — как без флагов.

   вершинный вид зеркала, §7).
3. **R-NR12c, включено:** `DM_NR_UI=1` (оба варианта zero-copy; затем вместе с `DM_NR=1 DM_NR_BUF=1 DM_NR_DESC=1 DM_NR_DRAW=1`).

   `parts_ms_per_frame draw` падает на ≈ 0.2 мс в кампании; скриншоты HUD / инвентаря / фильтров / размытия / тач-кнопок равны;
   `DM_VK_VALIDATION=1` в первом прогоне — без ошибок привязок индексов.
4. **Цена (ABBA × 2, 60 с, инвентарь открыт и кампания):** `DM_NR_UI=0` против `1`; `submit_cpu_ms`, `parts_ms draw`, температура.
