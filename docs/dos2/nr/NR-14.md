# NR-14 `DM_GFX_SAMPLES_TS=0` — мёртвые отчёты samples (сегмент S7)

Ветка `dos2-nr14` (worktree `wt-nr14`, база `dos2` 94d287d). На телефоне **не запускалось**. Шаг из `AUDIT-REMAINING.md` (ветка
`dos2-nraudit`) §1. В отличие от обычного правила «умолчание 0 = старое поведение», здесь по заданию меняется **умолчание DOS2**:
переключатель уже существовал (`DM_GFX_SAMPLES_TS`, VERTEX.md §5.1), новый режим 0 — его значение, а не новый `DM_NR_*`.

## 1. Кто читает отчёты samples (проверено)

| Читатель | Факт | Источник |
|---|---|---|
| CPU игры | указатель CPU буфера счётчиков `dev+0x25ac8` (128 КБ, `0x932900`) в `main` встречается в 3 местах: обнуление при уничтожении `0x9382bc`, создание `0x938e40`, и `BeginFrame 0x92168c` — там только **запись** пред-заливки `{0, -1}` (`stur xzr / x11`, шаг 16 Б, `0x9216b0…0x9216cc`). Объект буфера `+0x25ae8` — только при создании (`0x938edc`, два вызова через таблицу функций NVN, результат второго — адрес GPU); адрес GPU `+0x25b18` — только постройка таблицы пар (`0x938f08`, `0x938ff0`). Загрузок содержимого буфера на CPU нет | скан `main.raw` (capstone, все `movz #0x5aXX; movk #2, lsl 16`), этот шаг; NR-03.md §1 |

| Хост (condr) | только при `DM_GFX_COND_RENDER≠0` (по умолчанию 0: условие даже не пишется в поток) | `xbg_game.cpp` namespace `condr` |
| Хост (NR-03) | при `DM_NR_OCC≠0` пары — свои запросы Vulkan; старые отчёты он сам выбрасывает (`DROP=1`) | `dos2-nr03:xbg_nr_occ.inc` |
| Чтения хоста по адресам отчётов | `rc1.dm.log`: `why=…a0(0,0,…)` (`access_by[7]` = 0 — ни один in-stream доступ не задел ждущий отчёт), `texel … fallback=0.00` | лог телефона 17.11 |
| Сегодняшнее содержимое | счётчик хоста при `COND_RENDER=0` не считает (`count_samples=false`, игра не делает ResetCounter) → в память всегда писалось `{0, ts}` | `condr` комментарий, `init_counting` |

Вывод: при `COND_RENDER=0` и без NR-03 у 526 отчётов на кадр нет читателя. Метка `TIMESTAMP_TOP` / `TIMESTAMP` для DRS (NB-18b-11,
6303037) — другой тип (`NVN_COUNTER_TYPE_TIMESTAMP` после замены), путь NR-14 его не трогает. Без записи в память игры там остаётся
пред-заливка игры `{0, -1}`, то есть пара читалась бы «не равно» = рисовать — то же, что Switch видит у видимого объекта.

### `DM_GFX_SAMPLES_TS`
| Значение | Поведение |
|---|---|
| не задан, DOS2 | **0**, если нет потребителя (`DM_GFX_COND_RENDER` не задан / 0 и `DM_NR_OCC` не задан / 0); **4**, если есть |
| не задан, другие игры (D3 / TL2 — общий код) | 1, как раньше (D3 отсекает объекты по этим отчётам на CPU) |
| `0` | отчёт samples не записывается вовсе: ни штампа (WFI), ни `PendingReport` (ни `vkGetQueryPoolResults` на retire), ни записи 16 Б в память игры, ни конца прохода (при упавшем самотесте `report_inpass`). `GPASS rep=` его считает. Если хост всё же считает сэмплы (был ResetCounter → открыт прогон occlusion) — этот отчёт идёт как 4 |
| `1` | штамп BOTTOM_OF_PIPE на отчёт (старое) |
| `2` | TOP_OF_PIPE (старое) |
| `3` | сверка: как 1 + счётчики стража и красные строки «0 выбросил бы то, что это читает» |
| `4` | один штамп на проход (старое, VERTEX.md) |
| другое значение | 1 (строка лога «env value not 0..4») |

Значение из env побеждает всегда (0 тоже — A/B). Строка при старте:
`NVN samples-report timestamps DM_GFX_SAMPLES_TS=0 (auto: no consumer (DM_GFX_COND_RENDER=0, no DM_NR_OCC); …)`.

### Страж (режим 0 по умолчанию — значит, нужна автоматическая страховка)
Хост ведёт ограничивающий прямоугольник адресов всех увиденных отчётов samples (DOS2: один буфер 128 КБ, обе половины).
In-stream доступ к нему (`cpu_access` любого вида кроме 1 / 2 = снимки GPU; источник копии буфер→буфер — вид 12) в режиме 0 даёт красную
строку `【红】NVN samples reports: access … inside their range … the run switches to 4` и переключает прогон на 4 (до 16 строк;
`fallbacks=`). Снимки GPU (виды 1 / 2) только считаются (`snaps=`): они и сейчас видят последний записанный отчёт. Ошибки стража — только
в сторону безопасности (прямоугольник шире реальных пар → лишний откат на 4, не потеря данных). Не покрыто: чтение отчёта шейдером через
дескриптор (uniform texel / SSBO на этот буфер) — игра так не делает (§1), и `texel fallback=0` в логах.

## 5. Риски
- Низкий: данных отчёта никто не читает (§1); `TIMESTAMP_TOP` / DRS не задеты. Остаточный: неизвестный читатель через дескриптор
  шейдера (не ловится стражем) — по §1 его нет.
- `DM_GFX_SAMPLES_TS=0` вручную вместе с `DM_GFX_COND_RENDER≠0`: пары не пишутся → condr считает их «ещё не записанными» → рисует
  (безопасно, но condr ничего не отсекает). Авто-режим так не делает.
- После слияния с NR-03: его хук стоит на той же строке (`OP_REPORT_COUNTER`, после `need(...)`) — конфликт текстовый, тривиальный:
  NR-03 первым (`nrocc::report`), потом NR-14. При `DM_NR_OCC≠0` авто = 4.
- Счётчик `counter` в NB merge-blocker'ах (`nb_plan.c hz_why`, `NB_HZ_COUNTER`) не трогал: при мёртвых отчётах он мог бы не мешать
  слияниям проходов, но слияния сейчас выключены (аудит NR-15).
