# VK-NATIVE, карта интерфейса рендерера, часть 2: состояние, константы, текстуры, цели, draw

Статический разбор 45 функций нижнего слоя рендерера (объект `r`, глобальный указатель `[main+0x2bbdc68]`) сборки для Switch. Игра не запускалась, ничего не менялось. Источник: декомпиляция Ghidra в папке `scratchpad\vk\re\out\<адрес>.c`, таблица `nvn_slot_map.tsv`, список `nvn_by_function.txt`.

Пометки:

- **[бин]** — прочитано прямо из декомпиляции.
- **[выв]** — вывод или догадка.

Смысл числовых значений перечислений NVN (номера стадий, биты программ, режимы глубины и начала координат, функция альфа-теста, флаги текстур) взят по памяти из заголовков NVN, поэтому всюду считается **[выв]**.

Обозначения: `dev = [r+0xb70]`, буфер команд `cb = [dev+0x5248] + 0x38`, счётчик кадров `[dev+0x51f0]`. Дескриптор движка — 64 бита: младшие 32 бита индекс, биты 32..53 поколение.

## 0. Что расходится с исходным описанием или дополняет его

1. **Стадий три, а не две.** Массивы ячеек текстур и сэмплеров есть для стадий NVN 0 (вершинная), 1 (фрагментная) и 5 (вычислительная), по 32 ячейки на каждую [бин].
2. **Вершинная и фрагментная части — две отдельные программы NVN.** Вызовы `BindProgram(rec[1], биты=1)` и `BindProgram(rec[2], биты=2)`; вычислительная — `rec[3]` с битами `0x20` [бин].
3. **Общие блоки констант привязываются только в момент повторной выгрузки** (блок грязный или первый раз используется в кадре), сразу к стадиям 0, 1 и 5. Расчёт на то, что привязки NVN переживают смену программы [бин].
4. **Блоки шейдера выгружаются заново минимум раз за кадр**, даже если не менялись, и привязываются заново при каждой отрисовке [бин].
5. **Смена одного только сэмплера не сбрасывается в NVN.** Сброс текстур обходит только грязный диапазон текстур; грязный диапазон сэмплеров ведётся, но нигде не читается [бин].
6. **Смешивание принудительно включено для каждой привязанной цветовой цели.** «Без смешивания» должно быть выражено функциями смешивания [бин].
7. **Маска записи цвета выводится только из формата цели отрисовки.** Аргумент `mask` функции `9284e0` только запоминается и нигде не применяется [бин].
8. **Соглашения совпадают с Vulkan без преобразований.** Инициализация устройства `0x938330` вызывает `nvnDeviceSetDepthMode(dev, 1)` и `nvnDeviceSetWindowOriginMode(dev, 1)` [бин]; читаю это как глубину 0..1 и начало координат в левом верхнем углу [выв]. У `nvnCommandBufferSetDepthRange` ноль мест вызова во всём файле (по таблице слотов) [бин]. Значит, переворот по вертикали и пересчёт глубины не нужны.
9. **`930210` не использует смещение в динамическом буфере индексов.** В `DrawElements` передаётся базовый адрес буфера индексов, хотя `928dd0` вернула смещение (оно только кладётся в `r+0x17d0`) [бин]. **Открытый вопрос не закрыт:** декомпиляции `928dd0` в папке `out` нет (нет и `930850`), прочитать её не удалось. Перед тем как полагаться на это поведение, `928dd0` нужно декомпилировать отдельно: возможно, она всегда пишет с начала буфера и возвращает ноль.

## 1. Общие структуры

### 1.1. Пулы в `r`

Каждый пул: массив страниц / массив поколений / размер страницы. Запись находится как `страницы[индекс / размер][индекс % размер]`, поколение сверяется с битами 32..53 дескриптора.

| Пул | Смещения (страницы / поколения / размер страницы) | Размер записи | Поля |
|---|---|---|---|

| Шейдеры | `+0xc0` / `+0xc8` / `+0xd0` | `0x60` | см. 1.3 |
| Буферы вершин | `+0x180` / `+0x188` / `+0x190` | `0x68` | `[0]` не ноль, если жив; `+8` адрес на видеопроцессоре; `+0x10` указатель в обычной памяти; `+0x38` кадр; `+0x40` размер |
| Буферы индексов | `+0x240` / `+0x248` / `+0x250` | `0x58` | `+8` адрес на видеопроцессоре; `+0x18` кадр; `+0x24` тип индекса NVN; `+0x28` размер индекса |
| Буферы хранения | `+0x300` | — | `[0]` кадр; `[+8] × [+0xc]` = размер в байтах; `+0x18` адрес на видеопроцессоре |
| Именованные ресурсы текстур | `+0x3c0` / `+0x3c8` / `+0x3d0` | `0x20` | `+8` дескриптор текстуры |
| Форматы вершин | `+0x480` / `+0x488` / `+0x490` | `0x80` | `+0x18` / `+0x1c` не ноль, если используется поток 1 / 2; `+0x20` 16 состояний атрибутов; `+0x60` состояния потоков (в них шаг вершины) |

| Растеризация | `+0x780` / `+0x788` / `+0x790` | `0x18` | `+8` `NVNpolygonState` |

### 1.2. Объект текстуры [бин]

- `+0x0` — `NVNtexture` (занимает `0xc0` байт).
- `+0xc0` — номер текстуры в пуле текстур NVN.
- `+0xc4 + 4·i` — номера отдельных видов (−1 = нет).
- `+0x100` — собственный номер сэмплера (меньше нуля = нет).

### 1.3. Запись шейдера (`0x60`, указатель на текущую в `r+0x17e0`) [бин]

| Смещение | Содержимое |
|---|---|
| `+0x00` | кадр последнего использования |
| `+0x08` | вершинная программа NVN |
| `+0x10` | фрагментная программа NVN |
| `+0x18` | вычислительная программа NVN |
| `+0x20` / `+0x28` / `+0x30` | массивы блоков констант: вершинная / фрагментная / вычислительная стадия (записи по `0x40`) |
| `+0x38` / `+0x39` / `+0x3a` | число блоков в каждом массиве (u8) |
| `+0x40` | хеш-таблица констант (имя → смещения в блоках) |
| `+0x48` | хеш-таблица ресурсов (имя → ячейки текстур, изображений, буферов хранения) |

### 1.4. Хеш-таблицы [бин]

Число корзин в `+4`, массив корзин в `+8`. Индекс корзины = (хеш, либо `0x1f77c8c`, если хеш равен нулю) по модулю числа корзин. Узел: `{следующий, ключ, полезные данные с +0x10}`.

- **Узел константы:** u16 смещения в блоке для вершинной / фрагментной / вычислительной стадии в `+0x10` / `+0x12` / `+0x14` (`0xffff` = в этой стадии нет); u16 номера блоков в `+0x16` / `+0x18` / `+0x1a`.
- **Узел ресурса:** s8 номера ячеек для вершинной / фрагментной / вычислительной стадии в `+0x10` / `+0x11` / `+0x12` (меньше нуля = нет); s32 номер сэмплера в `+0x14`.

### 1.5. Блок констант (`0x40`) [бин]

| Смещение | Содержимое |
|---|---|
| `+0x00` | отметка кадра последней выгрузки |
| `+0x10` | адрес на видеопроцессоре (внутри кольца) |
| `+0x18` | указатель в обычной памяти внутри кольца (0 = ни разу не выгружался) |
| `+0x20` | теневая копия в обычной памяти |
| `+0x28` | максимум использованного размера с последней выгрузки |
| `+0x2c` | предыдущее значение этого максимума |
| `+0x30` | размер блока |
| `+0x34` | признак «грязный» (u8) |
| `+0x35` | номер привязки (u8) |

### 1.6. Дополнительные поля кеша в `r` [бин]

- `+0x171c` — область вывода `{ширина, высота, x, y}` (`+0x171c`, `+0x1720`, `+0x1724`, `+0x1728`).
- `+0x1718` — примитив в виде значения NVN (движковый — в `+0x1714`).
- `+0x1750` / `+0x1758` — буферы вершин 1 / 2.
- `+0x1788..` — смещения по ячейкам буферов вершин.
- `+0x17d0` — первый индекс.
- `+0x1854` / `+0x1858` — размер цели отрисовки.
- `+0x185c` / `+0x185d` — запрет отрисовки: текущий / предыдущий признак; `+0x1860` — связанный запрос.
- `+0xb78` — признак «привязана вычислительная программа».
- `+0x8a8..+0x8c8` — текстуры по умолчанию.
- `+0x8d0` — динамический буфер вершин (кольцо 1 МиБ, голова в `+0x8d8`); `+0x8e0` — динамический буфер индексов.
- `+0x8f0`, `+0x8f8`, `+0x900`, `+0x908` — встроенные шейдеры; `+0x910`, `+0x918`, `+0x920`, `+0x928` — встроенные форматы вершин; `+0x930` — 16 байт константы для двумерных отрисовок.
- `+0x888` — объект камеры; `+0x890` — объект вида; `+0x870` — время (double); `+0x898` — флаг.
- `+0xbe0` — блокировка списка общих блоков, `+0xbe4` — поток-владелец; `+0xbf8` — массив указателей на общие блоки, число = `([r+0xc00] >> 24) & 0xffffff`.
- `+0xdb0` / `+0xdb8` — дескрипторы двух общих блоков (вид и камера); их данные собираются в `r+0xc40` и `r+0xcc0`.

Каждое использование ресурса записывает текущий счётчик кадров `[dev+0x51f0]` в его запись [бин].

### 2.1. Подробности `925740` [бин]

- **Условие выгрузки:** номер привязки меньше 8 и (блок грязный или отметка кадра не равна текущему кадру).
- **Выделение из кольца** под блокировкой `dev+0x25aa8` (бит записи `0x100000`; ожидание — до 400 попыток с уступкой потока, затем системный вызов):
  1. голова (`dev+0x25a60`) выравнивается вверх до 256;
  2. если голова + размер ≥ `0x1380000`, голова = 0;
  3. смещение = голова; голова += размер.
  Проверки на перезапись ещё используемых данных нет.
- **Копирование:** весь размер блока (`+0x30`) из теневой копии по адресу `[dev+0x25a98] + смещение`. Затем `+0x10 = [dev+0x25aa0] + смещение`, `+0x18` = указатель в обычной памяти, признак «грязный» = 0, `+0x2c = +0x28`, `+0x28 = 0`, отметка = текущий кадр.
- **Проход привязки, при каждом вызове:** для каждого блока с `+0x18 ≠ 0` и номером меньше 8 — `nvnCommandBufferBindUniformBuffer(cb, стадия, номер, адрес, размер)`; стадия 0 для вершинного списка, 1 для фрагментного, 5 для вычислительного.
- Вершинный и фрагментный списки — разные блоки с разными теневыми копиями, поэтому один и тот же логический блок выгружается дважды.
- [выв] Блоки шейдера с номером привязки 8 и больше — заглушки под общие блоки.

| К каким стадиям | к своей (0, 1 или 5) | ко всем трём сразу |
| Проверка номера привязки | меньше 8 | нет |

### 4.1. Блок `92c3c0` [бин]

| Смещение | Поле |
|---|---|
| `+0x00` | шейдер |
| `+0x08` | состояние глубины и трафарета |
| `+0x10` | опорное значение трафарета |
| `+0x18` | растеризация |
| `+0x20` | смешивание |
| `+0x28` | формат вершин |
| `+0x30` / `+0x38` / `+0x40` | буферы вершин 0–2 |
| `+0x48` | буфер индексов |
| `+0x50` | примитив (u8) |

Порядок применения:

- **Шейдер:** `9283a0`.
- **Глубина и трафарет** (при смене дескриптора или опорного значения): `nvnCommandBufferBindDepthStencilState`, `SetStencilMask(3, маска)`, `SetStencilValueMask(3, маска)`, `SetStencilRef(3, опорное)`; грань 3 = лицевая и обратная [выв]. Одна и та же маска идёт и на запись, и на сравнение.
- **Растеризация:** `nvnCommandBufferBindPolygonState`.
- **Смешивание:** `9284e0` с маской −1.
- **Формат вершин:** `nvnCommandBufferBindVertexAttribState(16, rec+0x20)` и `nvnCommandBufferBindVertexStreamState(n, rec+0x60)`; n = 3, если `+0x1c ≠ 0`, иначе 2, если `+0x18 ≠ 0`, иначе 1.
- **Буфер вершин i:** `nvnCommandBufferBindVertexBuffer(cb, i, адрес, размер)` при смене дескриптора или ненулевом запомненном смещении; потоки 1 и 2 — только когда дескриптор не ноль. Шаг вершины берётся из состояния потока, а не из этого вызова. После привязки смещение в кеше обнуляется.
- **Буфер индексов:** только запоминается (`r+0x17c8`, `r+0x17d0 = 0`), ставится отметка кадра.
- **Примитив:** `r+0x1714`, переводится через таблицу `0x1f58640[примитив−1]` (7 записей) в `r+0x1718`; вне диапазона — 0.

### 4.2. Область вывода, ножницы, глубина

- Кеш `{ширина, высота, x, y}` в `r+0x171c..+0x1728`; вызовы `nvnCommandBufferSetViewport(cb, x, y, ширина, высота)` и `nvnCommandBufferSetScissor` с теми же числами [бин] (то же видно во внешнем вызывающем `ab50e0`).
- Переворота по вертикали в коде нет [бин]; начало координат — левый верхний угол [выв, по `SetWindowOriginMode(1)`].
- Диапазон глубины не задаётся нигде [бин]; режим глубины 0..1 [выв, по `SetDepthMode(1)`].
