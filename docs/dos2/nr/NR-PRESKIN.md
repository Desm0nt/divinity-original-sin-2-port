# N7 NR-PRESKIN — предскиннинг для слабых Mali / PowerVR (ночь 19.11.2026, ветка `dos2-npreskin`)

Задача координатора (после N1 NR-NSHADER §11.1): скиннинговые меши затеняются вершинным шейдером по 1.5–4 раза за кадр (3 каскада теней,
пре-пасс, G-buffer, FX); на Adreno 750 весь скиннинг стоит 0.05–0.14 мс (не трогаем), на Mali G57 VS скиннинга ≈ 50 циклов LS на вершину
(кости грузятся в обоих вариантах IDVS) — верхняя граница модели ≈ −2.5 мс на G57 MC2. Сделать: проход скиннинга один раз за кадр на
экземпляр меша, варианты VS, читающие готовое, ключ «палитра костей + вершины», доказательство бит в бит интерпретатором на настоящих VS пака,
`DM_NR_PRESKIN` 0 / 2 счёт / 1, умолчание 0, память по NR-29, Adreno выключен. Телефона не было: ниже — пак, офлайн-компиляторы, хост-тесты.
[м] = модель.

## 0. Коротко
- **Сделано и собрано** (`DM_NR_PRESKIN` 0 везде / 2 счёт / 1 применить / 3 яд). Вместо «compute + свой код скиннинга» — **сам VS игры,
  разрезанный пополам** по минимальному разрезу графа значений: **слайс** (те же инструкции в том же порядке, что считают скиннинг, пишут
  сырые 32-битные слова результата в буфер) и **потребитель** (тот же VS, где эти значения читаются как uint-атрибуты и bitcast обратно;
  весь код костей становится мёртвым и уходит). Слайс запускается **вершинным draw без растеризации** (POINT_LIST, rasterizer discard) по
  вершинам меша с **теми же вершинными буферами и форматами** — та же фиксированная выборка атрибутов, никаких своих переводов UNORM / half.
- **Где он стоит в кадре:** все слайсы подачи (submission) пишутся в её **пролог** (`Slot::pro`, тот же буфер команд, что уже шёл перед
  основным для загрузок / копий) и отправляются тем же `vkQueueSubmit` впереди. **Своего барьера нет**: основной буфер слота и так начинается
  с полного барьера ALL → ALL (`recording_slot`), он и упорядочивает записи пролога перед всеми draw. Входы слайса — только то, что CPU
  записал до отправки (вершины / UBO без ожидающих результатов GPU — проверяется), поэтому начальный барьер тоже не нужен: слайс может
  перекрыться с хвостом прошлого кадра. На Adreno — выключено навсегда (умолчание 0; там это минус).
- **Разрез у всех 2 001 скиннингового VS пака находится и проверяется:** 50 VS, которые встретились в сессии хозяина (play-1118, 252
  конвейера), — **все 50**; запись на вершину — **3 слова** (позиция после костей; все depth-VS: тени, пре-пасс) или **12 слов** (позиция +
  нормаль + касательная + знак касательной; G-buffer / FX). Кости (48 загрузок), блендинг весов и мировая матрица уходят из VS целиком.
- **Бит в бит (семантика SPIR-V):** интерпретатор (`tools/spv_interp.py`, каждый float-оп со своим округлением) — оригинал против
  «потребитель(входы, слайс(входы))» на **всех 2 001 VS × 3 цепочки загрузки** (Adreno / Mali + UBOVEC / Mali + retype входов) и 50 VS
  сессии × 8: **0 расхождений из 12 406 прогонов**, плюс 7 204 прогона «потребитель читает ЧУЖУЮ, более широкую запись» (общий хэш значения у
  разных VS — тоже бит в бит, 0 расхождений); spirv-val (vulkan1.1) — 0 ошибок на 21 701 модуле. Подкрашивание любого слова записи меняет
  выход (проверка чувствительности).
- **Цена [м, malioc 2026.5, цикл LS — узкое место]:** depth-VS G57 позиция 18.1 → **4.1**, varying 19.5 → **5.5**; G-buffer-VS позиция 18.3 →
  **6.2**, varying 27.2 → **13.2** (и регистры 64 / 50 % занятости → 32 / 100 %); слайс 18.1 (3 слова) / 21.0 (12 слов) на вершину меша. Форт
  (вершины N1): **≈ −5 М циклов / кадр ≈ −2.6 мс на G57 MC2** верхняя граница; с пре-пассом NR-30, который на тайлерах уже снят по
  умолчанию, — **≈ −2.0 мс верх, реалистично −1…−2 мс**; палуба TUT −2.6…−4.5 мс верх. Mi 14 — 0 (не включается).

## 1. Что было известно и что проверено заново
- N1 §11.1: скиннинговые VS = `_SK_` / ≥ 30 циклов malioc; вершины скиннинга за кадр Форт 305 k (тени 153 k / пре-пасс 45 k / G-buffer 74 k
  / FX 33 k), TUT 761 k; Adreno 750 — весь скиннинг 70.6 М слотов ≈ 0.05 мс (Форт) / 0.14 мс (TUT); G57 — верх −2.5 мс. Опасение N1:
  «на разных стадиях драйвер может сжимать mul+add по-разному» — снято устройством решения (§3.3): слайс — тоже вершинный шейдер, а сжатие
  выключено там же, где оно выключено у оригинала.
- Перепись проверена по пакету: в паке 6 132 VS, **2 001 читают UBO по индексу из вершинного входа** (Location 15 × 48 = 3 строки vec4 на
  кость). В списке конвейеров play-1118 — 252 скиннинговых конвейера (76 depth-only, 176 с цветом), **50 разных VS**, вершинные форматы:
  позиция `R16G16B16_SFLOAT` (0) / `R32G32B32_SFLOAT`, нормаль `R16G16B16A16_SNORM` (1), UV `R16G16_SFLOAT` (4), веса `R8G8B8A8_UNORM` (14),
  индексы `R8G8B8A8_UINT` (15); 1 или 3 потока, страйд 26 / 12 / 30.
- Форма модулей после цепочки загрузки телефона (fold / temps / canon / f2i, + UBOVEC на Mali): **все 2 001 — один базовый блок, без чтений
  Function-переменных**, один «костяной» UBO (`c[3]`, NVN-слот 0: кости 0..383, мировая матрица 384..387).

## 2. Что сделано
### 2.1 План — `dm/gfx/vulkan/engine/xbg_spirv_preskin.{h,cpp}` (C++ без Vulkan)
- Классы значений блока: **inv** — функция только Location-входов, UBO set 0 и констант (не встроенные, не образы, не push); **кость** —
  зависит от загрузки из UBO по индексу из вершинного входа. Граф: S → каждая такая загрузка, каждое не-inv значение и каждое
  записываемое в Output → T; inv-значение 32-битного скаляра / вектора стоит 64 на компонент (+1, если зависит от UBO, не костяного — так
  разрез избегает значений, которые меняет константа прохода), прочее не режется. **Минимальный разрез (Dinic)** = набор значений записи.
  Пример: depth-VS — 3 скаляра (позиция после костей и мировой матрицы, до view-proj `c[15]`), G-buffer-VS — 12 (3 из них зависят от знака
  касательной из `c[1]`).
- Каждому значению — структурный хэш (опкоды, типы, константы, Location входов, ключ данных UBO = `source << 16 | NVN slot`), маска его
  Location и UBO. Запись упорядочена по хэшу: у разных VS одно и то же значение = один хэш (у G-buffer-записи 3 из 12 слов — те же, что у
  depth-VS: «надмножество»).
- Отказ (с причиной) — не одна функция / блок, чтение Function-переменной, запись не в Output, неизвестная инструкция, другой набор ExtInst,
  нет конечного разреза, > 16 слов, нет свободных Location < 16, SPIR-V > 1.3. На паке отказов **0**.
### 2.2 Слайс и потребитель (там же)
- **Слайс:** из тела оставлены только предки значений разреза (в исходном порядке); выходы, образы, лишние входы удалены; добавлены
  `gl_VertexIndex` и SSBO (set 0, binding = максимальный + 1); в конце `data[gl_VertexIndex * m + c] = bitcast<uint>(значение)`.
  **NoContraction** на float-арифметике слайса, которая в оригинале питала `Invariant`-выход (`gl_Position`) — см. §3.3.
- **Потребитель (раскладка):** значения разреза читаются из uint / uvecN входов (группы ≤ 4 подряд идущих слов записи, самые нижние
  свободные Location), `OpBitcast` под исходным id; мёртвый код (кости, веса, мировая матрица) удалён, входы, которые больше не читаются, сняты
  с интерфейса. Раскладка задаётся позициями слов в записи (`pos`): своя запись — `vec4`-группы, чужая (надмножество) — по одному слову.
### 2.3 Таблица записей — `dm/gfx/nr/nr_preskin.h` (чистый C)
Запись = (ведро: идентичность костяного UBO, идентичности источника каждого Location и UBO-слота, прочитанных слайсом, m, nverts,
смещение в арене, значения с хэшами и масками листьев). Потребитель берёт запись, если **каждое** его значение там есть с тем же хэшем и
**все его листья** (атрибут + поток / диапазон UBO) те же, что связаны у этого draw сейчас, и записи хватает вершин. Идентичность атрибута:
формат, смещение, страйд, адрес / размер диапазона, VkBuffer + смещение снимка; UBO — адрес, байты, VkBuffer + смещение снимка (снимки одной
эпохи по одному адресу — один и тот же буфер). Арена — бамп на подачу (слот), сброс, когда слот снова пишет (его прошлая подача отработала).
### 2.4 Бэкенд — `dm/gfx/vulkan/engine/xbg_nr_preskin.inc` (namespace `nrps`)
- **Загрузка:** при `DM_NR_PRESKIN ≠ 0` у VS — признак кандидата (`Shader::psk`, `xbg_spirv_preskin_candidate`), слова модуля сохраняются.
- **`decide()`** в `draw()` сразу после `nrpo::decide` (перед полосой NR-09): код retype входов (как его посчитает `draw()`), план на
  (VS, код) — лениво, один раз; вход слайса — атрибуты Location из `slice_locs` (не инстансные, без ожидающих результатов GPU), число
  вершин по диапазонам потоков (≤ `DM_NR_PRESKIN_MAXV`), UBO-слоты (снимок тот же, что взял `descriptors()`; выравнивание проверено).
  Поиск в таблице подачи → своя / чужая запись, иначе новая: место в арене, конвейер слайса (кэш по раскладке входа, через `pipeline_cache`),
  набор дескрипторов (UBO + SSBO записи; наборы выделяются раз на (слот, план) и переписываются — у vk_tramp нет `vkResetDescriptorPool`),
  задание в пролог. Привязка записи — самая верхняя свободная от входов VS (нулевой поток берёт самую нижнюю).
- **Старый путь `draw()`:** без памяти конвейера по состоянию (как NR-POSONLY), `apply_old()` после всех выборов модуля VS (retype, NR-32,
  IDVS) и после `nrpo::rewrite`: сначала проверка (тот же код retype, привязка свободна), потом модуль потребителя (обрезанный NR-32 так же,
  как модуль, который он заменяет) и вершинный ввод (атрибуты, которые потребитель не читает, уходят; группы записи — на привязке P.k со
  страйдом 4 × m); привязка буфера записи.
- **Полоса NR-09:** слово варианта 4, биты 40–43 — привязка записи, 44–63 — id раскладки потребителя (формат глубины занимает 32–39);
  привязка записи вместо снимка. Свёртка baseVertex в смещения работает и для записи (тот же индекс вершины).
- **Пролог (`submit_slots`):** слайсы подачи — первыми в прологе (один пустой render pass без вложений 1×1, на задание: конвейер, набор,
  вершинные буферы, `vkCmdDraw(nverts)`), затем копии / загрузки как раньше (их барьеры только при них).
- Строка раз в 10 с: `[nr] preskin (DM_NR_PRESKIN=…, …): draws …; skinned depth-only … / colour …; eligible …; applied|would apply …;
  records a frame: position-class … (… k vertices) / wider …, … MB; reuse: own … / …, another shader's record … / … (draws per record …);
  model (SPIR-V body ops) saved … - slice …; malioc G57 model [m, every index shaded]: saved … M cycles - slice … M = … M (… ms …);
  slices recorded …, arena peak …; plans … (refused …), consumers …, slice pipelines …; code mismatch …; not: <причина> … (… M idx), …`.
  Плюс до 8 строк `[nr] preskin plan vs=…` и `[nr] preskin slice pipeline … ms` (время сборки конвейера слайса).

## 3. Доказательство бит в бит
### 3.1 Пак — `dm/gfx/vulkan/engine/tests/nr_preskin_test.cpp` (производственный `xbg_spirv_preskin.cpp`, WSL g++)
На ключ: модуль как на телефоне (цепочка `xbg_game.cpp` tidy_rewrite: n f t c p, +u UBOVEC как на Mali, +r retype Location 15 → uint как на
Mali), план, потребитель, слайс; свои проверки: детерминизм (два прогона — те же слова), выходы потребителя те же, слайс пишет ровно m слов
и ничего в Output, потребитель больше не индексирует кости, план потребителя отказывает («резать нечего»). **2 001 / 2 001 с планом в каждой
из 3 цепочек, FAIL 0; надмножеств 1 174, FAIL 0.** Размеры записей: 3 слова — 867 VS, 4 — 34, 6 — 327, 12 — 773.
### 3.2 Интерпретатор — `tools/dos2_preskin_check.py`
spirv-val `--target-env vulkan1.1` на всех модулях (0 ошибок). Прогон: случайные входы (Location 15 = слова int 0..127, Location 14 веса в
[0, 1], прочее ±2), случайные UBO (кости, мировая, view-proj), `gl_VertexIndex` случайный; оригинал → O; слайс → запись R; потребитель(R) → O'.
O' = O побитно по всем выходам (gl_Position и все varying). Надмножество: потребитель P читает запись слайса другого VS Q (UBO по ключу
данных: в Q тот же блок на другом binding). Итог:
| набор | модулей | прогонов (своя запись + чужая) | расхождений |
|---|---|---|---|
| 50 VS сессии, цепочка Mali + retype, n = 8 | 50 | 400 + 160 | **0** |
| весь пак, Adreno (nftcp), n = 2 | 2 001 | 4 002 + 2 348 | **0** |
| весь пак, Mali (nftcpu), n = 2 | 2 001 | 4 002 + 2 348 | **0** |
| весь пак, Mali + retype (nftcpur), n = 2 | 2 001 | 4 002 + 2 348 | **0** |
Чувствительность: изменение любого одного слова записи (×0x400000) меняет выход у 12 / 12 и 3 / 3 слов (проверено на двух VS).
(Первая версия проверки надмножеств давала расхождения из-за ошибки самой проверки — UBO отдавался по номеру binding, а у второго VS тот же
блок на другом binding; исправлено ключом данных.)
### 3.3 Почему это бит в бит и на железе (позиции), и где оговорка (нормали)
- Слайс и потребитель — **те же инструкции SPIR-V в том же порядке** на тех же входах; запись несёт сырые биты (uint-формат, без
  денормал-флаша выборки); выборка атрибутов слайса — та же фиксированная (те же форматы / смещения / страйды).
- Транслятор пишет MAD как явный `Fma`; свободу сжатия драйвер имеет только для пар FMul+FAdd. У оригинала `gl_Position` объявлен
  `Invariant`: Mesa (`vk_nir.c` → `nir_propagate_invariant`) помечает всё, что его питает, как exact (без сжатия); `NoContraction` даёт то же
  (`vtn_alu.c`). Поэтому в слайсе `NoContraction` стоит ровно на float-арифметике, питавшей `Invariant`-выход оригинала → **позиции бит в бит
  с оригиналом** на любом драйвере, который выполняет invariance через exact (Mesa — да; Arm — так требует `invariant`, проверить пробой).
- Значения, которые в оригинале питали только varying (нормали G-buffer), драйвер вправе сжимать по-своему и в оригинале; сжатие через
  разрез невозможно → возможна разница в 1 ulp нормали **относительно того, как этот драйвер скомпилировал бы оригинал** (не относительно
  SPIR-V). Это класс «тот же шейдер другим компилятором», картинка та же; позиции и глубина не затронуты.
- Пре-пасс + G-buffer (EQUAL / LEQUAL глубины): если один из них берёт запись, а другой нет (например `MAXM=4`), позиции всё равно равны
  (предыдущий пункт). Все draw одного меша в подаче, которые берут запись, читают одни и те же слова — между собой они равны тождественно.

| TUT | (153 k + 263 k) × 28.1 = 11.7 М − ≈ 263 k × 18 = 4.7 М → **7.0 М** | 315 k × 26.1 = 8.2 М − 6.6 М → **1.6 М** | **≈ −4.5 мс верх** |

| Mi 14 (Adreno 750) | **0** — не включается (N1: весь скиннинг 0.05–0.14 мс; слайс + трафик записи съели бы это) | | |
**Поправка на умолчание тайлеров:** на Mali / PowerVR по умолчанию включён `DM_DOS2_PREPASS` (NR-30: непрозрачные draw пре-пасса не рисуются,
G-buffer кладёт глубину сам) — пре-пасса скиннинговых мешей там почти нет. Тогда Форт: тени 153 k × 28.1 = 4.3 М − 0.9 М = 3.4 М + G-buffer
0.4 М ≈ **3.8 М ≈ −2.0 мс верх (−1…−2 мс)**; TUT: 153 k × 28.1 − 0.9 М + 1.6 М ≈ 5.0 М ≈ **−2.6 мс верх**. Это числа для решения на Mali.
G-buffer сам по себе почти в ноль (своя запись, повтор 1×); главный выигрыш — тени (3 каскада на одну запись) и пре-пасс, где он есть. Запись G-buffer
содержит 3 слова depth-класса, но кадр рисует тени раньше G-buffer, поэтому общая запись получается только для draw после G-buffer (FX);
«предсказание» широкой записи на первой тени не сделано (§8). Поэтому `MAXM` — рычаг A/B: 16 (всё) против 3 (только depth).
### 4.2 Память и полоса
Запись 12 Б / вершину (depth) или 48 Б (G-buffer). Форт: ≈ 51 k × 12 + 74 k × 48 ≈ 4.2 МБ на кадр в арене (8 МБ на слот, 2 слота = 16 МБ, под
долей статики NR-29). Полоса G-buffer: выборка 26 → 52 Б на вершину + запись слайса 48 Б → ≈ +7 МБ / кадр (≈ 0.2 ГБ/с при 30 fps — ~1 % LPDDR4X);
depth: 18 → 16 Б на вершину (меньше). Барьер: **0 новых** (§0). CPU транслятора: решение на скиннинговый draw (поиск в таблице, 2–6 хэшей) —
доли мкс; первая встреча VS — план (min-cut на ~1 000 значений) + 2 модуля + конвейер слайса (лог пишет мс).

## 7. Риски
- Поведение драйвера Arm с `Invariant` / `NoContraction` проверить картинкой (P4): позиции у пре-пасса и G-buffer должны совпасть (дыр /
  мерцания глубины нет). На Mesa доказано кодом драйвера.
- Сборка конвейера слайса — синхронно при первой встрече (лог `slice pipeline … ms`); на Mali десятки мс × ~50 VS за сессию — разовые
  подёргивания (дальше — `pipeline_cache`). Конвейер потребителя идёт обычным путём (async-сборка может пропустить draw на несколько кадров,
  как у любого нового конвейера).
- Счёт вершин — весь диапазон потока, привязанный draw; если игра привязывает общий большой буфер, слайс скиннит лишнее (`MAXV`, счётчик
  `mesh too big`); P1 покажет `k vertices` против индексов.
- Таблица записей живёт одну подачу; кадр, разбитый на несколько подач (синхронизации), скиннит заново в каждой (корректно, дороже).
- Без `vertexPipelineStoresAndAtomics` — только счёт (Mali / PowerVR его отдают, проверить в `NVN caps`).

## 8. Не сделано / идеи
- «Предсказание» широкой записи: по прошлому кадру на первой тени меша сразу считать запись G-buffer (тогда и G-buffer читает готовое:
  ещё ≈ −1.5 М циклов в Форте); мешает лист `c[1]` (знак касательной) — связан у тени другой UBO; решать по ключу листа на значение.
- Слайс как compute (без render pass) — не нужен, пока у устройств есть vertexPipelineStores.
- Тот же разрез годится для других «дорогих одинаковых» частей VS разных проходов (матрица мира у статики, ветер травы) — та же
  инфраструктура, другая метка «источника».
- Перенос в другие порты: D3 / XC2 / TL2 скиннинг тоже через UBO-индекс у транслятора (тот же вид) — модулем после A/B на Mali.
