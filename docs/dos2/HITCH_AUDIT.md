## Фикс 1: `DM_GFX_DESWZ_DIRECT` (перенос PERF-D12 из DOOM 2016)
- **Что:** полная заливка цветной block-linear текстуры (не CPU-декод BC, не linear) раньше: `std::vector` (обнуляется при resize) →
  `nvn_deswizzle` (на каждые 16 байт `nvn_bl_offset` с делениями и остатками) → `stream_buffer` (второй memcpy). Теперь
  `nvn_deswizzle_gob` (смещение строки один раз сдвигами, GOB-строка = 4 копии по 16 байт) **прямо в mapped staging**; частичные
  перезаливки (`partial_upload`) собирают грязные блоки `nvn_deswizzle_gob_block`. Те же смещения подресурсов (выравнивание 16), те же
  pitch и copies; не обнуляются только щели выравнивания, которые ни одна copy не читает.
- **Переключатель:** `DM_GFX_DESWZ_DIRECT` = **1 для DOS2** (код по умолчанию; для других игр дерева 0), 0 — старый путь, 2 — старый путь +
  GOB-деswizzle каждого подресурса и memcmp (`NVN PERF deswz … cmp= mism=`, первые 16 расхождений `NVN deswz MISMATCH full …`; заливаются
  старые байты). Умолчание 1 потому, что поведение не меняется: заливаются те же байты (хост-тест побайтно), меняется только CPU-время.
  Хэш всей текстуры после заливки оставлен как был (у D16 при =1 он пропускается — это уже смена семантики, здесь не перенесено).
- **Лог:** при старте `NVN deswizzle DM_GFX_DESWZ_DIRECT=1 (…)`; каждые 60 кадров `NVN PERF deswz mode= full= full_mb= full_ms= old= old_ms=
  partial_blocks= cmp= mism=` (full — заливки новым путём, old — остальные: глубина, CPU-декод, linear, ASTC-кэш/полосы идут своими путями).
- **Эталон:** D16 `doom-port/src/dm/gfx/tex/nvn_deswizzle.c` (`nvn_deswizzle_gob*`), `xbg_game.cpp get_image_slow` (r5).
  Здесь: `dm/gfx/tex/nvn_deswizzle.{c,h}`, `dm/gfx/vulkan/engine/xbg_game.cpp` (`namespace dzd`, `get_image_slow`, `partial_upload`, строка PERF).
- **Проверка на ПК:** `dm/gfx/tests/t_deswz_direct.c` (из D16, `make t_deswz_direct`, WSL gcc): 3312 текстур, 191 593 уровня/слоя (12.4 ГБ),
  1 008 042 частичных блока, **0 расхождений, PASS**; скорость x86: RGBA8 2048² 9.84 → 1.24 мс (×7.96), BC7 4096² 8.98 → 1.08 мс (×8.34).
- **Ожидание на телефоне (не мерено):** доля deswizzle в 50–87 мс — большая часть (D16: вход в ТВ-комнату 565–744 → 256–275 мс, хитчи −35 %).
  Ждём `上传贴图 … / N ms` в тех же событиях в 2–4 раза меньше.

## Фикс 2: лог длинных кадров не считает паузу хитчем
- `hle_os.c dm_guest_frozen_ns()` — накопленное время заморозки часов гостя (⚙-меню, фон, системная клавиатура, заморозка экрана
  загрузки). `hle_nvn.c`: на кадр пишется `pause_ms`; «длинный» и скользящее среднее считаются по кадру **без** паузы. Кадр, длинный только из-за
  паузы (≥ 100 мс), печатается с хвостом `；其中暂停 N ms（⚙ 菜单 / 后台 / 系统键盘：客体时钟冻结），扣掉后 X ms，不是卡顿`. Чистая диагностика:
  игра и рендер не меняются; без хоста (графические юнит-тесты) слабая ссылка = 0 → как раньше. `DM_LONGFRAME=0` по-прежнему выключает лог.

  пишущие глубину draw нельзя без риска дыр в кадре (ровно то, что функция отсекает), поэтому не делалось.

## Шаги на телефоне (делает главный агент; перед force-stop — бэкап `files/save`)
1. Поставить APK этой ветки (`wt-hitch/work/DOS2-port-debug.apk`), env без изменений (DESWZ_DIRECT=1 по умолчанию).
2. Прогон A: холодный старт → меню → Continue → загрузка кампании → смена локации. Собрать `boot.log`. Смотреть: строки `[长帧]` с
   `上传贴图 … MB / N ms` (сравнить с таблицей п.1: 50–87 мс), `NVN PERF deswz full_ms`, отсутствие мусора/полос на текстурах.
3. Прогон B (тот же маршрут, `DM_GFX_DESWZ_DIRECT=0` в `dm/env`): то же, для A/B. Один прогон `=2`: в логе `mism=0`, 0 строк `deswz MISMATCH`.
4. Открыть/закрыть ⚙ в кампании: длинный кадр после `menu closed` должен идти с хвостом `其中暂停 … 不是卡顿`.
5. Сид пайплайнов: `adb pull` листа `files/.../vk-pipeline-list.bin` (рядом с `vk-pipeline-cache.bin`), `python dm/android/tools/merge_warm_lists.py`
   → `dm/shaders/vk-pipeline-list.seed`, пуш в `Download/DivinityOriginalSin2Mobile/dm/shaders`; проверка — на чистых данных `NVN warm list seeded
   from …` и `created` 0–5 при первом входе в локацию.
6. Для п.3/п.4: прогон с `DM_FS_STATS=1` (средняя / макс. задержка pread на загрузках) — следующая итерация.
7. Force-stop игры после сбора логов.
